# Հարցումների սահմանափակումներ {#rate-limits}

Յուրաքանչյուր հարցում հաշվվում է ընդհանուր սահմանաչափի մեջ։ Endpoint-ները, որոնք ընդունում են հավաստագիր, դիմում են այլ ընկերության համակարգին կամ տեղադրումից դուրս ինչ-որ բան են ուղարկում, լրացուցիչ հաշվվում են ավելի խիստ անվանական սահմանաչափով։ Երբ սահմանաչափը սպառվում է, API-ն կանչը մերժում է `429` պատասխանով՝ մինչև սահմանաչափը նորից ազատվի։

## Քաղաքականություններ {#policies}

Յուրաքանչյուր սահմանաչափ հարցումների քանակ է սահող պատուհանում, որը հաշվվում է յուրաքանչյուր մուտք գործած օգտատիրոջ համար, իսկ առանց հավաստագրի հարցման դեպքում՝ կանչողի հասցեի համար։ Պատուհանը սահում է վեց քայլով, ուստի սահմանաչափի մի մասը վերադառնում է յուրաքանչյուր մի քանի վայրկյանը մեկ, ոչ թե ամբողջը՝ միանգամից, սահմանագծին։

### Որ endpoint-ներն ինչ քաղաքականություն են օգտագործում {#which-endpoints-use-each-policy}

Այս ցանկը կարդացվում է API-ի վերահսկիչներից՝ կայքը կառուցելու ժամանակ։ Պլագինների քաղաքականությունները դրանում չկան՝ դրանք կիրառում է պլագինների կանչերի ֆիլտրը այն ուղիներին, որոնք հայտարարում են պլագինները։

Հարգեք <code>Retry-After</code>-ը։ Անմիջապես նորից փորձելը ձեզ ուղիղ նույն մերժման մեջ է վերադարձնում։

Այս վերնագրերը գալիս են միայն `429`-ի հետ։ Քաղաքականությունների անունները և սահմանաչափերը նույնն են, ինչ այս էջում, ուստի վերնագրերը կանչողին տեղադրման մասին ոչինչ չեն ասում այն ամենից բացի, ինչ այստեղ հրապարակված է։ Մեկ այլ ծագումից բրաուզերում աշխատող սկրիպտը չի կարող դրանք կարդալ՝ API-ն դրանք չի թվարկում `Access-Control-Expose-Headers`-ում։ Դրանք հասանելի են սերվերին, հրամանի տողի գործիքին և այն էջին, որը մատուցվում է նույն ծագումից։

Սպասեք վերնագրում նշված վայրկյանների քանակով, ապա նորից փորձեք։ Զանգվածային աշխատանքը բաշխեք ժամանակի մեջ, ոչ թե ուղարկեք մեկ պոռթկումով։

## Պրոքսիի հետևում {#behind-a-proxy}

Սահմանաչափերը հաշվվում են կանչողի հասցեի համար, ուստի երբ API-ի առջև պրոքսի է կանգնած, API-ն պետք է իմանա, թե որ հասցեն է կանչողինը։ Այն հասցեն կարդում է `X-Forwarded-For`-ից միայն այն չափով, որքան վստահելի պրոքսիների մասին իրեն ասվել է, և միայն երբ հարցումը գալիս է իրեն հայտնի պրոքսիից։

## Կարգավորումներ {#settings}

Վերևի սահմանաչափերը լռելյայն արժեքներ են։ Օպերատորը դրանք փոխում է API ծառայության համար՝ compose-ի վերասահմանման մեջ։ Կարգավորումները՝ իրենց լռելյայն արժեքներով և տիրույթներով, թվարկված են [Հարցումների սահմանափակումների կարգավորումներ](/hy/operators/configuration#rate-limit-settings-compose-override-only) բաժնում։ `global`-ից մեծ մակարդակը կամ դրական չհանդիսացող արժեքը թույլ չի տալիս API-ին գործարկվել։

## Մուտքի արգելափակում {#sign-in-lockout}

Մուտքի արգելափակումը առանձին է հարցումների սահմանափակումներից։ Անընդմեջ չափազանց շատ սխալ գաղտնաբառերից հետո հաշիվը արգելափակվում է, և յուրաքանչյուր մուտք պատասխանում է `SIGN_IN_ACCOUNT_LOCKED`՝ `423` կարգավիճակով, ինչ գաղտնաբառ էլ ուղարկվի, մինչև արգելափակման ավարտը։

]" />

Հաշվիչը պահվում է հաշվի վրա, ուստի այն պահպանվում է վերագործարկումների ընթացքում և ընդհանուր է API-ի բոլոր օրինակների համար։ Հաջող մուտքը զրոյացնում է այն։
