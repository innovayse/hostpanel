# Ճարտարապետության ակնարկ {#architecture-overview}

<Callout type="note">
Երբ այս էջը և կանոնների ֆայլերը չեն համընկնում, վճռորոշ են կանոնների ֆայլերը։
</Callout>

## Բաղադրիչները {#the-pieces}

```
Browser
  ├── Admin panel (admin/)      calls    API
  └── Client portal (client/)   calls    server routes  calls  API
                                                                 │
                                                   Database, Queue, Cache
```

| Բաղադրիչ | Ինչ է սա |
|----------|----------|
| **API** (`Innovayse.Hostpanel.API`) | Հետևի մաս։ Մշակում է բոլոր HTTP հարցումները, կատարում է ֆոնային առաջադրանքներ, աշխատում է տվյալների բազայի, հաղորդագրությունների հերթի և քեշի հետ։ |
| **Ադմինի վահանակ** (`admin/`) | Մեկ էջանոց հավելված աշխատակիցների համար։ Կարդում և գրում է API-ի միջոցով։ |
| **Հաճախորդի պորտալ** (`client/`) | Սերվերում ձևավորվող հավելված հաճախորդների համար։ Ունի սեփական սերվերային երթուղիներ, որոնք միջնորդում են API-ին, ուստի API-ն երբեք չի կանչվում անմիջապես դիտարկիչից։ |
| **Տվյալների բազա** | Ռելյացիոն պահոց։ Յուրաքանչյուր աղյուսակի, սյունակի, բանալու, ինդեքսի և սահմանափակման անունը PascalCase է։ |
| **Հաղորդագրությունների հերթ** | Փոխանցում է հրամանները և հարցումները API-ի գործընթացի և նրա ֆոնային աշխատողների միջև։ |
| **Քեշ** | Ընդհանուր քեշ, որն օգտագործվում է հարցումների սահմանափակման, նիստի վիճակի և կարճատև տվյալների համար։ |

Պլագինների SDK-ն (`Hostpanel.Sdk`) MIT լիցենզիայով է և գտնվում է `backend/src/Hostpanel.Sdk` հասցեում՝ որպես git submodule։ Սա կոդի միակ մասն է, որն օգտագործում են երրորդ կողմի պլագինների հեղինակները։

## Շերտերը {#the-layers}

Կախվածությունները ուղղված են ներս։ Արտաքին շերտերը կարող են հղվել ներքիններին, իսկ ներքինները երբեք չեն հղվում արտաքիններին։ Այս կանոնը ստուգում են `Innovayse.Hostpanel.Architecture.Tests`-ի ճարտարապետական թեստերը։

| Շերտ | Նախագիծ | Ինչ է պարունակում |
|------|---------|-------------------|
| **SharedKernel** | `Innovayse.Hostpanel.SharedKernel` | Բոլոր շերտերի համար ընդհանուր հիմնական տարրեր՝ բազային տիպեր, արդյունքի տիպեր, ընդլայնման մեթոդներ։ |
| **Domain** | `Innovayse.Hostpanel.Domain` | Էակներ, թվարկումներ և դոմենի տրամաբանություն։ Չի կախված ենթակառուցվածքից կամ կիրառական շերտի հարցերից։ |
| **Application** | `Innovayse.Hostpanel.Application` | Օգտագործման դեպքեր՝ հրամաններ, հարցումներ, մշակիչներ, վավերացուցիչներ։ Սահմանում է պորտեր (`I<Port>` ինտերֆեյսներ) այն ամենի համար, ինչ հավելվածին պետք է դրսից։ |
| **Infrastructure** | `Innovayse.Hostpanel.Infrastructure` | Ադապտերներ, որոնք իրականացնում են հավելվածի պորտերը՝ ORM, էլ. փոստ, պահոց, հաղորդագրությունների բաս, ֆոնային առաջադրանքներ։ |
| **API** | `Innovayse.Hostpanel.API` | Կոնտրոլերներ, միջանկյալ շերտ, գործարկում։ Կազմման արմատն է, որը միացնում է ամեն ինչ իրար։ |
| **Shared** | `Shared` | Հիմնական նախագծի ընդհանուր կոդը՝ `BaseApiController`, `StatusMapping`, ընդհանուր մոդելներ։ Պլագինները այս նախագծին չեն հղվում։ |

## Պլագինների SDK-ն և ներկառուցված պլագինները {#the-plugin-sdk-and-bundled-plugins}

SDK-ն գտնվում է `backend/src/Hostpanel.Sdk` հասցեում՝ որպես git submodule (առանձին տեղադրված է `github.com/innovayse/hostpanel-sdk` հասցեում)։ Կլոնավորեք պահոցը `--recurse-submodules`-ով կամ սովորական կլոնավորումից հետո կատարեք `git submodule update --init`։

Ներկառուցված պլագինները մատակարարվում են սերվերի պատկերի հետ և գտնվում են `backend/src/Innovayse.Providers.*` ենթակայքերում։ Դրանք պլագինների հեղինակների համար հղման իրականացումներ են։

Պլագինների ստեղծման ամբողջական ուղեցույցի համար տե՛ս [Գրեք պլագին](./write-a-plugin) ուղեցույցը։

## Պահոցը {#the-repository}

| Թղթապանակ | Պարունակություն |
|-----------|-----------------|
| `backend/` | `src/` (նախագծեր), `tests/` (թեստային նախագծեր), `plugins/` (միգրացիայի հավելում), `agent/` (SSH բանալիների գործակալ) |
| `admin/` | Ադմինի վահանակ |
| `client/` | Հաճախորդի պորտալ |
| `docker/` | Compose ֆայլեր, միջավայրի ձևանմուշներ, nginx կարգավորում |
| `docs/` | Այս փաստաթղթերի կայքը |
| `rules/` | Կոդի ոճի կանոններ։ Կոդի ոճի որոշումների աղբյուրը։ |
| `scripts/` | CI-ի և սպասարկման սկրիպտներ |

## Կանոնների թղթապանակը {#the-rules-folder}

`rules/*.md`-ը կոդի ոճի աղբյուրն է։ Երբ այս էջը և կանոնները չեն համընկնում, հաղթում են կանոնները։

| Ֆայլ | Ինչ է ընդգրկում |
|------|-----------------|
| `rules/project.md` | Նախագծի ակնարկ, որտեղ ինչ է դրվում, ինչով է տարբերվում աշխատանքային տարածքի պայմանավորվածություններից |
| `rules/clean-architecture.md` | Շերտերի կանոններ և կախվածության ուղղություն |
| `rules/csharp-style.md` | C# ոճ՝ ձևավոր փակագծեր, կոնստրուկտորներ, անվանում, մեկ տիպ՝ մեկ ֆայլում |
| `rules/dotnet-format.md` | Ֆորմատավորչի կարգավորում և commit-ից առաջվա քայլեր |
| `rules/xml-docs.md` | XML փաստաթղթային մեկնաբանությունների պահանջներ C#-ի համար |
| `rules/jsdoc.md` | JSDoc պահանջներ TypeScript-ի և Vue-ի համար |
| `rules/vuejs-style.md` | Vue բաղադրիչների և կոմպոզաբլների պայմանավորվածություններ |
