# Փաստաթղթերի թարգմանություն {#translating-the-documentation}

Փաստաթղթերը հրապարակվում են անգլերեն, ռուսերեն և հայերեն լեզուներով։ Անգլերենը սկզբնական լեզուն է և գտնվում է կայքի արմատում, ուստի նրա հասցեներում լեզվի նախածանց չկա։ Ռուսերենը սպասարկվում է `/ru/` հասցեի տակ, հայերենը՝ `/hy/`։

Հենց Hostpanel հավելվածը թարգմանելու համար (ադմինի վահանակ, հաճախորդի պորտալ և API-ի հաղորդագրություններ) տե՛ս [Hostpanel-ի թարգմանություն](./translating)։

## Ինչպես են դասավորված պանակները {#how-the-folders-are-laid-out}

Յուրաքանչյուր լեզու իր էջերը պահում է առանձին պանակում, իսկ ռուսերեն և հայերեն պանակները ֆայլ առ ֆայլ կրկնում են անգլերեն ծառը․

| Անգլերեն էջ | Ռուսերեն էջ | Հայերեն էջ |
|-------------|-------------|------------|
| `docs/en/index.md` | `docs/ru/index.md` | `docs/hy/index.md` |
| `docs/en/staff/orders.md` | `docs/ru/staff/orders.md` | `docs/hy/staff/orders.md` |
| `docs/en/operators/index.md` | `docs/ru/operators/index.md` | `docs/hy/operators/index.md` |

Անգլերեն պանակը հասցեի մաս չէ․ `docs/en/staff/orders.md` ֆայլը սպասարկվում է `/staff/orders` հասցեով, իսկ `docs/ru/staff/orders.md`՝ `/ru/staff/orders` հասցեով։ Ֆայլերը, որոնք որևէ լեզվի չեն պատկանում (`public`, `scripts`, `tests`, `.vitepress` և փաթեթների ֆայլերը), մնում են `docs` պանակի արմատում։

Դեռ չթարգմանված էջը «չի գտնվել» սխալ չի վերադարձնում։ Կառուցման ժամանակ Hostpanel-ը գրում է փոխարինող էջ՝ յուրաքանչյուր անգլերեն էջի համար, որը տվյալ լեզվում չկա։ Փոխարինող էջը ցույց է տալիս կարճ ծանուցում ընթերցողի լեզվով, իսկ ներքևում՝ անգլերեն տեքստը։ Որոնողական համակարգերին ասվում է չինդեքսավորել այն և որպես բնօրինակ դիտարկել անգլերեն էջը։ Փոխարինող էջերը ստեղծվում են `docs/_fallback/` պանակում, որը git-ը անտեսում է, ուստի դրանք երբեք չեն commit արվում։ Երբ ավելացնեք իրական էջը, հաջորդ կառուցման ժամանակ այն կփոխարինի փոխարինող էջին։

Չեն թարգմանվում և փոխարինող էջեր չունեն `components` էջը և `api-reference/_partials` պանակի ստեղծված հատվածները։ `docs/brand` պանակը պարունակում է բրենդի փաթեթը և որևէ լեզվի էջ չէ։ Ցանկը գտնվում է `docs/.vitepress/i18n/locales.json` ֆայլի `untranslated` դաշտում։

## Էջի թարգմանություն {#translate-a-page}

1. Պատճենեք անգլերեն ֆայլը (`docs/en/...`) `docs/ru/` կամ `docs/hy/` պանակի նույն ճանապարհով։
2. Թարգմանեք front matter-ի `title` և `description` դաշտերը և էջի տեքստը։ Front matter-ի մյուս բոլոր բանալիները թողեք առանց փոփոխության։
3. Յուրաքանչյուր ներքին հղում սկսեք լեզվի պանակով՝ ռուսերեն էջում `[Orders](/ru/staff/orders)`, հայերեն էջում `[Orders](/hy/staff/orders)`։ Հղումը այն էջին, որը երբեք չի թարգմանվում (օրինակ՝ `/components`), մնում է ինչպես կա։
4. Յուրաքանչյուր վերնագրի խարիսխը պահեք նույնը, ինչ անգլերենում՝ ձեռքով ավելացնելով այն, օրինակ՝ `## Dashboard {#dashboard}`։ Այլ էջեր հղվում են այդ խարիսխներին, իսկ թարգմանված վերնագրի ինքնաշխատ խարիսխը կլիներ այլ։
5. Գործարկեք ստուգումները (տե՛ս ստորև) և բացեք էջը dev սերվերում։
6. Եթե էջը նոր է անգլերենում, էջի վերնագիրն ավելացրեք կողագոտում։ Բոլոր լեզուների կողագոտի վերնագրերը գտնվում են `docs/.vitepress/i18n/en.json`, `ru.json` և `hy.json` ֆայլերում՝ `pages` բաժնում, էջի հղումով բանալիավորված։

Էջերը թարգմանվում են ամբողջությամբ։ Էջի կեսը անգլերեն մի թողեք․ մասամբ թարգմանված էջը ընթերցողի համար ավելի վատ է, քան փոխարինող էջը։

## Ինչը մնում է անթարգմանելի {#what-stays-untranslated}

Այս բաները պահեք ճիշտ այնպես, ինչպես անգլերենում են, բոլոր լեզուներում․

- Կոդը, հրամանները, ֆայլերի անունները, ճանապարհները, միջավայրի փոփոխականների անունները և կարգավորման բանալիները։
- Հրամանի տողի դրոշակները և դրանց արժեքները։
- API-ի ճանապարհները, HTTP մեթոդները, կարգավիճակի կոդերը, JSON դաշտերի անունները և սխալների կոդերը։
- Արտադրանքների և տեխնոլոգիաների անունները, ինչպիսիք են Hostpanel, Docker, Nginx, cPanel, WHMCS, SSH, SSO և OpenAPI։
- **Հավելվածում** կոճակների և մենյուի կետերի անունները, երբ հավելվածն ինքը դրանք ցույց է տալիս անգլերեն։ Եթե հավելվածն ունի ռուսերեն կամ հայերեն ինտերֆեյս, օգտագործեք այն բառը, որ օգտագործում է ինտերֆեյսը, որպեսզի ընթերցողը կարողանա գտնել այն էկրանին։ Ինտերֆեյսի տեքստերը գտնվում են `admin/src/locales/` և `client/locales/` պանակներում։

Կոդի մեջ մեկնաբանության տեքստը թարգմանեք միայն այն դեպքում, երբ մեկնաբանությունը ընթերցողին ինչ-որ բան է բացատրում։ Շրջապատող կոդը մի թարգմանեք։

## Օգտագործեք բառարանը {#use-the-glossary}

`docs/.vitepress/i18n/glossary.json` բառարանում թվարկված են հիմնական եզրույթները (պլագին, հաշիվ-ապրանքագիր, պրովիժնինգ, սերվեր, դոմեն, հաճախորդ, աշխատակիցներ և այլն) երեք լեզուներով։ Բառերը համապատասխանում են ադմինի վահանակին և հաճախորդի պորտալին, ուստի փաստաթղթերը և էկրանները նույն բանի համար օգտագործում են նույն անունը։ Բառարանի բառը օգտագործեք ամեն անգամ․ նույն եզրույթի համար երկրորդ բառ մի հորինեք։ Եթե եզրույթը բացակայում է, ավելացրեք այն բառարանում՝ այն էջի հետ նույն փոփոխության մեջ, որին այն պետք է։

Ռուսերենում «դուք»-ը գրեք քաղաքավարի ձևով (вы), հայերենում՝ դուք։ Նախադասությունները պահեք կարճ և ներգործական սեռով, ինչպես անգլերեն տեքստում։

## Փաստաթղթերի բաղադրիչները {#documentation-components}

Բաղադրիչները (`Callout`, `Steps`, `SettingTable`, `Label`, `Screenshot`, `DemoLink`) բոլոր լեզուներում աշխատում են նույն կերպ։ Նրանց ներկառուցված բառերը (`SettingTable`-ի սյունակների անունները, `Label`-ի տեքստը, պատկերների դիտիչի կոճակները) վերցվում են `docs/.vitepress/i18n/` պանակի լեզվական ֆայլերից։ Թարգմանեք այն տեքստը, որ դնում եք դրանց ներսում, ոչ թե նրանց անունները կամ ատրիբուտները։

## Հենց կայքի տեքստը {#the-text-of-the-site-itself}

Նավիգացիայի գոտին, կողագոտը, որոնման դաշտը, «Այս էջում» վերնագիրը, նախորդ և հաջորդ հղումները, 404 էջը և թեմայի բաղադրիչների տեքստերը Markdown ֆայլերում չեն։ Դրանք գտնվում են `docs/.vitepress/i18n/en.json`, `ru.json` և `hy.json` ֆայլերում։ Երեք ֆայլերն ունեն նույն բանալիները, և թեստը ձախողվում է, եթե որևէ բանալի դրանցից մեկում բացակայում է։ Տեքստը փոխելու համար փոխեք այն երեք ֆայլերում էլ։

## Ստուգեք ձեր աշխատանքը {#check-your-work}

Գործարկեք սրանք `docs` պանակից․

```bash
npm test
npm run build
```

`npm test`-ը ստուգում է, որ յուրաքանչյուր լեզվի ֆայլ ունի բոլոր բանալիները, որ կողագոտի յուրաքանչյուր հղում գոյություն ունի բոլոր լեզուներում (որպես իրական էջ կամ որպես փոխարինող էջ), և որ փոխարինող էջերը և `hreflang` հղումները ճիշտ են գրված։ `npm run build`-ը նույնպես ձախողվում է կոտրված հղման դեպքում։

`npm run dev`-ը փոխարինող էջերը գրում է մեկ անգամ՝ գործարկվելիս։ Եթե աշխատելու ընթացքում թարգմանված էջ ավելացնեք, վերագործարկեք այն։
