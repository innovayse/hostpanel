# Hostpanel-ի թարգմանություն {#translating-hostpanel}

Hostpanel-ը մատակարարվում է անգլերեն, ռուսերեն և հայերեն լեզուներով։

<Callout type="note">
Անգլերենը սկզբնական լեզուն է և պահուստային տարբերակը, երբ տեքստը մյուս լեզվում բացակայում է։
</Callout>

## Որտեղ են գտնվում տեքստերը {#where-the-texts-live}

| Մաս | Ճանապարհ | Բեռնում է |
|-----|----------|-----------|
| Ադմինի վահանակ | `admin/src/locales/<lang>/<area>.json` | `admin/src/locales/messages.ts` |
| Հաճախորդի պորտալ | `client/locales/<lang>/<module>.json` | `client/plugins/i18n.ts` (`MODULES` ցանկ) |
| API-ի սխալների հաղորդագրություններ | `backend/src/Innovayse.Hostpanel.Application/Resources/ErrorMessages.resx` (en)՝ `ErrorMessages.ru.resx` / `ErrorMessages.hy.resx` ֆայլերի հետ | Լեզուն կարդացվում է `X-Language` հարցման վերնագրից, `Accept-Language`-ը չի օգտագործվում։ Անհայտ կամ բացակայող արժեքի դեպքում օգտագործվում է `en`։ |
| API-ի վավերացման հաղորդագրություններ | `ApplicationValidationMessages*.resx` `Application/Resources/` պանակում և `ValidationMessages*.resx` `Shared/Resources/` պանակում | Նույնը, ինչ վերևում․ `X-Language` վերնագիր, պահուստային լեզուն՝ `en`։ |
| Նամակների ձևանմուշներ | Խմբագրվում են լեզվով ադմինի վահանակում, ոչ թե ֆայլերում | |
| Հանրային կայքի բովանդակություն | Մուտքագրվում է լեզվով ադմինի վահանակում | |

## Ինչպես են անվանվում բանալիները {#how-keys-are-named}

**Ադմինի վահանակ։** Ֆայլի անունը բանալու առաջին հատվածն է։ `nav.json` ֆայլը պարունակում է `nav.*` բանալիները, որոնք օգտագործվում են որպես `t('nav.dashboard')`։ Յուրաքանչյուր ոլորտ ունի իր ֆայլը՝ `billing.json`, `clients.json`, `servers.json` և այլն։

**Հաճախորդի պորտալ։** Բանալիները ներդրված են մոդուլների ֆայլերում և գործարկման ժամանակ `client/plugins/i18n.ts`-ով միավորվում են մեկ հավաքածուի մեջ։

**API։** Բանալին սխալի կոդն է, օրինակ՝ `SIGN_IN_UNAUTHORIZED`։

<Callout type="warning">
Թարգմանության ֆայլում երբեք մի վերանվանեք բանալին։ Փոխեք միայն արժեքը։
</Callout>

## Տեղապահներ և հոգնակի թվեր {#placeholders-and-plurals}

Յուրաքանչյուր `{name}` տեղապահ պահեք ճիշտ այնպես, ինչպես այն երևում է անգլերեն սկզբնաղբյուրում։ Համապատասխանության թեստերը ստուգում են դրանք և ձախողվում են, եթե տեղապահը բացակայում է կամ վերանվանված է։

Ադմինի վահանակում `admin/src/i18n.ts` ֆայլում սահմանված է ռուսերենի հոգնակի թվի կանոն։ Ռուսերենում հոգնակի ձև ավելացնելիս հետևեք այնտեղ արդեն եղած կանոնին։ Օրինակ՝

```ts
// admin/src/locales/ru/billing.json
{
  "invoiceCount": "{n} счёт | {n} счёта | {n} счетов"
}
```

Երեք դիրքերը համապատասխանում են մեկին, երկուսից չորսին և հինգից ավելիին, ինչպես `i18n.ts`-ի `russianPlural` ֆունկցիայում։

## Ոճ {#style}

Կարճ, պարզ նախադասություններ։ Օգտագործեք նույն եզրույթները, ինչ լեզվի մնացած մասում։ Հիմնական եզրույթների փոքր բառարան՝

| English | Русский | Հայերեն |
|---------|---------|---------|
| Invoices | Счета | Հաշիվ-ապրանքագրեր |
| Services | Услуги | Ծառայություններ |
| Support Tickets | Тикеты поддержки | Աջակցության հայտեր |
| Servers | Серверы | Սերվերներ |
| Clients | Клиенты | Հաճախորդներ |

Մի ավելացրեք արտադրանքների անուններ, որոնք անգլերեն սկզբնաղբյուրում չկան։

## Ստուգեք, որ ոչինչ չի բացակայում {#check-that-nothing-is-missing}

<Callout type="tip">
Push անելուց առաջ գործարկեք <code>lint:i18n</code>-ը։ CI-ն գործարկում է նույն սկրիպտները։
</Callout>

::: code-group

```bash [Ադմինի վահանակ]
cd admin && npm run lint:i18n
```

```bash [Հաճախորդի պորտալ]
cd client && yarn lint:i18n
```

```bash [API]
cd backend && dotnet test tests/Innovayse.Hostpanel.Architecture.Tests --filter ResourceCoverageTests
```

:::

Բացակայող բանալիներով գործարկումն այսպիսին է․

```
lint:i18n failed: 2 problem(s).
  missing in ru: nav.documentation
  missing in hy: nav.documentation
```

Ադմինի վահանակի ստուգումը հաղորդում է բացակայող բանալիների, ավելորդ բանալիների, չօգտագործվող բանալիների և այն թարգմանության կանչերի մասին, որոնք անգլերեն սկզբնաղբյուր չունեն։ `admin/tests/locales/parity.test.ts` և `admin/tests/locales/messages.test.ts` թեստային ֆայլերը ստուգում են, որ բոլոր լեզուներն ունեն նույն բանալիները և որ տեղապահներ չեն բացակայում։

Հաճախորդի պորտալի `lint:i18n`-ը և `client/tests/locales/parity.test.ts`-ը ստուգում են նույն բաները․ նույն բանալիները բոլոր լեզուներում, դատարկ տողերի բացակայություն, նույն տեղապահները։

`ResourceCoverageTests`-ը (backend-ի ճարտարապետության թեստերում) ստուգում է, որ `HostpanelErrorCodes.cs`-ի յուրաքանչյուր սխալի կոդ ունի նախադասություն յուրաքանչյուր լեզվի ֆայլում, առանց ավելորդ բանալիների և անգլերենից տարբերվող արժեքներով։

## Տեսեք ձեր լեզուն տեղային միջավայրում {#see-your-language-locally}

Գործարկեք dev միջավայրը (տե՛ս [Տեղային գործարկում](./local-dev))։

- **Դեմո․** եթե հանրային դեմո կա, փաստաթղթերի նավիգացիայի գոտու «Try the demo» կոճակը բացում է ադմինի վահանակը։ Այնտեղ փոխեք լեզուն՝ ընթացիկ վիճակը տեսնելու համար առանց տեղային միջավայրի։
- **Ադմինի վահանակ․** օգտագործեք վերևի գոտու լեզվի փոխարկիչը։ Ընտրությունը պահվում է բրաուզերում որպես `admin.locale`։
- **Հաճախորդի պորտալ․** օգտագործեք լեզվի փոխարկիչը, որը URL-ին ավելացնում է `/ru` կամ `/hy`։ Անգլերենը սպասարկվում է առանց նախածանցի։ Տե՛ս [Հաճախորդի պորտալ](../customers/portal)՝ հաճախորդների տեսածի ակնարկի համար։
- **API-ի սխալների հաղորդագրություններ․** ցանկացած հարցմանը ավելացրեք `X-Language: en`, `X-Language: ru` կամ `X-Language: hy` և կարդացեք սխալի մարմնի `detail` դաշտը։ Ցանկացած չաջակցվող արժեքի դեպքում օգտագործվում է `en`։
- **Նամակների ձևանմուշներ․** թարգմանված տարբերակները կառավարվում են ադմինի վահանակում։ Լեզվական տարբերակ ավելացնելու մասին տե՛ս [Նամակների ձևանմուշներ](../staff/email-templates)։

## Ուղարկեք փոփոխությունը {#send-the-change}

Մեկ pull request մեկ լեզվի և ոլորտի համար լավ է։ Նախ գործարկեք վերևի բոլոր ստուգումները։ Երկու-երեք թարգմանված էկրանի սքրինշոթները օգնում են վերանայմանը։ Pull request-ը բացեք `develop` ճյուղի դեմ։
