# Արագ մեկնարկ {#quick-start}

Այս էջը ձեզ տանում է մաքուր Linux սերվերից մինչև առաջին հոսթինգի հաշիվը, որը Hostpanel-ը ստեղծում է հաճախորդի համար։ Յուրաքանչյուր քայլը կարճ է, իսկ մանրամասների համար կա հղում լրիվ ուղեցույցին։

## Ինչ է պետք {#what-you-need}

- Linux սերվեր՝ Docker-ով և Compose v2 plugin-ով, և երկու DNS անուն, որոնք ցույց են տալիս նրան. մեկը՝ հաճախորդի պորտալի, մյուսը՝ ադմինի վահանակի համար։ Լրիվ ցանկը [Նախքան սկսելը](/hy/operators/install#before-you-start) բաժնում է։
- Կառավարման վահանակով սերվեր, որտեղ կստեղծվեն հաշիվները, և նրա API հասանելիությունը։ Հաշիվներն ավտոմատ ստեղծող ներկառուցված մոդուլը cPanel-ն է, իսկ տեղադրված վահանակների պլագինները ավելացնում են իրենցը, տես [Սերվերներ և սերվերների խմբեր](/hy/servers/servers)։
- Էլ. փոստի հասցե ադմինիստրատորի հաշվի համար։

## 1. Տեղադրեք Hostpanel {#1-install-hostpanel}

Սերվերի վրա գործարկեք տեղադրիչը.

```bash
curl -fsSL https://raw.githubusercontent.com/innovayse/hostpanel/main/install.sh | bash
```

Այն հարցնում է պորտալի դոմենը, ադմինի վահանակի դոմենը և ադմինիստրատորի էլ. փոստը, գործարկում է ստեկը և սպասում `/health`-ին։ Վերջում տպում է երկու հասցեները և մեկանգամյա կարգավորման թոքեն։ Թոքենը պահեք հաջորդ քայլի համար։ Դրոշակները, սեփական TLS պրոքսիի հետևում տեղադրումը և docker compose-ով ձեռքով տեղադրումը նկարագրված են [Hostpanel-ի տեղադրում](/hy/operators/install) էջում։

## 2. Ստեղծեք առաջին ադմինիստրատորին {#2-create-the-first-administrator}

Բացեք ադմինի վահանակի հասցեն։ Քանի դեռ Admin դերը ոչ ոք չունի, երևում է **Սկզբնական կարգավորում** էկրանը։ Ստեղծեք հաշիվ, տեղադրեք կարգավորման թոքենը և սեղմեք **Ստանալ ադմինիստրատորի դերը**։ Եթե թոքենը կորել է, [Առաջին գործարկում](/hy/operators/install#first-run) բաժնում ցույց է տրված, թե ինչպես կարդալ այն API-ի մատյանից։

## 3. Կարգավորեք փոստը {#3-set-up-mail}

Տեղադրիչը միտումնավոր թողնում է `SMTP_HOST`-ը դատարկ։ Քանի դեռ `.env`-ում իրական ռելե չեք նշել և ստեկը չեք վերագործարկել, հաստատման, գաղտնաբառի վերականգնման և հաշիվ-ապրանքագրերի նամակներ չեն ուղարկվում։ Տես [Փոստի կարգավորում](/hy/operators/install#set-up-mail)։

## 4. Ստուգեք արժույթը {#4-check-the-currency}

Բացեք **Կարգավորումներ → Արժույթներ**։ Գները կարելի է ստանալ միայն այն դեպքում, երբ հիմնական արժույթը սահմանված է, հակառակ դեպքում API-ն պատասխանում է `BASE_CURRENCY_NOT_CONFIGURED`։ Եթե ցանկում հիմնական արժույթ չկա, ավելացրեք ձերը և դարձրեք հիմնական։ Տես [Արժույթներ, երկարացումներ և աշխատանքներ](/hy/staff/currencies)։

## 5. Ավելացրեք սերվեր {#5-add-a-server}

<Steps>
<li>

Բացեք **Սերվերներ** և սեղմեք **Ավելացնել նոր սերվեր**։

</li>
<li>

«Ընդհանուր» ներդիրում մուտքագրեք անունը, հոսթի անունը և IP հասցեն։ «Մանրամասների» ներդիրում ընտրեք մոդուլը և մուտքագրեք հասանելիությունը. cPanel-ի համար՝ WHM օգտատերը և API թոքենը, վահանակի պլագինի համար՝ այն, ինչ նկարագրված է նրա էջում։

</li>
<li>

Պահպանեք և սերվերի տողում սեղմեք **Ստուգել միացումը**։ Նշանը պետք է ցույց տա «Առցանց»։

</li>
</Steps>

cPanel-ի դեպքում սկզբում WHM-ում ստեղծեք API թոքեն, ինչպես նկարագրված է [cPanel սերվերներ](/hy/servers/cpanel) էջում։ Եթե օգտագործում եք մեկից ավելի մոդուլ, ապրանքի պատվերների համար պետք է սերվերների խումբ, տես [Սերվերների խմբեր](/hy/servers/servers#server-groups)։

## 6. Ստեղծեք ապրանք {#6-create-a-product}

Բացեք **Կարգավորումներ → Ապրանքներ → Ստեղծել ապրանք**։ Ընտրեք «Ընդհանուր հոսթինգ» տեսակը, ապրանքների խումբը, անվանումը և slug-ը։ **Փաթեթի անվանում** դաշտում գրեք սերվերի վրա գոյություն ունեցող փաթեթի ճշգրիտ անունը և հիմնական արժույթով գինը լրացրեք առնվազն մեկ վճարման ժամանակահատվածի համար։ Դատարկ գինը ապրանքը այդ ժամանակահատվածում անվաճառելի է դարձնում։ **Թաքնված** նշումը չդնեք, որպեսզի հաճախորդները կարողանան պատվիրել։ Ամբողջ ձևը նկարագրված է [Ապրանքներ և գնագոյացում](/hy/staff/products) էջում։

## 7. Միացրեք վճարման եղանակը {#7-turn-on-a-payment-method}

Hostpanel-ի մեջ ներկառուցված է բանկային փոխանցումը, իսկ առցանց վճարային համակարգերը գալիս են plugin-ներից։ Առաջին փորձի համար բանկային փոխանցումը բավական է։ Բացեք **Ինտեգրացիաներ**, **Վճարային համակարգեր** կատեգորիան, «Բանկային փոխանցում» քարտի վրա սեղմեք **Կարգավորել →**, լրացրեք բանկային տվյալներից առնվազն մեկը, պահպանեք և միացրեք այն։ Հաճախորդներին բանկային փոխանցումը առաջարկվում է միայն այն ժամանակ, երբ այն միացված է և առնվազն մեկ տվյալ լրացված է։ Մանրամասներն ու plugin-ների ճանապարհը՝ [Վճարային համակարգեր](/hy/payments/gateways) էջում։

## 8. Կատարեք փորձնական պատվեր {#8-place-a-test-order}

Բացեք հաճախորդի պորտալը, պատվիրեք ապրանքը և վճարեք բանկային փոխանցմամբ, տես [Պատվիրում](/hy/customers/ordering)։ Ապա ադմինի վահանակում բացեք **Հաշվարկներ**, **Սպասվող բանկային փոխանցումներ** և սեղմեք **Հաստատել**։ Հաշիվ-ապրանքագիրը վճարվում է, պատվերը կատարվում է։

## 9. Ստեղծեք ծառայությունը {#9-provision-the-service}

Վճարված պատվերը ստեղծում է ծառայություն **Սպասման մեջ** կարգավիճակով։ Hostpanel-ը հոսթինգի հաշիվը այդ պահին չի ստեղծում։ Արեք հետևյալներից մեկը.

- Հիմնական ճանապարհ. հաճախորդի պորտալում հաճախորդը վճարումից հետո սեղմում է **Կարգավորել ծառայությունը** կամ ավելի ուշ ծառայության վրա՝ **Անցնել կարգավորումը**, և կարգավորման օգնականում ընտրում է դոմենը և մուտքի տվյալները, տես [Պատվիրում](/hy/customers/ordering) և [Ծառայություններ](/hy/customers/services)։ Այն հասանելի է առաջին հաշիվ-ապրանքագիրը ամբողջությամբ վճարելուց հետո։
- Ադմինի վահանակում բացեք ծառայությունը և **Մոդուլի հրամաններ** քարտում սեղմեք **Ստեղծել**։ Սա աշխատում է միայն այն դեպքում, երբ ծառայության համար նշված են դոմենը և օգտանունը։ Առանց դրանց հարցումը մերժվում է `SERVICE_HOSTING_DETAILS_MISSING` (409) կոդով, տես [Ինչ է կատարվում պրովիժնինգի ժամանակ](/hy/servers/provisioning#what-happens-on-provisioning)։

Երբ վահանակը հաստատում է, ծառայությունը դառնում է **Ակտիվ**, իսկ հաճախորդը ստանում է `service-provisioned` նամակը։ Եթե ինչ-որ բան ձախողվի, սխալի կոդը բացատրված է [Պրովիժնինգ](/hy/servers/provisioning) էջում։

## Ինչ անել հետո {#where-to-go-next}

- Առկա հաճախորդների տեղափոխում՝ [Միգրացիայի ստուգացանկ](/hy/migration/fifteen-minutes)։
- Իրական հաճախորդներ ընդունելուց առաջ պահուստավորեք տվյալների բազան և `.env`-ը՝ [Պահուստավորում և վերականգնում](/hy/operators/backup)։
- Ամենօրյա աշխատանք՝ [Աշխատակիցների ուղեցույց](/hy/staff/)։
