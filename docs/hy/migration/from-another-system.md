# Տեղափոխում WHMCS-ից {#moving-from-whmcs}

<Label type="admin" />

<DemoLink path="/migration" />

Hostpanel-ը ներմուծում է ձեր տվյալները WHMCS-ից։ Դուք WHMCS-ում տեղադրում եք փոքր PHP հավելում (addon)։ Այնուհետև Hostpanel-ը հավելումից մեկ-մեկ էջերով հարցնում է ձեր գրառումները և ներմուծում դրանք։ WHMCS-ում ոչինչ հետ չի գրվում։

## Ինչ է պետք {#what-you-need}

- WHMCS տեղադրում, որն աշխատում է PHP 8.1-ով կամ ավելի նոր տարբերակով։ Հավելումն օգտագործում է PHP 8.1-ի հնարավորություններ։
- Այդ WHMCS-ի հանրային HTTPS հասցե։ Hostpanel-ը կանչում է այն ձեր Hostpanel սերվերից։
- Երկու համակարգերի ադմինի հասանելիություն, ինչպես նաև FTP կամ SSH հասանելիություն WHMCS-ի ֆայլերին։

## WHMCS-ից՝ հինգ քայլով {#from-whmcs-in-five-steps}

1. Hostpanel-ում անցեք **Միգրացիայի գործիքներ**, սեղմեք **Նոր միգրացիա**, մուտքագրեք ձեր WHMCS-ի հասցեն և ընտրեք ներմուծվող տվյալները։ Hostpanel-ը ստեղծում է գաղտնի բանալի։
2. Առաջադրանքի քարտից ներբեռնեք `innovayse-migration.zip` ֆայլը և բացեք այն WHMCS-ի արմատային թղթապանակում։
3. WHMCS-ում անցեք **Configuration > System Settings > Addon Modules**, ակտիվացրեք **Hostpanel Migration**, սեղմեք **Configure** և բանալին տեղադրեք **Migration Key** դաշտում։
4. Hostpanel-ում սեղմեք **Ստուգել**։ Սպասեք «Պլագինը միացված է» հաղորդագրությանը։
5. Սեղմեք **Սկսել ներմուծումը**, ապա ավարտից հետո դիտեք **Ներմուծման հաշվետվությունը**։

Ստորև բաժիններում բացատրվում է յուրաքանչյուր քայլը և ինչ անել, երբ ինչ-որ բան սխալ է ընթանում։

## Ինչպես է աշխատում միգրացիան {#how-a-migration-works}

Միգրացիայի առաջադրանքը պահում է գաղտնի բանալի։ Սկզբնաղբյուր համակարգի հավելումը կարդում է յուրաքանչյուր հարցում, ստուգում է բանալին և վերադարձնում է մեկ էջ գրառումներ։ Hostpanel-ը ներմուծում է յուրաքանչյուր էջը՝ նախքան հաջորդը հարցնելը։ Ներմուծումն աշխատում է ֆոնում, ուստի բրաուզերը փակելը այն չի դադարեցնում։

Եթե սերվերը վերագործարկվում է ներմուծման կեսին, վերականգնման աշխատանքը (`RecoverInterruptedMigrationJobsCommand`) գործարկվում է յուրաքանչյուր հինգ րոպեն մեկ և ձախողված է նշում ցանկացած առաջադրանք, որի heartbeat-ը չի թարմացվել վերջին տասնհինգ րոպեում (երկու ընդմիջումներն էլ կարգավորվում են), որպեսզի առաջադրանքը կարողանա կրկնվել։

Աղբյուրի հասցեն պետք է լինի հանրային HTTPS հասցե։ Ներքին հասցեները և ոչ HTTPS սխեմաները թույլատրված չեն։

## Ինչ է ներմուծվում {#what-is-imported}

Գրառումները քաշվում են այս կարգով։ Կարգը կարևոր է. ծառայությանը նախ պետք է գոյություն ունենան իր հաճախորդն ու ապրանքը։ Աջակցության հայտի պատասխանին՝ իր հայտը։

| Կարգ | Գրառման տեսակ | Նշումներ |
|---|---|---|
| 1 | Հաճախորդներ | Մեկ հաշիվ՝ յուրաքանչյուր հաճախորդի համար։ |
| 2 | Կոնտակտներ | Ներմուծված հաճախորդի ենթակոնտակտներ։ |
| 3 | Ապրանքներ | Ապրանքների կատալոգ՝ ապրանքների խմբերով։ |
| 4 | Հաշիվ-ապրանքագրեր | Հաճախորդին կապվում են էլ. հասցեով։ |
| 5 | Ծառայություններ | Կապվում են հաճախորդին և ապրանքին՝ ըստ անվան։ |
| 6 | Դոմեններ | Կապվում են հաճախորդին։ |
| 7 | Աջակցության հայտեր | Կապվում են հաճախորդին։ |
| 8 | Պատվերներ | Այստեղ կապվում են ապրանքներին։ |
| 9 | Գործարքներ | Կապվում են հաշիվ-ապրանքագրին։ |
| 10 | Գնառաջարկներ | Կապվում են հաճախորդին։ |
| 11 | Գիտելիքների բազա | Հոդվածներ և դրանց կատեգորիաներ։ |
| 12 | Հայտերի պատասխաններ | Ներմուծված հայտերի պատասխանները։ |
| 13 | Հայտարարություններ | Հանրային հայտարարություններ։ |
| 14 | Ներբեռնումներ | Ֆայլեր և դրանց կատեգորիաներ։ |
| 15 | Ցանցային խնդիրներ | Կարգավիճակի էջի միջադեպեր։ |

Առաջադրանք ստեղծելիս ընտրում եք, թե որ տեսակները ներառել։ Չընտրված տեսակները լիովին բաց են թողնվում։

## Ինչ չի ներմուծվում {#what-is-not-imported}

**Գաղտնաբառեր։** Տեղափոխված հաճախորդները ստանում են պատահական, անօգտագործելի գաղտնաբառ։ Նրանք պետք է այն վերականգնեն գաղտնաբառի վերականգնման ընթացքով՝ նախքան մուտք գործելը։

<Callout type="note">
Ասեք ձեր հաճախորդներին, որ տեղափոխումից հետո առաջին մուտքի ժամանակ օգտագործեն «Մոռացել եմ գաղտնաբառը»։
</Callout>

Գրառումները, որոնք հավելումը չի արտահանում, չեն ներմուծվում, և դրանք պետք է նորից կարգավորեք ձեռքով։ Դրանց թվում են վճարային համակարգերի տվյալները, էլ. փոստի մատյանները և երկգործոն նույնականացման կարգավորումները։

## Նախքան սկսելը {#before-you-start}

<Callout type="danger">
Առաջին ներմուծումից առաջ կատարեք Hostpanel տվյալների բազայի պահուստային պատճեն։ Միգրացիան հնարավոր չէ ավտոմատ հետ շրջել։ Եթե ինչ-որ բան սխալ ընթանա, պահուստային պատճենը վերականգնման միակ ճանապարհն է։
</Callout>

<Callout type="tip">
Ներմուծումից առաջ Hostpanel-ում կարգավորեք արժույթները, հոսթինգի սերվերներն ու աջակցության բաժինները։ Ծառայությունները կապվում են ապրանքներին և սերվերներին, աջակցության հայտերը՝ բաժիններին։ Այն գրառումները, որոնց ծնողը այստեղ գոյություն չունի, բաց են թողնվում։
</Callout>

## Միգրացիայի ստեղծում {#create-a-migration}

<Steps>
<li>

**Բացեք Միգրացիայի գործիքները**

Ադմինի վահանակում անցեք **Միգրացիայի գործիքներ** և սեղմեք **Նոր միգրացիա**։

Լրացրեք.
- **Աղբյուրի URL**՝ ձեր WHMCS-ի արմատային հասցեն, օրինակ՝ `https://billing.example.com`։ Hostpanel-ը ինքն է ավելացնում հավելման ուղին՝ `/modules/addons/innovayse_migration/api.php`։ Կարող եք նաև տեղադրել լրիվ հասցեն, որը ցույց է տալիս հավելման սեփական էջը։ Ուղին երկու անգամ չի ավելացվում։
- **Պիտակ** (ոչ պարտադիր)՝ այս առաջադրանքի անվանումը, օրինակ՝ `Production Server`։
- **Ներմուծվող տվյալներ**՝ քաշվող գրառումների տեսակները։ Օգտագործեք **Ընտրել բոլորը** կամ ընտրեք առանձին տեսակներ։

Սեղմեք **Ստեղծել միգրացիա**։ Առաջադրանքի համար ստեղծվում է գաղտնի բանալի։

</li>
<li>

**Տեղադրեք հավելումը WHMCS-ում**

**Անհրաժեշտ է կարգավորում** քարտից ներբեռնեք `innovayse-migration.zip` ֆայլը և բացեք այն WHMCS-ի արմատային թղթապանակում։ Ֆայլերը հայտնվում են.

```
/modules/addons/innovayse_migration/
```

WHMCS-ի ադմինի մասում անցեք **Configuration > System Settings > Addon Modules**։ Գտեք **Hostpanel Migration** և սեղմեք **Activate**, ապա **Configure**։ **Անհրաժեշտ է կարգավորում** քարտից գաղտնի բանալին տեղադրեք **Migration Key** դաշտում և սեղմեք **Save Changes**։

**Access Control**-ի տակ նշեք ադմինի այն դերերը, որոնք կարող են բացել հավելման էջը WHMCS-ում։ Այդ էջը ցույց է տալիս՝ բանալի սահմանված է արդյոք, և **Աղբյուրի URL**-ը, որը կանչում է Hostpanel-ը։ Հենց ներմուծման համար ոչ մի դեր նշել պետք չէ։

</li>
<li>

**Ստուգեք միացումը**

Սեղմեք **Ստուգել**։ Hostpanel-ը կանչում է հավելման ping endpoint-ը։ Քարտը ցույց է տալիս հետևյալներից մեկը.
- **Պլագինը միացված է**՝ բանալին ընդունվեց։
- **Ստուգվում է…**՝ հարցումը ընթացքի մեջ է։
- **Սպասում է պլագինին…**՝ սպասում է կրկնելու համար։
- **Անհասանելի է**՝ հավելումը չպատասխանեց կամ մերժեց բանալին։ Ստուգեք աղբյուրի URL-ը, համոզվեք, որ հավելումը ակտիվ է WHMCS-ում, և որ հավելման կարգավորումներում բանալին համընկնում է քարտի վրա եղածի հետ։

</li>
<li>

**Սկսեք ներմուծումը**

Սեղմեք **Սկսել ներմուծումը**։ Առաջադրանքն անցնում է **Հերթում է** վիճակի, ապա **Կատարվում է**, երբ ֆոնային աշխատողը վերցնում է այն։ **Տեղափոխված**, **Բաց թողնված** և **Ձախողված** հաշվիչները թարմացվում են գրառումների մշակման ընթացքում։

</li>
</Steps>

## Առաջադրանքի կարգավիճակներ {#job-statuses}

| Կարգավիճակ | Նշանակություն |
|---|---|
| Սպասում է | Առաջադրանքը ստեղծված է, դեռ չի սկսվել։ |
| Հերթում է | Մեկնարկը պահանջվել է։ Ֆոնային աշխատողը դեռ չի վերցրել այն։ |
| Ընթանում է | Աշխատողն ակտիվորեն քաշում է տվյալները։ |
| Ավարտված է | Ընտրված բոլոր գրառումների տեսակները քաշվել են առանց սխալի։ |
| Ձախողված է | Ներմուծումը կանգ առավ՝ նախքան ավարտվելը։ |

## Երբ առաջադրանքը ձախողվում է {#when-a-job-fails}

Ձախողման պատճառը ցուցադրվում է առաջադրանքի քարտի վրա։ Սեղմեք **Կրկնել ներմուծումը**՝ ներմուծումը նորից հերթագրելու համար։ Կրկնությունը զրոյացնում է հաշվիչները և սկսում է սկզբից։ Արդեն ներմուծված գրառումները բաց են թողնվում, ուստի կրկնությունը ավելացնում է միայն նորը։

| Պատճառ | Ինչ անել |
|---|---|
| Աղբյուրը հասանելի չէ | Ստուգեք աղբյուրի URL-ը և համոզվեք, որ WHMCS-ը աշխատում է։ |
| Աղբյուրը մերժեց հարցումը, ստուգեք բանալին | Հավելումը պատասխանեց սխալի կարգավիճակով։ Առավել հաճախ բանալին սխալ է, կամ հավելումը ակտիվ չէ։ Նորից պատճենեք բանալին առաջադրանքի քարտից հավելման կարգավորումներ։ Նույն պատճառը ցուցադրվում է, երբ հավելումը պատասխանում է 429 (այս հասցեից չափազանց շատ սխալ բանալիներ։ Սպասեք 15 րոպե), 503 (հավելումը չի կարող գրել իր փորձերի մատյանը սերվերի ժամանակավոր թղթապանակում) կամ 500 (արտահանումը ձախողվեց։ Ստուգեք WHMCS-ի սխալների մատյանը)։ |
| Գրառումները հնարավոր չեղավ ներմուծել | Մանրամասների համար ստուգեք սերվերի մատյանը։ Շտկեք հիմնական խնդիրը և կրկնեք։ |
| Ներմուծումը դադարեցվեց | Ներմուծումը չեղարկվել է։ Կրկնեք, երբ պատրաստ լինեք։ |
| Սերվերը կանգ առավ մինչև ներմուծման ավարտը | Գործընթացը ընդհատվել է (վերագործարկում կամ խափանում)։ Վերականգնման աշխատանքը գործարկվում է յուրաքանչյուր 5 րոպեն մեկ և ձախողում է 15 րոպե heartbeat չունեցող ցանկացած առաջադրանք (երկուսն էլ կարգավորվում են)։ Կրկնեք, երբ սերվերը կայուն լինի։ |
| Աղբյուրի հասցեն թույլատրված չէ, նշեք հանրային HTTPS հասցե | Աղբյուրի URL-ը պետք է օգտագործի HTTPS և վերածվի հանրային հասցեի։ Ներքին հասցեները թույլատրված չեն։ |

## Կրկնեք անվտանգ {#run-it-again-safely}

<Callout type="note">
Գրառումների յուրաքանչյուր տեսակ երկրորդ գործարկման ժամանակ բաց է թողնում կրկնօրինակները։ Ապրանքների խմբերը, գիտելիքների բազայի կատեգորիաները և ներբեռնումների կատեգորիաները վերօգտագործվում են անաղմուկ։ Մնացած բոլոր առկա գրառումները մատյանում գրանցվում են որպես Բաց թողնված՝ «Արդեն գոյություն ունի» պատճառով և մնում են անփոփոխ։
</Callout>

Գրառումները համընկնեցվում են այսպես. հաճախորդները՝ էլ. հասցեով, կոնտակտները՝ էլ. հասցեով, ապրանքները՝ անունով, դոմենները՝ դոմենի անունով, ծառայությունները՝ հաճախորդով և աղբյուրի ծառայության id-ով (id-ի պահպանումից առաջ ներմուծված տողերը՝ հաճախորդով և դոմենով կամ վահանակի օգտանունով), հաշիվ-ապրանքագրերը՝ հաճախորդով և արտաքին id-ով, աջակցության հայտերն ու գնառաջարկները՝ հաճախորդով և թեմայով, պատվերները՝ պատվերի համարով, գործարքները՝ հաճախորդով և գործարքի id-ով, գիտելիքների բազայի հոդվածները՝ վերնագրով, հայտարարությունները՝ վերնագրով և ամսաթվով (միայն վերնագրով, երբ աղբյուրը ամսաթիվ չունի), ցանցային խնդիրները՝ վերնագրով և սկսվելու ամսաթվով (միայն վերնագրով, երբ աղբյուրը սկսվելու ամսաթիվ չունի), ներբեռնումները՝ վերնագրով և կատեգորիայով, հայտերի պատասխանները՝ հայտով, հեղինակով, դերով և հաղորդագրությամբ։ Ներբեռնումների կատեգորիաները համընկնեցվում են անունով։

Աղբյուրի գրառման յուրաքանչյուր ծառայություն կրում է իր սեփական id-ն, ուստի կրկնությունը բաց է թողնում արդեն ներմուծված ծառայությունը, նույնիսկ եթե այն դոմեն կամ վահանակի օգտանուն չունի, և նույն դոմենը կիսող երկու ծառայություններն էլ ներմուծվում են։ Հաճախորդով և դոմենով (կամ վահանակի օգտանունով) համընկնեցվում են միայն id-ի պահպանումից առաջ ներմուծված ծառայությունները։ Նրանցից այն ծառայությունը, որն ոչ մեկը չունի, համընկնեցման բանալի չունի և կրկնության ժամանակ ներմուծվում է նորից։

Համընկնեցման բանալի ունեցող տեսակների համար (հաճախորդներ, կոնտակտներ, ապրանքներ, ծառայություններ, դոմեններ, հաշիվ-ապրանքագրեր, աջակցության հայտեր, գնառաջարկներ, պատվերներ, գործարքներ, գիտելիքների բազայի հոդվածներ, հայտարարություններ, ցանցային խնդիրներ, ներբեռնումներ և հայտերի պատասխաններ) նույն առաջադրանքի երկրորդ գործարկումը ավելացնում է միայն այն գրառումները, որոնք նոր են վերջին գործարկումից հետո։

Փոփոխված գրառումը նորից ներմուծելու համար նախ ջնջեք այն Hostpanel-ում, ապա կրկնեք առաջադրանքը։

## Ստուգեք արդյունքը {#check-the-result}

Ներմուծումն ավարտվելուց հետո ընտրովի ստուգեք տվյալները.

- Հաճախորդների քանակը համընկնում է WHMCS-ի հետ։
- Բաց հաշիվ-ապրանքագրերն ու մնացորդները ճիշտ են։
- Ակտիվ ծառայությունները գտնվում են ճիշտ սերվերների վրա։
- Դոմենների ժամկետանցի ամսաթվերը ճիշտ են։
- Բաց աջակցության հայտերը ճիշտ բաժիններում են։
- Ընտրեք հինգ հաճախորդ և սկզբից մինչև վերջ ստուգեք նրանց ծառայությունները, հաշիվ-ապրանքագրերն ու հայտերը։

Բացեք **Ներմուծման հաշվետվությունը**՝ բոլոր բաց թողնված և ձախողված գրառումները դիտելու համար։ Տես [Ներմուծման հաշվետվություն և բաց թողնելու պատճառներ](/hy/migration/import-report)։

## Տեղափոխումից հետո {#after-the-move}

Երբ միգրացիան ավարտված է և ստուգված.

- WHMCS-ում մաքրեք հավելման **Migration Key** դաշտը և պահպանեք։ Առանց բանալու հավելումը մերժում է յուրաքանչյուր հարցում։ Ապա ապաակտիվացրեք հավելումը և ջնջեք `modules/addons/innovayse_migration/` թղթապանակը։
- Ջնջեք հին միգրացիայի առաջադրանքները (**Ջնջել միգրացիան**), երբ դրանց ներմուծման հաշվետվությունն այլևս պետք չէ։ Սա հեռացնում է առաջադրանքը և նրա ամբողջ մատյանը և հնարավոր չէ չեղարկել։

`ping` գործողությունը վերադարձնում է `{"ok":true}`։ `totals` գործողությունը վերադարձնում է մեկ քանակ՝ յուրաքանչյուր էության տեսակի համար։ Տվյալների բազմությունների գործողությունները վերադարձնում են տողերի մեկ էջ։

### Նույնականացում {#authentication}

Հավելումը ստուգում է բանալին հաստատուն ժամանակում։ 15 րոպեանոց պատուհանում 10 ձախողված փորձից հետո զանգահարողի հասցեն արգելափակվում է մինչև պատուհանի ավարտը։ Հաջող նույնականացումը զրոյացնում է հաշվիչը։

### Սխալի պատասխաններ {#error-responses}

| HTTP կարգավիճակ | Հաղորդագրություն | Պայման |
|---|---|---|
| 401 | `Invalid migration key.` | Բանալին բացակայում է, կարգավորված չէ կամ սխալ է։ |
| 429 | `Too many failed attempts.` | Հասցեն արգելափակվել է սահմանափակիչի կողմից։ |
| 503 | `Attempt log unavailable.` | Սահմանափակիչի մատյանի ֆայլը հնարավոր չէ կարդալ կամ գրել։ |
| 400 | `Unknown action.` | `action` դաշտը ոչ մի հայտնի գործողություն չի նշում։ |
| 500 | `Source system bootstrap not found.` | `init.php`-ը այնտեղ չէ, որտեղ հավելումը սպասում է։ |
| 500 | `Export failed.` | Արտահանողը սխալ նետեց։ Մանրամասները զանգահարողին չեն վերադարձվում։ |

### Թեստերի գործարկում {#running-the-tests}

```bash
cd backend/plugins/innovayse_migration
composer install
./vendor/bin/phpunit
```

Թեստերն օգտագործում են հիշողության մեջ աշխատող տվյալների բազայի դրայվեր և չեն պահանջում աշխատող սկզբնաղբյուր համակարգ։

### Սխալի կոդեր (Hostpanel API) {#error-codes-hostpanel-api}

Hostpanel API-ն վերադարձնում է այս կոդերը միգրացիայի գործողությունների համար.

| Կոդ | Հաղորդագրություն |
|---|---|
| `MIGRATION_JOB_NOT_FOUND` | Այդպիսի միգրացիայի առաջադրանք չկա։ |
| `MIGRATION_JOB_NOT_PENDING` | Այս միգրացիայի առաջադրանքն արդեն սկսվել կամ ավարտվել է և չի կարող նորից սկսվել։ |
| `MIGRATION_JOB_NOT_FAILED` | Այս միգրացիայի առաջադրանքը չի ձախողվել, ուստի չի կարող կրկնվել։ |
| `MIGRATION_JOB_INVALID_TRANSITION` | Այս միգրացիայի առաջադրանքը իր ընթացիկ վիճակում չի կարող դա անել։ |
| `MIGRATION_PLUGIN_NOT_FOUND` | Միգրացիայի պլագինը հասանելի չէ այս տեղակայման վրա։ |
| `MIGRATION_CONNECTION_UPSTREAM_FAILED` | Սկզբնաղբյուր համակարգին չհաջողվեց հասնել։ Ստուգեք հասցեն և կրկին փորձեք։ |
