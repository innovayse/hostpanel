# cPanel սերվերներ <Label type="admin" /> {#cpanel-servers}

Hostpanel-ը կառավարում է cPanel հաշիվները WHM API 1-ի միջոցով։ Մեկ ծառայությունը մեկ cPanel հաշիվ է։

<Callout type="warning">
Այս ինտեգրացիան դեռ չի փորձարկվել իրական WHM սերվերի վրա։ Կանչերը հետևում են cPanel-ի WHM API 1 տեղեկատուին և փորձարկված են միայն կեղծ (stub) սերվերի վրա։ Հաճախորդների համար օգտագործելուց առաջ փորձեք այն թեստային սերվերի վրա և հաղորդեք ձեր գտածոների մասին։
</Callout>

## Ինչ է անում {#what-it-does}

| Գործողություն Hostpanel-ում | WHM API 1 ֆունկցիա |
|---|---|
| Ստեղծել | `createacct`՝ `username`, `domain`, `password` և `plan` պարամետրերով |
| Կասեցնել | `suspendacct`՝ `user` և `reason` պարամետրերով |
| Վերսկսել | `unsuspendacct`՝ `user` պարամետրով |
| Դադարեցնել | `removeacct`՝ `username` պարամետրով |
| Փոխել փաթեթը | `changepackage`՝ `user` և `pkg` պարամետրերով |
| Փոխել գաղտնաբառը | `passwd`՝ `user` և `password` պարամետրերով |
| Մուտք cPanel | `create_user_session`՝ `user` և `service=cpaneld` պարամետրերով |
| Միացման ստուգում | `version`, ապա `listaccts`՝ հաշիվները հաշվելու համար |
| Հաշվի որոնում | `listaccts`՝ `searchtype=user` և `searchmethod=exact` պարամետրերով |

Ապրանքի **Փաթեթի անվանում** դաշտը պետք է լինի սերվերի վրա գտնվող WHM փաթեթի ճշգրիտ անվանումը։

## WHM-ում API թոքենի ստեղծում {#create-an-api-token-in-whm}

1. Մուտք գործեք WHM որպես `root` կամ որպես վերավաճառող (reseller), որին պատկանում են հաշիվները։
2. Անցեք **Development > Manage API Tokens** և սեղմեք **Generate Token**։
3. Տվեք նրան անուն, օրինակ՝ `hostpanel`։ Պատճենեք թոքենը։ WHM-ը ցույց է տալիս այն միայն մեկ անգամ։

Վերավաճառողի թոքենը կարող է կառավարել միայն այդ վերավաճառողի սեփական հաշիվները։

## Սերվերի ավելացում Hostpanel-ում {#add-the-server-in-hostpanel}

Անցեք **Սերվերներ**, սեղմեք **Ավելացնել նոր սերվեր** և **Ընդհանուր** ներդիրը լրացրեք ինչպես ցանկացած սերվերի համար։ **Մանրամասներ** ներդիրում.

| Դաշտ | Արժեք |
|---|---|
| Մոդուլ | cPanel |
| Օգտանուն | WHM օգտատերը, որին պատկանում է թոքենը, օրինակ՝ `root` |
| API թոքեն | WHM-ից ստացված թոքենը |

**Գաղտնաբառ** և **Մուտքի հեշ** դաշտերը cPanel-ի համար չեն օգտագործվում։ API թոքենը պահվում է `ENCRYPTION_KEY`-ով գաղտնագրված, ինչպես սերվերի մյուս գաղտնի արժեքները, և երբեք չի գրվում մատյանում։

**Օգտագործել SSL միացումների համար** դաշտը cPanel-ի համար անտեսվում է։ WHM-ին և հաշվի տերերին ցուցադրվող cPanel հասցեին միշտ միանում են HTTPS-ով՝ անկախ այդ վանդակից։

Ապա սեղմեք **Ստուգել միացումը**։ Աշխատող թոքենը ցույց է տալիս WHM-ի տարբերակը և հաշիվների քանակը։ `SERVER_CONNECTION_NO_API_KEY` նշանակում է, որ օգտանունը կամ API թոքենը բացակայում է։ Սերվերը, որը թոքենի ճիշտ լինելու դեպքում էլ հասանելի չէ, սովորաբար ներկայացնում է ինքնաստորագրված վկայական, տես [Անվտանգության նշումներ](#security-notes)։

## Պորտեր {#ports}

Hostpanel-ը WHM-ին կանչում է 2087 պորտով և հաշվի տերերին ցույց է տալիս cPanel հասցեն 2083 պորտով։ Երկուսն էլ HTTPS են։ Փոխեք դրանք բոլոր cPanel սերվերների համար միանգամից `Provisioning` կարգավորումներում.

| Կարգավորում | Լռելյայն |
|---|---|
| `Provisioning__CPanelWhmPort` | `2087` |
| `Provisioning__CPanelUserPort` | `2083` |

## Ինչ է ստուգում Hostpanel-ը՝ նախքան WHM-ին կանչելը {#what-hostpanel-checks-before-it-calls-whm}

- Նոր հաշվի հաշվի օգտանունը պետք է լինի 1-ից 16 փոքրատառ և թվանշան և սկսվի տառով։ Արդեն գոյություն ունեցող հաշիվները շարունակում են աշխատել իրենց պահված անվան տակ։ Կանոնը խախտող օգտանունը կանգնեցնում է կարգավորումը `CPANEL_USERNAME_INVALID` կոդով, և WHM-ին չի կանչվում։ Նույն կանոնը կիրառվում է այնտեղ, որտեղ աշխատակիցները պահպանում են cPanel սերվերի վրա «Սպասման մեջ» ծառայության հոսթինգի հաշիվը, իսկ աշխատակիցների ավելացրած առկա հաշիվը պետք է ունենա WHM-ի կողմից հասցեավորվող անուն (տառեր, թվանշաններ, ընդգծման նշան, գծիկ կամ կետ՝ մինչև 32 նիշ), ուստի վատ անունը ձախողվում է վաղ։
- Դոմենը պետք է լինի ճիշտ ձևավորված դոմենի անուն՝ առնվազն երկու պիտակով, ASCII նիշերով (միջազգայնացված անունը մուտքագրվում է իր `xn--` տեսքով)։ Հակառակ դեպքում կարգավորումը կանգնում է `CPANEL_DOMAIN_INVALID` կոդով։
- Դատարկ արժեքը երբեք չի ուղարկվում WHM-ին։
- WHM-ի 16 ՄԲ-ից մեծ պատասխանը համարվում է անընթեռնելի։
- Երբ WHM-ը չի պատասխանում ստեղծման կանչին, և Hostpanel-ը հետո նույնպես չի կարողանում հաշիվը որոնել, կարգավորումը ձախողվում է որպես ժամանակավոր սխալ, այլ ոչ թե մերժում, քանի որ հաշիվը կարող է գոյություն ունենալ։ Կրկնեք կարգավորումը, երբ սերվերը պատասխանի։

## Ինչպես են աշխատում կրկնությունները {#how-retries-behave}

- Ստեղծում. եթե WHM-ը մերժում է, և այդ օգտանունով հաշիվ արդեն կա, Hostpanel-ը հաղորդում է առկա հաշվի մասին՝ նրա դոմենով։ Այն որդեգրվում է միայն եթե դոմենը ծառայության սեփականն է։
- Կասեցում և վերսկսում. մերժումն ընդունվում է, եթե հաշիվն արդեն պահանջվող վիճակում է։
- Դադարեցում. մերժումն ընդունվում է միայն երբ WHM-ը հստակ հաղորդում է, որ այդպիսի հաշիվ չկա։
- Փաթեթի փոփոխություն. մերժումն ընդունվում է, եթե հաշիվն արդեն պահանջվող փաթեթի վրա է։
- Եթե Hostpanel-ը չի կարողանում կարդալ WHM-ի պատասխանը, այն երբեք չի ենթադրում, թե հաշիվը չկա կամ ստեղծվել է։
- Ստեղծում կորած պատասխանով. եթե դրան հաջորդող որոնումը նույնպես կորում է, կարգավորումը պատասխանում է `PROVISIONING_OUTCOME_UNKNOWN` (503)՝ մերժման փոխարեն, ծառայությունը մնում է «Սպասման մեջ», և կրկնությունը կարգավորում է հարցը։

WHM-ի սեփական սխալի տեքստը երբեք չի ցուցադրվում և չի գրվում մատյանում, քանի որ այն կարող է նշել հաշվի անունը։

## Անվտանգության նշումներ {#security-notes}

- WHM-ի յուրաքանչյուր կանչ POST է, և նրա արգումենտները, ներառյալ `createacct`-ի և `passwd`-ի հաշվի գաղտնաբառը, ուղարկվում են հարցման մարմնում, այլ ոչ թե URL-ում, ուստի WHM-ի մուտքի մատյանը և նրա առջև դրված ցանկացած proxy գաղտնաբառը չեն գրանցում։ Hostpanel-ը երբեք չի գրանցում այդ URL-ները, և WHM-ի HTTP կլիենտի հարցումների գրանցումն անջատված է։
- WHM-ը պետք է ներկայացնի վկայական, որին Hostpanel-ը վստահում է՝ թողարկված հանրային մարմնի կողմից կամ այնպիսի մարմնի, որին վստահում է ձեր Hostpanel հոսթը։ WHM-ը գալիս է ինքնաստորագրված վկայականով, իսկ Hostpanel-ը չի շրջանցում վկայականների ստուգումը, ուստի այն դեռ օգտագործող սերվերը միացումը ստուգելիս երևում է որպես անհասանելի։ Նախ տեղադրեք վստահելի վկայական WHM-ում։
- `create_user_session`-ից ստացված մեկանգամյա մուտքի (single sign-on) հղումները մեկանգամյա են և ժամկետանց են դառնում։ WHM-ը դրանք չի կապում բրաուզերի հասցեին։ Hostpanel-ը հղումը բրաուզերին է տալիս միայն եթե այն `https` հասցե է՝ առանց օգտանվան կամ գաղտնաբառի, նրա հոսթը սերվերի սեփական հոսթի անունն է կամ IP հասցեն (համեմատվում է առանց տառաչափի հաշվառման, իսկ վերջի կետը դարձնում է այլ անուն), և նրա պորտը cPanel պորտն է (`Provisioning__CPanelUserPort`)։ Բրաուզերին տրվում է ստուգված հասցեն՝ իր վերլուծված տեսքով։ Ցանկացած այլ հղում դեն է նետվում, հաճախորդը տեսնում է `SERVICE_CPANEL_SSO_URL_UPSTREAM_FAILED`, և հղումից ոչինչ չի գրանցվում մատյանում։
- WHM-ի կանչերն անցնում են ելքային հասցեների պահակով (outbound address guard), ինչպես մյուս վահանակներինը։ Մասնավոր հասցեով սերվերին պետք է [մասնավոր ցանցի երթուղի](/hy/servers/servers#private-network-routes)։
