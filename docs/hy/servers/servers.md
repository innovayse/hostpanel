# Սերվերներ և սերվերների խմբեր <Label type="admin" /> {#servers-and-server-groups}

<DemoLink path="/servers" />

Պրովիժնինգի սերվերներն ու բեռի հավասարակշռման խմբերը կառավարելու համար անցեք **Սերվերներ** բաժին։ Ենթավերնագիր՝ «Մատակարարման սերվերների և բեռի հավասարակշռման խմբերի կառավարում»։

## Սերվերների ցանկ {#the-server-list}

Սերվերները խմբավորված են ըստ մոդուլի՝ յուրաքանչյուր մոդուլի համար մեկ աղյուսակում։ Յուրաքանչյուր տողում երևում են **Սերվերի անվանում**, **IP հասցե**, **Հաշիվներ**, **Կարգավիճակ** և **Գործողություններ**։ Սերվերի կարգավորումները բացելու համար տողի վրա սեղմեք **Խմբագրել**։ Երբ միացումը առողջ է, կարգավիճակը ցույց է տալիս «Առցանց · հաշիվներ՝ _n_ · _version_»։

**Կարգավիճակի նշաններ.** Առցանց, Օֆլայն, Չի ստուգվել։

**Տողի գործողություններ.** Ստուգել միացումը, SSH (բացում է SSH բանալիների կառավարման երկխոսությունը), Խմբագրել, Ջնջել։

**ԼՌԵԼՅԱՅՆ** նշանը ցույց է տալիս իր մոդուլի լռելյայն սերվերը։ Երբ մնացած պայմանները հավասար են, նոր հաշվի համար սերվեր ընտրելիս լռելյայն սերվերը նախապատվություն ունի իր խմբի կամ մոդուլի ներսում (տես [Լրացման տեսակներ](#fill-types))։

<Callout type="note">
<strong>CWP7</strong>-ը, <strong>Plesk</strong>-ը և <strong>cPanel</strong>-ը հաշիվներ ստեղծում են ավտոմատ։ cPanel-ը նոր է և դեռ չի փորձարկվել իրական WHM սերվերի վրա։ Տես <a href="/hy/servers/cpanel">cPanel սերվերներ</a>։ Մոդուլների ցանկի մյուս գրառումները (DirectAdmin, CentOS, Lukittu, Virtualmin, HyperVm) պահվում են, բայց հաշիվներն ավտոմատ չեն ստեղծում և չեն կարող ստուգվել։
</Callout>

## Սերվերի ավելացում {#add-a-server}

Սեղմեք **Ավելացնել նոր սերվեր**։ Ձևն ունի երեք ներդիր։

### Ընդհանուր ներդիր {#general-tab}

| Դաշտ | Նշումներ |
|------|----------|
| Անուն | Հասկանալի անվանում, որը ցուցադրվում է վահանակում |
| Հոսթի անվանում | Օգտագործվում է այս սերվերի հետ API միացումների համար |
| IP հասցե | Սերվերի հիմնական հանրային IP հասցեն |
| Նշանակված IP հասցեներ | Լրացուցիչ IP-ներ (մեկական տողում) |
| Ամսական արժեք (USD) | Ձեր սեփական հաշվառման համար |
| Տվյալների կենտրոն / NOC | օրինակ՝ Hetzner, OVH |
| Առավ. հաշիվների քանակ | Թողեք դատարկ՝ առանց սահմանափակման |
| Սերվերի կարգավիճակի հասցե | Կարգավիճակի էջի ամբողջական ուղին, որը ցուցադրվում է հաճախորդի պորտալի կարգավիճակի մոնիտորում |
| Լռելյայն սերվեր | Նշեք որպես այս մոդուլի լռելյայն սերվեր։ Երբ մնացած պայմանները հավասար են, այն նախապատվություն ունի իր խմբի կամ մոդուլի ներսում |
| Անջատել այս սերվերը | Արգելում է այստեղ նոր հաշիվներ նշանակել |

### Անվանային սերվերների ներդիր {#nameservers-tab}

Մինչև հինգ անվանային սերվեր (յուրաքանչյուրի հոսթի անունը և IP-ն), որոնք ցուցադրվում են հաճախորդներին, երբ այս սերվերում հաշիվ է ստեղծվում՝ Հիմնական, Երկրորդ, Երրորդ, Չորրորդ, Հինգերորդ։

### Մանրամասների ներդիր {#details-tab}

| Դաշտ | Նշումներ |
|------|----------|
| Մոդուլ | Կառավարման վահանակ՝ cPanel, Plesk, DirectAdmin, CentOS Web Panel, CWP7, Lukittu, Virtualmin, HyperVm |
| Օգտանուն | API օգտանուն |
| Գաղտնաբառ | API գաղտնաբառ (պահվում է գաղտնագրված) |
| API թոքեն | API թոքեն, երբ մոդուլը օգտագործում է թոքենով նույնականացում (պահվում է գաղտնագրված) |
| Մուտքի հեշ | Օգտագործվում է CWP7-ի և Plesk-ի կողմից API նույնականացման համար (պահվում է գաղտնագրված)։ cPanel-ը փոխարենը օգտագործում է Օգտանունը և API թոքենը |
| Օգտագործել SSL միացումների համար | Միացնում է HTTPS API հարցումների համար։ Անտեսվում է cPanel-ի համար, որին միշտ միանում են HTTPS-ով |

Խմբագրելիս ինքնության տվյալների դաշտերը ցույց են տալիս **(դատարկ՝ չփոխել)**։ Գաղտնի արժեքները պահվում են `ENCRYPTION_KEY`-ով գաղտնագրված։ Պորտի դաշտ չկա։ Վահանակի API պորտը ամրագրված է յուրաքանչյուր մոդուլի համար։

## Միացման ստուգում {#test-a-connection}

Սերվերի տողում սեղմեք **Ստուգել միացումը**։ Hostpanel-ը կանչում է սերվերի վահանակի API-ն և թարմացնում է կարգավիճակի նշանը։ Արդյունքը ցուցադրվում է տեղում, այլ ոչ թե որպես էջի սխալ։

**Հաջողություն.** «Առցանց · հաշիվներ՝ _n_ · _version_»

**Ստուգման արդյունքում ցուցադրվող ձախողման կոդեր.**

| Կոդ | Ինչ ստուգել |
|-----|-------------|
| `SERVER_CONNECTION_UNREACHABLE` | Հոսթի անունը կամ IP-ն սխալ է, վահանակի API պորտը արգելափակված է, կամ վահանակը չի աշխատում |
| `SERVER_CONNECTION_NO_ACCESS_HASH` | Այս սերվերի համար մուտքի հեշ պահված չէ։ Ավելացրեք այն Մանրամասների ներդիրում |
| `SERVER_CONNECTION_NO_API_KEY` | API բանալի կամ մուտքի հեշ պահված չէ։ Ավելացրեք տվյալները Մանրամասների ներդիրում |
| `SERVER_CONNECTION_MODULE_UNSUPPORTED` | Այս մոդուլը միացման ստուգում չունի։ Դրա համար ստուգումը հասանելի չէ |

## Սերվերի խմբագրում և ջնջում {#edit-and-delete-a-server}

Ձևը բացելու համար տողի վրա սեղմեք **Խմբագրել**։ Այլևս գոյություն չունեցող սերվերի հետ գործողությունները վերադարձնում են `SERVER_NOT_FOUND`։ Այն սերվերի ջնջումը, որը դեռ հյուրընկալում է հաճախորդների ծառայություններ կամ SSH բանալիներ, մերժվում է (`SERVER_IN_USE`)։

## Սերվերների խմբեր {#server-groups}

Սերվերների խմբերը թույլ են տալիս սերվերների մի հավաքածու նշանակել ապրանքին։ Նոր պատվերները բաշխվում են խմբի միջև՝ ըստ լրացման տեսակի։

### Խմբի ստեղծում {#create-a-group}

Սերվերների ցանկի տակ գտնվող **Խմբեր** բաժնում սեղմեք **Ստեղծել խումբ**։

| Դաշտ | Նշումներ |
|------|----------|
| Խմբի անվանում | օրինակ՝ «CWP սերվերներ» |
| Լրացման տեսակ | Ինչպես են հաշիվները բաշխվում (տես ներքևում) |
| Սերվերներ | Սերվերները Հասանելիից տեղափոխեք Խմբում |

### Լրացման տեսակներ {#fill-types}

| Լրացման տեսակ | Պիտակ |
|---------------|-------|
| LeastFull | Ավելացնել ամենաքիչ լցված սերվերին |
| FillUntilFull | Լցնել ակտիվ սերվերը մինչև լրիվ լինելը, ապա անցնել հաջորդին |

**Երբեք չընտրվող սերվերներ.** երկու տեսակի դեպքում էլ անջատված և լրիվ սերվերները բաց են թողնվում։ Սերվերը լրիվ է, երբ նրա հաշիվների քանակը հասել է Առավ. հաշիվների քանակին։ Առավ. հաշիվների քանակ 0-ն համարվում է լրիվ։ Առանց առավելագույնի սերվերը (դաշտը դատարկ թողնված է) երբեք լրիվ չէ։

**LeastFull.** հաղթում է ամենացածր լրացման հարաբերակցությամբ սերվերը (հաշիվներ ÷ առավ. հաշիվներ)։ Առանց առավելագույնի սերվերների լրացման հարաբերակցությունը 0 է։ Հավասարության դեպքում առավելությունը տրվում է լռելյայն սերվերին, ապա՝ ավելի մեծ տարողությամբ սերվերին, ապա՝ անվան առաջին սերվերին։

**FillUntilFull.** նախ օգտագործվում է լռելյայն սերվերը։ Դրանից հետո օգտագործվում են առավելագույն ունեցող սերվերները՝ անվան կարգով։ Առանց առավելագույնի սերվերները գալիս են վերջում՝ որպես արտահոսք։ Սերվերը լցվում է մինչև իր առավելագույնը, ապա օգտագործվում է հաջորդը։

**Առանց խմբի.** երբ ապրանքը սերվերների խումբ չունի, միշտ կիրառվում է LeastFull՝ անկախ ձեր խմբերի լրացման տեսակներից։

**Լռելյայն սերվեր.** բոլոր դեպքերում, երբ մնացած պայմանները հավասար են, լռելյայն սերվերը նախապատվություն ունի իր խմբի կամ մոդուլի ներսում։

<Callout type="note">
Հաշիվների քանակները գալիս են միացման ստուգումներից և Sync Server Account Counts աշխատանքից, ուստի ցուցադրվող և ընտրության համար օգտագործվող լրացվածությունը համաժամեցումների միջև մոտավոր է։
</Callout>

### Խմբի ջնջում {#delete-a-group}

Այն խմբի ջնջումը, որի մեջ ապրանքները դեռ պրովիժնինգ են անում, մերժվում է (`SERVER_GROUP_IN_USE`)։ Չօգտագործվող խմբի ջնջումը նրա բոլոր սերվերներին հանում է խմբից, բայց ինքը՝ սերվերները, չի ջնջում։

## Մասնավոր ցանցի երթուղիներ {#private-network-routes}

Երբ սերվերի կառավարման վահանակի API-ն հասանելի է միայն VPN-ով կամ մասնավոր ցանցով, տեղակայման միջավայրում սահմանեք `PANEL_HOST_ADDRESSES`՝ որպես `hostname=address` զույգեր (ստորակետով բաժանված, օրինակ՝ `srv4.example.com=10.77.0.1`)։ Hostpanel-ը կապվում է մասնավոր հասցեին, բայց հարցման և TLS վկայականի ստուգման համար պահպանում է հոսթի անունը, ուստի հաճախորդներին ուղղված հղումները և վկայականների ստուգումները չեն փոխվում։

Միջավայրի կարգավորումների ամբողջական ցանկի համար տես [Կարգավորումների տեղեկատու](/hy/operators/configuration)։
