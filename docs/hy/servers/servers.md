# Սերվերներ և սերվերների խմբեր <Label type="admin" /> {#servers-and-server-groups}

<DemoLink path="/servers" />

Պրովիժնինգի սերվերներն ու բեռի հավասարակշռման խմբերը կառավարելու համար անցեք **Սերվերներ** բաժին։ Ենթավերնագիր՝ «Մատակարարման սերվերների և բեռի հավասարակշռման խմբերի կառավարում»։

## Սերվերների ցանկ {#the-server-list}

Սերվերները ցուցադրվում են ըստ անվանման՝ քարտերով, 20-ական մեկ էջում։ Յուրաքանչյուր քարտում երևում են **Սերվերի անվանում**, **IP հասցե**, **Հաշիվներ**, **Կարգավիճակ** և **Գործողություններ**։ Սերվերի կարգավորումները բացելու համար տողի վրա սեղմեք **Խմբագրել**։ Երբ միացումը առողջ է, կարգավիճակը ցույց է տալիս «Առցանց · հաշիվներ՝ _n_ · _version_»։

**Կարգավիճակի նշաններ.** Առցանց, Օֆլայն, Չի ստուգվել։

Սերվերը գտնելու համար որոնման դաշտում գրեք անվանման, հոսթի անվան կամ IP հասցեի մի մասը։ **Ֆիլտրեր** կոճակը նեղացնում է ցանկը ըստ մոդուլի և ըստ կարգավիճակի (Առցանց, Օֆլայն կամ Չի ստուգվել). կիրառված ֆիլտրերը երևում են որպես հեռացվող պիտակներ։ Որոնումը, ֆիլտրերը և էջը պահվում են հասցեում, ուստի հղումը կամ վերաբեռնումը բացում է նույն ցանկը։ Որոնման մեջ `%` և `_` նշանները սովորական նշաններ են։ Այն էկրանները, որտեղ պետք է սերվեր ընտրել (խմբի ձևը, գոյություն ունեցող ծառայության ավելացումը և ծառայության սերվերը), և վահանակի բեռնվածության քարտը կարդում են բոլոր սերվերները՝ անկախ էջից։

**Տողի գործողություններ.** Ստուգել միացումը, SSH (բացում է SSH բանալիների կառավարման երկխոսությունը), Խմբագրել, Ջնջել։

**ԼՌԵԼՅԱՅՆ** նշանը ցույց է տալիս իր մոդուլի լռելյայն սերվերը։ Երբ մնացած պայմանները հավասար են, նոր հաշվի համար սերվեր ընտրելիս լռելյայն սերվերը նախապատվություն ունի իր խմբի կամ մոդուլի ներսում (տես [Լրացման տեսակներ](#fill-types))։

<Callout type="note">
<strong>cPanel</strong>-ը հաշիվներ ստեղծում է ավտոմատ և ներկառուցված է. այն նոր է և դեռ չի փորձարկվել իրական WHM սերվերի վրա, տես <a href="/hy/servers/cpanel">cPanel սերվերներ</a>։ Ցանկացած այլ կառավարման վահանակ, այդ թվում Control Web Panel-ը (CWP) և DirectAdmin-ը, աշխատում է միայն իր պլագինի միջոցով. տեղադրեք պլագինը պլագինների ռեեստրից կամ ֆայլ վերբեռնելով, միացրեք այն «Ինտեգրացիաներ» բաժնում (նոր տեղադրված պլագինը բեռնվում է հաջորդ գործարկման ժամանակ), և նրա վահանակների տեսակները կհայտնվեն մոդուլների ցանկում, դրանք կարելի է ընտրել, ստուգել և դրանց վրա հաշիվներ ստեղծել։ Մոդուլների ցանկում միայն cPanel-ն է, ստորև նկարագրված Linux սերվերը և տեղադրված պլագինների տեսակները, ուստի առանց պլագինի վահանակ չի առաջարկվում։ Եթե սերվերի օգտագործած վահանակի տեսակի պլագինը անջատված է, կարգավորված չէ կամ բացակայում է, համակարգը պատասխանում է, որ պլագինը հասանելի չէ (<code>PANEL_PLUGIN_UNAVAILABLE</code>), իսկ երկու տեղադրված պլագին, որոնք հայտարարում են վահանակի նույն տեսակը, մերժվում են (<code>PANEL_PLUGIN_CONFLICT</code>). Hostpanel-ը երբեք չի անցնում այլ մատակարարի։
</Callout>

Առանց կառավարման վահանակի սերվերն ավելացվում է **Linux սերվեր (առանց կառավարման վահանակի)** մոդուլով։ Այն ապրանք չէ, ուստի պատվերները երբեք չեն ընտրում այն. ավելացրեք այն առկա ընթացակարգով, տվեք SSH բանալի, և agent-ը կտեղադրի ներկառուցված `generic-linux` պրոֆիլը, որն աջակցում է SSH հաշիվներ, կայքեր և տվյալների բազաներ (տե՛ս [Սովորական Linux սերվերներ](./ssh-key-agent#սովորական-linux-սերվերներ-generic-linux))։

## Սերվերի ավելացում {#add-a-server}

Սեղմեք **Ավելացնել նոր սերվեր**։ Ձևն ունի երեք ներդիր։

| Հոսթի անվանում | Օգտագործվում է այս սերվերի հետ API միացումների համար |

| Սերվերի կարգավիճակի հասցե | Կարգավիճակի էջի ամբողջական ուղին, որը ցուցադրվում է հաճախորդի պորտալի կարգավիճակի մոնիտորում |
| Լռելյայն սերվեր | Նշեք որպես այս մոդուլի լռելյայն սերվեր։ Երբ մնացած պայմանները հավասար են, այն նախապատվություն ունի իր խմբի կամ մոդուլի ներսում |
| Անջատել այս սերվերը | Արգելում է այստեղ նոր հաշիվներ նշանակել |

### Անվանային սերվերների ներդիր {#nameservers-tab}

Մինչև հինգ անվանային սերվեր (յուրաքանչյուրի հոսթի անունը և IP-ն), որոնք ցուցադրվում են հաճախորդներին, երբ այս սերվերում հաշիվ է ստեղծվում՝ Հիմնական, Երկրորդ, Երրորդ, Չորրորդ, Հինգերորդ։

### Մանրամասների ներդիր {#details-tab}

| Դաշտ | Նշումներ |
|------|----------|
| Մոդուլ | Կառավարման վահանակի տեսակ՝ cPanel, Linux սերվեր (առանց կառավարման վահանակի) և տեղադրված վահանակների պլագինների տեսակները. հին տեսակով պահված սերվերը խմբագրելիս պահպանում է այն |
| Օգտանուն | API օգտանուն |
| Գաղտնաբառ | API գաղտնաբառ (պահվում է գաղտնագրված) |
| API թոքեն | API թոքեն, երբ մոդուլը օգտագործում է թոքենով նույնականացում (պահվում է գաղտնագրված) |
| Մուտքի հեշ | Օգտագործվում է որոշ վահանակների կողմից API նույնականացման համար, ինչպես նկարագրում է վահանակի պլագինը (պահվում է գաղտնագրված)։ cPanel-ը փոխարենը օգտագործում է Օգտանունը և API թոքենը |
| Օգտագործել SSL միացումների համար | Միացնում է HTTPS API հարցումների համար։ Անտեսվում է cPanel-ի համար, որին միշտ միանում են HTTPS-ով |

Խմբագրելիս ինքնության տվյալների դաշտերը ցույց են տալիս **(դատարկ՝ չփոխել)**։ Գաղտնի արժեքները պահվում են `ENCRYPTION_KEY`-ով գաղտնագրված։ Պորտի դաշտ չկա։ Վահանակի API պորտը ամրագրված է յուրաքանչյուր մոդուլի համար։

## Միացման ստուգում {#test-a-connection}

Սերվերի տողում սեղմեք **Ստուգել միացումը**։ Hostpanel-ը կանչում է սերվերի վահանակի API-ն և թարմացնում է կարգավիճակի նշանը։ Արդյունքը ցուցադրվում է տեղում, այլ ոչ թե որպես էջի սխալ։

**Հաջողություն.** «Առցանց · հաշիվներ՝ _n_ · _version_»։ Եթե վահանակը չի հաղորդում հաշիվների քանակը կամ տարբերակը, այդ մասը բաց է թողնվում. անհայտ քանակի համար «0 հաշիվ» երբեք չի ցուցադրվում։

**Ստուգման արդյունքում ցուցադրվող ձախողման կոդեր.** Արդյունքը կոդը (`errorCode`) կրում է իր նախադասության կողքին։

| Կոդ | Ինչ ստուգել |
|-----|-------------|
| `SERVER_CONNECTION_UNREACHABLE` | Հոսթի անունը կամ IP-ն սխալ է, վահանակի API պորտը արգելափակված է, կամ վահանակը չի աշխատում |
| `SERVER_CONNECTION_NO_ACCESS_HASH` | Այս սերվերի համար մուտքի հեշ պահված չէ։ Ավելացրեք այն Մանրամասների ներդիրում |
| `SERVER_CONNECTION_NO_API_KEY` | API բանալի կամ մուտքի հեշ պահված չէ։ Ավելացրեք տվյալները Մանրամասների ներդիրում |
| `SERVER_CONNECTION_NOT_CONFIGURED` | Այս կառավարման վահանակի համար միացման տվյալները թերի են։ Մանրամասների ներդիրում լրացրեք այն, ինչ պահանջում է վահանակի պլագինը |
| `SERVER_CONNECTION_AUTH_FAILED` | Կառավարման վահանակը մերժեց պահված տվյալները։ Մուտքագրեք դրանք նորից |
| `SERVER_CONNECTION_TIMED_OUT` | Վահանակը չպատասխանեց պլագինի կանչի ժամանակի սահմանաչափում (`PluginApi__CallTimeoutSeconds`, լռելյայն 30 վայրկյան)։ Ստուգեք, որ այն աշխատում է և որ firewall-ը միացումը չի կտրում |
| `SERVER_CONNECTION_TLS_FAILED` | Անվտանգ միացումը ձախողվեց։ Ստուգեք վահանակի վկայականը կամ թույլատրեք նրա ինքնաստորագրված վկայականը սերվերի կարգավորումներում |
| `PANEL_PLUGIN_UNAVAILABLE` | Այս մոդուլը սպասարկող տեղադրված պլագին չկա, կամ պլագինն անջատված է, կարգավորված չէ կամ չի աշխատում։ Ստուգեք պլագինների էջը |

## Սերվերի խմբագրում և ջնջում {#edit-and-delete-a-server}

Ձևը բացելու համար տողի վրա սեղմեք **Խմբագրել**։ Այլևս գոյություն չունեցող սերվերի հետ գործողությունները վերադարձնում են `SERVER_NOT_FOUND`։ Այն սերվերի ջնջումը, որը դեռ հյուրընկալում է հաճախորդների ծառայություններ կամ SSH բանալիներ, մերժվում է (`SERVER_IN_USE`)։

## Սերվերների խմբեր {#server-groups}

Սերվերների խմբերը թույլ են տալիս սերվերների մի հավաքածու նշանակել ապրանքին։ Նոր պատվերները բաշխվում են խմբի միջև՝ ըստ լրացման տեսակի։

### Խմբի ստեղծում {#create-a-group}

Սերվերների ցանկի տակ գտնվող **Խմբեր** բաժնում սեղմեք **Ստեղծել խումբ**։

| Դաշտ | Նշումներ |
|------|----------|
| Խմբի անվանում | օրինակ՝ «Արտադրական սերվերներ» |
| Լրացման տեսակ | Ինչպես են հաշիվները բաշխվում (տես ներքևում) |
| Սերվերներ | Սերվերները Հասանելիից տեղափոխեք Խմբում |

### Լրացման տեսակներ {#fill-types}

| Լրացման տեսակ | Պիտակ |
|---------------|-------|
| LeastFull | Ավելացնել ամենաքիչ լցված սերվերին |
| FillUntilFull | Լցնել ակտիվ սերվերը մինչև լրիվ լինելը, ապա անցնել հաջորդին |

**Երբեք չընտրվող սերվերներ.** երկու տեսակի դեպքում էլ անջատված և լրիվ սերվերները բաց են թողնվում։ Սերվերը լրիվ է, երբ նրա հաշիվների քանակը հասել է Առավ. հաշիվների քանակին։ Առավ. հաշիվների քանակ 0-ն համարվում է լրիվ։ Առանց առավելագույնի սերվերը (դաշտը դատարկ թողնված է) երբեք լրիվ չէ։

**LeastFull.** հաղթում է ամենացածր լրացման հարաբերակցությամբ սերվերը (հաշիվներ ÷ առավ. հաշիվներ)։ Առանց առավելագույնի սերվերների լրացման հարաբերակցությունը 0 է։ Հավասարության դեպքում առավելությունը տրվում է լռելյայն սերվերին, ապա՝ ավելի մեծ տարողությամբ սերվերին, ապա՝ անվան առաջին սերվերին։

**FillUntilFull.** նախ օգտագործվում է լռելյայն սերվերը։ Դրանից հետո օգտագործվում են առավելագույն ունեցող սերվերները՝ անվան կարգով։ Առանց առավելագույնի սերվերները գալիս են վերջում՝ որպես արտահոսք։ Սերվերը լցվում է մինչև իր առավելագույնը, ապա օգտագործվում է հաջորդը։

**Առանց խմբի.** երբ ապրանքը սերվերների խումբ չունի, միշտ կիրառվում է LeastFull՝ անկախ ձեր խմբերի լրացման տեսակներից։

**Լռելյայն սերվեր.** բոլոր դեպքերում, երբ մնացած պայմանները հավասար են, լռելյայն սերվերը նախապատվություն ունի իր խմբի կամ մոդուլի ներսում։

<Callout type="note">
Հաշիվների քանակները գալիս են միացման ստուգումներից և Sync Server Account Counts աշխատանքից, ուստի ցուցադրվող և ընտրության համար օգտագործվող լրացվածությունը համաժամեցումների միջև մոտավոր է։
</Callout>

### Խմբի ջնջում {#delete-a-group}

Այն խմբի ջնջումը, որի մեջ ապրանքները դեռ պրովիժնինգ են անում, մերժվում է (`SERVER_GROUP_IN_USE`)։ Չօգտագործվող խմբի ջնջումը նրա բոլոր սերվերներին հանում է խմբից, բայց ինքը՝ սերվերները, չի ջնջում։

## Մասնավոր ցանցի երթուղիներ {#private-network-routes}

Երբ սերվերի կառավարման վահանակի API-ն հասանելի է միայն VPN-ով կամ մասնավոր ցանցով, լրացրեք հենց սերվերի **API հասցե** դաշտը (Սերվերներ, սերվերի խմբագրում, Ընդհանուր), օրինակ՝ `10.77.0.1`։ Hostpanel-ը API կանչերի համար դիմում է այդ հասցեին և այն որպես կապի հոսթի անուն փոխանցում է վահանակի պլագինին, իսկ հաճախորդին ցուցադրվող կառավարման վահանակի և վեբփոստի հղումները շարունակում են կառուցվել հոսթի անունով։ Եթե սերվերը ընդունում է ինքնաստորագրված վկայական, ընդունվում է հենց այդ հասցեի վկայականը։ Դատարկ թողնելու դեպքում API-ն կանչվում է հոսթի անունով, ինչպես նախկինում։

Ադմինիստրատորը հասցեն սահմանում է յուրաքանչյուր սերվերի համար ադմինի վահանակում, ուստի VPN-ի հետևում գտնվող սերվեր ավելացնելու համար տեղակայումը փոխել պետք չէ։ Եթե ավելի հարմար է երթուղիները ամրագրել միջավայրում, կարելի է շարունակել օգտագործել `PANEL_HOST_ADDRESSES`՝ որպես `hostname=address` զույգեր (ստորակետով բաժանված, օրինակ՝ `srv4.example.com=10.77.0.1`)՝ Hostpanel-ը կապվում է մասնավոր հասցեին, բայց հարցման և TLS վկայականի ստուգման համար պահպանում է հոսթի անունը։

Միջավայրի կարգավորումների ամբողջական ցանկի համար տես [Կարգավորումների տեղեկատու](/hy/operators/configuration)։
