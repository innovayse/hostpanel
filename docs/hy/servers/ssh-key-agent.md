# SSH բանալիների agent <Label type="admin" /> {#ssh-key-agent}

<DemoLink path="/servers" />

SSH բանալիների agent-ը հաճախորդներին թույլ է տալիս իրենց հոսթինգի հաշիվներին ավելացնել սեփական ED25519 հանրային բանալիները։ Յուրաքանչյուր սերվերում աշխատում է փոքր agent գործընթաց։ Hostpanel-ը միանում է նրան SSH-ով՝ օգտագործելով սերվերի սեփական ինքնության բանալին և ամրագրված հոսթի fingerprint-ը։

## Ինչպես է աշխատում {#how-it-works}

```
Hostpanel ──ssh (pinned host key, per-server ED25519)──▶ hpsshkeys@server
  authorized_keys: restrict,command="sudo -n /usr/local/sbin/hostpanel-ssh-key-agent"
  sudoers:         hpsshkeys ALL=(root) NOPASSWD: /usr/local/sbin/hostpanel-ssh-key-agent
```

`restrict` հրահանգը հեռացնում է PTY-ն, port forwarding-ը և user rc-ն. պարտադրված հրամանը անտեսում է այն, ինչ հաճախորդը խնդրում է գործարկել։ Sudo-ն թույլատրում է միայն այդ ճշգրիտ ուղին՝ առանց արգումենտների։ Հարցումները stdin-ով ուղարկվում են որպես JSON փաստաթուղթ։ Agent-ը երբեք shell չի գործարկում և հարցումից ուղի չի վերցնում։

**Աջակցվող սերվերի մոդուլներ.** միայն CWP7-ն է համապատասխանում agent-ի պրոֆիլին (`cwp`)։ Սերվերների մնացած բոլոր տեսակների համար հաճախորդներին ցուցադրվում է «SSH բանալիների կառավարումը հասանելի չէ»։

## SSH-ի կարգավորում սերվերի վրա {#set-up-ssh-on-a-server}

Անցեք **Սերվերներ** և սերվերի վրա սեղմեք **SSH** տողի գործողությունը՝ SSH բանալիների կառավարման երկխոսությունը բացելու համար։

<Steps>
<li>

**Միացման կարգավորումներ։** Լրացրեք դաշտերը և պահպանեք։ Այս կարգավորումները օգտագործվում են բոլոր հաջորդ քայլերում։

| Դաշտ | Նշումներ |
|------|----------|
| SSH հոսթ | Հոսթի անվանումը, որով միանում են հաճախորդները (ցուցադրվում է հաճախորդին) |
| SSH պորտ | Լռելյայն՝ 22 |
| Agent-ի հոսթ | Հասցեն, որին Hostpanel-ը կապվում է agent-ին հասնելու համար (կարող է տարբերվել SSH հոսթից) |
| Agent-ի SSH պորտ | Լռելյայն՝ 22 |
| Ծառայողական օգտատեր | Համակարգային հաշիվը, որով աշխատում է agent-ը։ Լռելյայն՝ `hpsshkeys` |
| Միացման ժամկետ (վ) | Վայրկյաններ, որից հետո միացման փորձը լքվում է |
| Գործողության ժամկետ (վ) | Վայրկյաններ, որից հետո agent-ի հարցումը լքվում է |

**Ցանցային հասանելիություն։** Hostpanel-ը միանում է ֆիքսված հասցեից։ Agent-ի պորտում թույլատրեք միայն այդ հասցեն՝ ձեր firewall-ի համար (CSF, firewalld կամ ufw) ցուցադրված տողով։ Տեղակայման միջավայրում `SSH_AGENT_SOURCE_ADDRESSES`-ը սահմանեք այն հասցեով, որից կառավարվող սերվերները տեսնում են Hostpanel-ի միացումները։ Այդ դեպքում երկխոսությունը ցույց է տալիս պատրաստի firewall և sshd տողեր։

OpenSSH 9.8-ում և ավելի նոր տարբերակներում ձախողված կամ չնույնականացված միացումները տուգանվում են ըստ աղբյուրի հասցեի (`PerSourcePenalties`, լռելյայն միացված է)։ Ժամանակավոր արգելափակումից խուսափելու համար ավելացրեք Hostpanel-ի հասցեն `sshd_config`-ի `PerSourcePenaltyExemptList`-ում։ Երկխոսությունը ցույց է տալիս ճշգրիտ ավելացվող տողը։

VPN-ի կամ մասնավոր ցանցի դեպքում։ Որպես Agent-ի հոսթ մուտքագրեք սերվերի մասնավոր հասցեն։ Այն հոսթը, որի վրա աշխատում է Hostpanel-ը, պետք է գտնվի այդ ցանցում։

</li>
<li>

**Ստեղծեք ինքնության բանալի։** Սեղմեք **Ստեղծել բանալի**։ Hostpanel-ը այս սերվերի համար ստեղծում է ED25519 բանալու զույգ, գաղտնի բանալին պահում է գաղտնագրված և ցուցադրում է մեկ հրամանով installer։ Պատճենեք հրամանը և գործարկեք այն սերվերում որպես root։

<Callout type="warning">
Գործարկեք installer-ը բնիկ SSH տերմինալում, այլ ոչ թե հոսթինգի վահանակի բրաուզերային տերմինալում։ Բրաուզերային տերմինալները կորցնում են <code>$</code> փոփոխականները և կրկնում են մուտքագրվածը, ինչը կոտրում է հրամանը։
</Callout>

Installer-ը մինչև արխիվը բացելը ստուգում է ադմինի վահանակում ցուցադրված SHA256 ստուգիչ գումարը։ Այն տպում է սերվերի հոսթի բանալիների fingerprint-ները։ Գրի առեք դրանք հաջորդ քայլի համար։

Installer-ն ընդունում է այս դրոշակները.

| Դրոշակ | Ազդեցություն |
|--------|--------------|
| `--provider <profile>` | Agent-ի պրոֆիլ։ `cwp`՝ CWP7-ի համար, `generic-linux`՝ սովորական Linux-ի համար |
| `--binding <id>` | Այս տեղադրումը կապում է Hostpanel-ի սերվերի գրառմանը |
| `--config <file>` | Օգտագործել հատուկ կարգավորման ֆայլ՝ պրոֆիլի լռելյայնի փոխարեն (առաջադեմ) |
| `--dry-run` | Նախադիտել, թե ինչ կտեղադրվեր՝ առանց որևէ փոփոխության |
| `--check` | Ախտորոշել առկա տեղադրումը (օգտատեր, կողպեք, սեփականատեր/թույլտվություններ, sudoers, պարտադրված հրամանի բանալի, կարգավորում, ինքնաստուգում, հոսթի բանալի) |

Installer-ը նորից գործարկելը թարմացնում է agent-ի երկուական ֆայլը և կապը՝ պահպանելով առկա `agent.conf`-ը։ Installer-ը ստեղծում և գրում է.

- `/usr/local/sbin/hostpanel-ssh-key-agent`՝ agent-ի երկուական ֆայլը
- `/etc/sudoers.d/hostpanel-ssh-key-agent`՝ sudoers կանոնը
- `/etc/hostpanel-ssh-key-agent/agent.conf`՝ agent-ի կարգավորումը (պրոֆիլից)
- `/var/lib/hpsshkeys/.ssh/authorized_keys`՝ ծառայողական օգտատիրոջ պարտադրված հրամանի բանալին

Installer-ը երբեք չի դիպչում sshd-ին, firewall-ին, որևէ VPN-ին, Jailkit-ին կամ հաճախորդների հաշիվներին։

</li>
<li>

**Ամրագրեք հոսթի բանալին։** Սեղմեք **Կարդալ հոսթի բանալին**։ Hostpanel-ը միանում է agent-ին առանց նույնականացման և կարդում է սերվերի ներկայացրած fingerprint-ը։ Համեմատեք այն installer-ի տպածի հետ։ Եթե նույնն են, սեղմեք **Օգտագործել այս fingerprint-ը** և պահպանեք։ Բոլոր հետագա միացումները, որոնք ներկայացնում են այլ fingerprint, մերժվում են։

Եթե **Կարդալ հոսթի բանալին** ձախողվում է.

| Սխալի կոդ | Նշանակություն |
|-----------|---------------|
| `SSH_SETTINGS_INCOMPLETE` | Agent-ի հոսթի դաշտը դատարկ է։ Նախ լրացրեք միացման կարգավորումները |
| `SSH_AGENT_HOST_UNREACHABLE` | Agent-ի հոսթին և պորտին ցանցային ճանապարհ չկա։ Ստուգեք հասցեն, firewall-ը և VPN-ը |
| `SSH_AGENT_PORT_REFUSED` | Պորտը ակտիվորեն մերժեց միացումը։ Այնտեղ ոչինչ չի լսում, կամ firewall-ը մերժում է Hostpanel-ի հասցեն |
| `SSH_AGENT_CONNECTION_CLOSED` | Սերվերը ընդունեց, ապա փակեց միացումը SSH ողջույնից առաջ։ Ստուգեք `PerSourcePenalties`-ը, `MaxStartups`-ը և TCP wrappers-ը |
| `SSH_HOST_KEY_UNREADABLE` | Միացվեց, բայց հոսթի բանալի չստացվեց։ Ստուգեք, որ պորտում աշխատում է sshd |

</li>
<li>

**Ստուգեք միացումը։** Սեղմեք **Ստուգել agent-ը**։ Կարգավիճակի տողը ցույց է տալիս հետևյալներից մեկը.

- **Agent-ը հասանելի է**՝ agent-ը պատասխանեց, և կապը համընկնում է։
- **Agent-ը հասանելի չէ**՝ միացումը ձախողվեց։ Պատճառը տես «Վերջին ստուգումը ձախողվեց» տողում։
- **Ստուգված չէ**՝ կարգավորումները փոխվել են վերջին ստուգումից հետո։

Agent-ի տարբերակը ցուցադրվում է որպես «Agent _version_» կամ «Agent _version_ (_provider_)»։ Սերվերը միացնելու համար անհրաժեշտ է հաջող ստուգում։ Agent-ի հոսթի, պորտի, օգտատիրոջ, բանալու կամ ամրագրված fingerprint-ի փոփոխությունը մաքրում է ստուգումը։

Եթե ստուգումը ձախողվում է, պատճառը ցուցադրվում է որպես «Վերջին ստուգումը ձախողվեց՝ _reason_» (`servers.ssh.failures.*`).

| Պատճառ | Նշանակություն |
|--------|---------------|
| սերվերը հասանելի չէ | Agent-ի հոսթին ցանցային ճանապարհ չկա (`Unreachable`) |
| agent-ը ժամանակին չպատասխանեց | Միացումը բացվեց, բայց agent-ը ժամանակին չպատասխանեց (`Timeout`) |
| agent-ը տեղադրված է այլ սերվերի համար | Հոսթը ճիշտ է, բայց կապը սխալ է։ Ստուգեք agent-ի հոսթը կամ դրա վրա գործարկեք այս սերվերի տեղադրման հրամանը (`BindingMismatch`) |
| agent-ի տարբերակը չի աջակցվում | Agent-ը չափազանց հին է Hostpanel-ի այս տարբերակի համար (`UnsupportedVersion`) |
| agent-ի ներքին սխալ | Agent-ի կողմի սխալ։ Ստուգեք `/var/log/hostpanel-ssh-key-agent.log` (`InternalError`) |
| agent-ը մերժեց հարցումը | Agent-ի անսպասելի մերժում (`InvalidRequest`) |
| agent-ը չի աջակցում այս գործողությունը | Agent-ի տարբերակը չի իրականացնում այս գործողությունը (`UnknownOperation`) |
| հարցումը չափազանց մեծ է | Հարցման մարմինը գերազանցեց agent-ի չափի սահմանաչափը (`RequestTooLarge`) |
| սերվերը չունի agent-ի ամբողջական կարգավորումներ | Մեկ կամ մի քանի պարտադիր դաշտ դատարկ է (`AgentNotConfigured`) |
| անհայտ պատճառ | Անսպասելի պատասխան (`Unknown`) |

Աղյուսակը թվարկում է տարածված պատճառները։ Ադմինի վահանակը ցուցադրում է մոտ քսան պատճառ։ Ամբողջական ցանկի համար տես `servers.ssh.failures`-ը locale ֆայլում։

`SSH_AGENT_NOT_VERIFIED` ցուցադրվում է, երբ փորձում եք միացնել առանց անցած ստուգման։ `SSH_MODULE_NOT_SUPPORTED` վերադարձվում է այն սերվերների տեսակների համար, որոնց մոդուլը agent-ի պրոֆիլ չունի։

</li>
<li>

**Միացրեք։** Միացրեք **Այս սերվերի հաճախորդները կարող են կառավարել SSH բանալիները** անջատիչը։ Միացումը մերժվում է, եթե մեկ այլ արդեն միացված սերվեր օգտագործում է նույն agent-ի հոսթը և պորտը (`SSH_AGENT_ENDPOINT_IN_USE`)։ Agent-ի հոսթի, պորտի, օգտատիրոջ, բանալու կամ ամրագրված fingerprint-ի փոփոխությունը մաքրում է ստուգումը և նորից միացնելուց առաջ պահանջում է կրկին ստուգել։

</li>
</Steps>

### Ինքնության փոխարինում {#rotate-identity}

Սեղմեք **Փոխարինել բանալին**՝ նույն սերվերի կապի համար նոր բանալի թողարկելու համար։ Հաճախորդի SSH բանալիների հասանելիությունը անմիջապես դադարում է, մինչև installer-ը նորից գործարկվի ցուցադրված նոր հրամանով։

Աղետից վերականգնման համար **Լրացուցիչ** բաժինը թույլ է տալիս նոր բանալի ստեղծելու փոխարեն տեղադրել առկա գաղտնի բանալի։

## Agent-ի սխալի կոդեր {#agent-error-codes}

Այս կոդերը գալիս են հենց agent-ից և հայտնվում են Hostpanel-ի սխալի պատասխաններում կամ աշխատակիցների մատյաններում։

| Կոդ | Նշանակություն |
|-----|---------------|
| `invalid_account` | Հաշվի անունը չի համապատասխանում սերվերի անվանման կանոններին |
| `account_not_found` | Այս հաշվի համար passwd գրառում չկա |
| `account_not_eligible` | Հաշիվը կա, բայց բացառված է (`eligible_list`-ում չէ, `ssh_group`-ում չէ, կամ պրովայդերի վահանակի ստուգումը ձախողվել է) |
| `account_suspended` | Հաշվի գաղտնաբառը կողպված է (`usermod -L`), և `check_shadow_lock`-ը միացված է |
| `invalid_key` | Հանրային բանալին վավեր ED25519 բանալի չէ |
| `duplicate_key` | Այս բանալու fingerprint-ը արդեն գոյություն ունի այլ `key_id`-ի տակ |
| `key_id_conflict` | Նույն `key_id`, տարբեր բանալու նյութ |
| `too_many_keys` | Հաշիվը հասել է կառավարվող բանալիների առավելագույն քանակին |
| `ssh_disabled` | Հաշվի shell-ն անջատված shell է (օրինակ՝ `/sbin/nologin`), և `jail_enrol`-ը անջատված է |
| `unsafe_path` | `.ssh` թղթապանակը կամ `authorized_keys` ֆայլը սիմվոլիկ հղում է կամ անսպասելի տիրոջ է պատկանում |
| `file_too_large` | `authorized_keys`-ը գերազանցում է չափի սահմանաչափը |
| `timeout` | Հարցումը չափազանց երկար տևեց (stdin՝ 10 վ, ընդհանուր՝ 60 վ) |
| `internal_error` | Agent-ի կողմի խափանում։ Մանրամասները սերվերի աուդիտի մատյանում են |

## Հեռացում {#uninstall}

Agent-ը հեռացնելուց առաջ չեղարկեք բոլոր կառավարվող բանալիները, որպեսզի հաճախորդները չշարունակեն մուտք գործել որբացած բանալիներով։ Ադմինի վահանակում դեռ կոճակ չկա։ Օգտագործեք ադմինի API-ն անմիջապես.

1. Կանչեք `POST /api/admin/servers/{id}/ssh-keys/revoke-all`։ Սա սերվերից հեռացնում է բոլոր կառավարվող բանալիները։
2. Սերվերում, բացված installer փաթեթում, գործարկեք.

```bash
./uninstall.sh           # removes management key, sudoers entry, hpsshkeys user and agent binary; keeps agent.conf
./uninstall.sh --purge   # also removes agent.conf (audit log is always kept)
./uninstall.sh --dry-run # preview only
```

Uninstaller-ը երբեք չի դիպչում sshd-ին, firewall-ին, jailkit-ին կամ հաճախորդների ֆայլերին։

Ստուգելու համար, որ հեռացումից հետո կառավարվող բանալիներ չեն մնացել.

```bash
grep -rl 'hostpanel:' /home/*/.ssh/authorized_keys
```

## Ինչ են տեսնում հաճախորդները {#what-customers-see}

Հաճախորդները կառավարում են իրենց SSH բանալիները հաճախորդի պորտալում իրենց ծառայության **SSH բանալիներ** ներդիրից։ Նրանք կարող են ավելացնել բանալի՝ տեղադրելով հանրային բանալին և տալով նրան պիտակ, տեսնել յուրաքանչյուր տեղադրված բանալու fingerprint-ը և պիտակը, և չեղարկել ցանկացած բանալի առանձին։ Ավելացման և չեղարկման գործողություններն ուղղակիորեն գնում են սերվերի agent-ին։ Hostpanel-ում պահվում է միայն բանալու fingerprint-ը, երբեք՝ գաղտնի բանալին։

SSH հոսթի հասանելիություն հայտարարող պլագինին կարելի է թողարկել բանալի այն հաճախորդի ծառայության համար, որի ապրանքին օպերատորը **Հավելումներ** էջում կապել է պլագինի ծառայության վիջեթներից մեկը։ Միայն պլագինի սեփական մանիֆեստում նշված ապրանքը չի հաշվվում։ Քանի դեռ օպերատորը չի կապել այն, պլագինը ոչ մի հոսթինգի չի հասնում։ Hostpanel-ը ստեղծում է բանալու զույգը, հանրային մասը տեղադրում է այս agent-ի միջոցով ճիշտ այնպես, ինչպես հաճախորդի ավելացրած բանալին, և գաղտնի բանալին պլագինին տալիս է մեկ անգամ։ Hostpanel-ը երբեք չի պահում կամ գրանցում այն մատյանում։ Այդպիսի բանալին ցուցակվում է ծառայության **SSH բանալիներ** ներդիրում ինչպես մյուսները, և հաճախորդը կարող է ցանկացած պահի չեղարկել այն։ Պլագինն անջատելը պահպանում է նրա բանալիները (անջատված ժամանակ պլագինը չի կարող օգտագործել հոսթը)։ Պլագինը հեռացնելը չեղարկում է դրանք։

Հաճախորդի պորտալից ավելացման և չեղարկման հարցումները սահմանափակված են՝ 20 գործողություն 60 վայրկյանում յուրաքանչյուր հաճախորդի համար (`SshKeys` քաղաքականություն)։ Սա կարելի է կարգավորել տեղակայման հարցումների սահմանափակման կարգավորումներում։
