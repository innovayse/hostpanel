# Обзор API {#api-overview}

REST API Hostpanel доступен по адресу `/api` на хосте клиентского портала и на хосте администратора вашей установки. Каждая страница конечной точки в этом разделе генерируется из самого API при каждой сборке сайта, поэтому маршруты, параметры и статусы здесь совпадают с тем, что объявлено в коде.

Сначала идут страницы, которые относятся к каждой конечной точке: [Аутентификация](/ru/api-reference/authentication), [Ошибки](/ru/api-reference/errors), [Языки](/ru/api-reference/languages), [Ограничения частоты запросов](/ru/api-reference/rate-limits) и [Постраничная выдача](/ru/api-reference/pagination). Страницы конечных точек идут следом в боковом меню, сгруппированные по аудитории, а затем по областям.

<Callout type="tip">
В примерах используется <code>https://panel.example.com</code> для хоста клиентского портала и <code>https://admin.example.com</code> для хоста администратора. Замените их адресами своей установки или используйте локальный стенд, пока пробуете вызовы.
</Callout>

## Форматы {#formats}

- **JSON.** Тела запросов и ответов имеют тип `application/json`. Ошибки имеют тип `application/problem+json`. См. [Ошибки](/ru/api-reference/errors).
- **camelCase.** Имена полей в обмене данными пишутся в camelCase, например `createdAt` и `totalPages`. Перечисления передаются своими именами, например `"status": "Paid"`.
- **Даты.** ISO 8601 со смещением `+00:00`, то есть UTC, например `2026-11-04T05:12:38.265306+00:00`.
- **Деньги.** Число JSON в валюте, которую запись называет в поле `currency`, это код ISO 4217, например `USD`, как в `"total": 29.98`.
- **Параметры запроса.** Их имена сопоставляются без учёта регистра. Страницы конечных точек показывают их так, как они объявлены в API, например `Page` и `PageSize`.

## Проверка работоспособности {#health}

```
GET /health
```

Отвечает `200 OK`, пока процесс API обрабатывает запросы:

```json
{
  "status": "Ok",
  "timestamp": "2026-11-04T12:39:25.5302532+00:00"
}
```

Этот маршрут находится в корне хоста, а не под `/api`. Ему не нужен вход, и на него не действуют ограничения частоты запросов. Это проба живости, а не проверка базы данных: ответ `200` говорит, что процесс запущен, но ничего не говорит о его зависимостях.
