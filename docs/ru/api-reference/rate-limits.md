# Ограничения частоты запросов {#rate-limits}

Каждый запрос учитывается в общем лимите. Конечные точки, которые принимают учётные данные, обращаются к системе другой компании или отправляют что-либо за пределы установки, дополнительно учитываются в более жёстком именованном лимите. Когда лимит исчерпан, API отклоняет вызов ответом `429`, пока лимит снова не освободится.

## Политики {#policies}

Каждый лимит представляет собой число запросов в скользящем окне, которое считается для каждого вошедшего пользователя или для адреса вызывающей стороны, если запрос без учётных данных. Окно скользит шестью шагами, поэтому часть лимита возвращается каждые несколько секунд, а не вся сразу на границе.

Действуют оба лимита. Вызов конечной точки с именованной политикой учитывается в этой политике и в `global`, а решает более жёсткий. Очереди ожидания нет: вызов сверх лимита отклоняется сразу.

## Когда вам отказано {#when-you-are-refused}

Отклонённый вызов получает ответ `429 Too Many Requests` со стандартным [телом ошибки](/ru/api-reference/errors) и кодом `HOSTPANEL_RATE_LIMITED`. Заголовки сообщают, что делать и какой лимит вас остановил:

<SettingTable :settings="[
  { name: 'Retry-After', type: 'заголовок ответа', default: 'Нет', description: 'Сколько секунд подождать перед повторной попыткой. Не меньше 1. Для политики одновременности всегда 1: место освобождается, когда завершается другой вызов.' },
  { name: 'X-RateLimit-Policy', type: 'заголовок ответа', default: 'Нет', description: 'Имя политики, которая вас остановила, одно из имён в таблице выше, например auth или global.' },
  { name: 'X-RateLimit-Limit', type: 'заголовок ответа', default: 'Нет', description: 'Размер этого лимита: запросов в окне или одновременных вызовов для политики одновременности.' },
  { name: 'X-RateLimit-Remaining', type: 'заголовок ответа', default: '0', description: 'Сколько вызовов осталось в лимите, который вас остановил. В ответе 429 всегда 0.' },
  { name: 'X-RateLimit-Reset', type: 'заголовок ответа', default: 'Нет', description: 'Когда можно повторить попытку, как метка времени Unix в секундах. Это момент отказа плюс Retry-After.' },
]" />

<Callout type="warning">
Соблюдайте <code>Retry-After</code>. Повторная попытка сразу же приводит к тому же отказу.
</Callout>

Эти заголовки приходят только с ответом `429`. Имена политик и лимиты, те, что указаны на этой странице, поэтому заголовки ничего не сообщают вызывающей стороне об установке сверх опубликованного здесь. Скрипт, который работает в браузере с другого источника, не может их прочитать: API не перечисляет их в `Access-Control-Expose-Headers`. Они доступны серверу, инструменту командной строки и странице, которая отдана с того же источника.

Подождите столько секунд, сколько указано в заголовке, и повторите попытку. Распределяйте массовую работу во времени, а не отправляйте её одним всплеском.

## За прокси {#behind-a-proxy}

Лимиты считаются для адреса вызывающей стороны, поэтому, когда перед API стоит прокси, API должен знать, какой адрес принадлежит вызывающей стороне. Он берёт адрес из `X-Forwarded-For` лишь в пределах числа доверенных прокси, о которых ему сообщили, и только если запрос пришёл от известного ему прокси.

<SettingTable :settings="[
  { name: 'RATE_LIMIT_TRUSTED_PROXY_COUNT', type: 'number', default: '1', description: 'Сколько доверенных прокси стоит между вызывающей стороной и API. В поставляемых стеках задано 1, это встроенный пограничный прокси. Сам API стартует с 0 и не верит ни одному пересылаемому заголовку. Добавляйте по 1 за каждый дополнительный прокси перед ним.' },
]" />

Всю настройку, включая `RateLimit__KnownProxies__N` и `RateLimit__KnownNetworks__N`, описывает раздел [Обратный прокси и доверенные прокси](/ru/operators/configuration#reverse-proxy-and-trusted-proxies).

## Настройки {#settings}

Приведённые выше лимиты: значения по умолчанию. Оператор меняет их для сервиса API в переопределении compose. Настройки с их значениями по умолчанию и диапазонами перечислены в разделе [Настройки ограничения частоты запросов](/ru/operators/configuration#rate-limit-settings-compose-override-only). Уровень больше `global` или значение, которое не является положительным, не даёт API запуститься.

## Блокировка входа {#sign-in-lockout}

Блокировка входа не зависит от ограничений частоты запросов. После слишком большого числа неверных паролей подряд учётная запись блокируется, и каждый вход отвечает `SIGN_IN_ACCOUNT_LOCKED` со статусом `423`, какой бы пароль ни был отправлен, пока блокировка не закончится.

<SettingTable :settings="[
  { name: 'SignInLockout__MaxFailedAttempts', type: 'number', default: '5', description: 'Сколько неверных паролей подряд блокируют учётную запись. От 1 до 100.' },
  { name: 'SignInLockout__LockoutMinutes', type: 'number', default: '15', description: 'Как долго заблокированная учётная запись отклоняет любой пароль, в минутах. От 1 до 1440.' },
]" />

Счётчик хранится в учётной записи, поэтому он сохраняется при перезапусках и общий для всех экземпляров API. Успешный вход его обнуляет.
