# Обзор архитектуры {#architecture-overview}

<Callout type="note">
Если эта страница и файлы правил расходятся, решают файлы правил.
</Callout>

## Компоненты {#the-pieces}

```
Browser
  ├── Admin panel (admin/)      calls    API
  └── Client portal (client/)   calls    server routes  calls  API
                                                                 │
                                                   Database, Queue, Cache
```

| Компонент | Что это |
|-------|-----------|
| **API** (`Innovayse.Hostpanel.API`) | Бэкенд. Обрабатывает все HTTP-запросы, запускает фоновые задачи, работает с базой данных, очередью сообщений и кэшем. |
| **Панель администратора** (`admin/`) | Одностраничное приложение для сотрудников. Читает данные из API и записывает их. |
| **Клиентский портал** (`client/`) | Приложение с серверным рендерингом для клиентов. Имеет собственные серверные маршруты, которые проксируют API, поэтому браузер никогда не обращается к API напрямую. |
| **База данных** | Реляционное хранилище. Имена всех таблиц, столбцов, ключей, индексов и ограничений записаны в PascalCase. |
| **Очередь сообщений** | Передаёт команды и запросы между процессом API и его фоновыми воркерами. |
| **Кэш** | Общий кэш для ограничения частоты запросов, состояния сессий и краткоживущих данных. |

SDK плагинов (`Hostpanel.Sdk`) распространяется под лицензией MIT и подключён как git-субмодуль в `backend/src/Hostpanel.Sdk`. Это единственная часть кодовой базы, которой пользуются сторонние авторы плагинов.

## Слои {#the-layers}

Зависимости направлены внутрь. Внешние слои могут ссылаться на внутренние; внутренние никогда не ссылаются на внешние. Это проверяют архитектурные тесты в `Innovayse.Hostpanel.Architecture.Tests`.

| Слой | Проект | Что содержит |
|-------|---------|-------|
| **SharedKernel** | `Innovayse.Hostpanel.SharedKernel` | Примитивы, общие для всех слоёв: базовые типы, типы результата, методы расширения. |
| **Domain** | `Innovayse.Hostpanel.Domain` | Сущности, перечисления и доменная логика. Без зависимостей от инфраструктуры и от задач приложения. |
| **Application** | `Innovayse.Hostpanel.Application` | Сценарии использования: команды, запросы, обработчики, валидаторы. Определяет порты (интерфейсы `I<Port>`) для всего, что приложению нужно извне. |
| **Infrastructure** | `Innovayse.Hostpanel.Infrastructure` | Адаптеры, реализующие порты приложения: ORM, электронная почта, хранилище, шина сообщений, фоновые задачи. |
| **API** | `Innovayse.Hostpanel.API` | Контроллеры, промежуточное ПО, запуск. Корень композиции: связывает всё воедино. |
| **Shared** | `Shared` | Сквозной код основного проекта: `BaseApiController`, `StatusMapping`, общие модели. Плагины на этот проект не ссылаются. |

## SDK плагинов и встроенные плагины {#the-plugin-sdk-and-bundled-plugins}

SDK лежит в `backend/src/Hostpanel.Sdk` как git-субмодуль (размещён отдельно на `github.com/innovayse/hostpanel-sdk`). Клонируйте репозиторий с `--recurse-submodules` или выполните `git submodule update --init` после обычного клонирования.

Встроенные плагины поставляются в образе сервера и лежат в `backend/src/Innovayse.Providers.*`. Это эталонные реализации для авторов плагинов.

Полное руководство для авторов плагинов смотрите в разделе [Написание плагина](/ru/developers/write-a-plugin).

## Репозиторий {#the-repository}

| Папка | Содержимое |
|--------|---------|
| `backend/` | `src/` (проекты), `tests/` (тестовые проекты), `plugins/` (дополнение для миграции), `agent/` (агент SSH-ключей) |
| `admin/` | Панель администратора |
| `client/` | Клиентский портал |
| `docker/` | Файлы Compose, шаблоны окружения, конфигурация nginx |
| `docs/` | Этот сайт документации |
| `rules/` | Правила стиля кода. Источник истины для решений по стилю кода. |
| `scripts/` | Скрипты для CI и обслуживания |

## Папка rules {#the-rules-folder}

`rules/*.md` служат источником истины по стилю кода. Если эта страница и правила расходятся, побеждают правила.

| Файл | О чём |
|------|-------|
| `rules/project.md` | Обзор проекта, где что лежит, чем проект отличается от соглашений рабочей среды |
| `rules/clean-architecture.md` | Правила слоёв и направление зависимостей |
| `rules/csharp-style.md` | Стиль C#: скобки, конструкторы, именование, один тип на файл |
| `rules/dotnet-format.md` | Настройка форматтера и шаги перед коммитом |
| `rules/xml-docs.md` | Требования к XML-комментариям документации в C# |
| `rules/jsdoc.md` | Требования к JSDoc для TypeScript и Vue |
| `rules/vuejs-style.md` | Соглашения для компонентов и композаблов Vue |
