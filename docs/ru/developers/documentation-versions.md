# Версии документации {#documentation-versions}

Документация существует в одном экземпляре на каждый минорный релиз, поэтому читатель старого релиза видит страницы, которые ему соответствуют.

| Адрес | Что это |
|---------|------------|
| `/` | Последний стабильный релиз. Эту версию индексируют поисковые системы. |
| `/vX.Y/` | Одна сборка на каждый более старый минорный релиз, сделанная из самого нового патч-тега этого минорного релиза. |
| `/next/` | Ветка `develop`, ещё не выпущенная. Она помечена `noindex` и не имеет карты сайта. |

Переключатель версий в шапке перечисляет их. Список читается во время работы из `versions.json`, который публикуется рядом с последней документацией, поэтому старая сборка показывает релизы, выпущенные после неё, без пересборки.

## Как переключатель открывает страницу {#how-the-switcher-opens-a-page}

`versions.json` это список записей, у каждой есть `label` (`v0.3`, `next`), `link` (путь к главной странице этой версии с конечным слешем) и `kind` (`latest`, `release` или `next`). Файл читается в браузере и ему не доверяют:

- Запись, у которой `link` не является путём сайта документации (адрес с хостом, `//host`, путь с `..`, путь вне корня документации или путь с обратным слешем, полноширинным слешем или обратным слешем, нулевым символом либо закодированным слешем, обратным слешем или нулевым символом, таким как `%2f`, `%5c` или `%00` в любом регистре букв, сколько бы раз он ни был закодирован, как в `%252f`), игнорируется и никогда не попадает в список. Ссылка декодируется, пока не перестанет меняться, а ссылка, которую нельзя декодировать, например с избыточной кодировкой `%c0%af`, тоже игнорируется. Запись с повторяющейся меткой более ранней записи также игнорируется, а из файла читаются только первые 100 записей.
- Выбор версии открывает ту же страницу в ней, если такая страница существует, а если нет, то главную страницу этой версии. При открытии списка переключатель запрашивает у сервера страницу в каждой другой версии методом `HEAD` и повторно запрашивает методом `GET` только тогда, когда сервер отвечает 405 или 501. Перенаправления не отслеживаются.
- Об отсутствии страницы решает только окончательный ответ: любой статус, который не является успехом и не является проходным сбоем, например 404, 403 или 400, либо перенаправление. Поэтому сервер, отвечающий на `HEAD` статусом 403 или 400, получает ссылку на главную страницу. Неудавшийся запрос, отсутствие ответа в течение четырёх секунд и статус 5xx, 408 или 429 не считаются ответом о странице. Пока ссылка ведёт на главную страницу этой версии, а страница запрашивается снова при следующем открытии списка.
- Поиск ограничен. Запрашиваются не более 20 версий, по 4 запроса одновременно, а версия сверх лимита ссылается на свою главную страницу. Окончательные ответы (страница есть или её нет) сохраняются для каждой страницы на время визита, поэтому повторное открытие списка не запрашивает их заново. Неокончательные ответы никогда не сохраняются. Закрытие списка, открытие другой страницы или уход со страницы останавливают запросы, которые ещё выполняются.

## Как выглядит старая версия {#what-an-older-version-looks-like}

- Уведомление вверху сообщает, какая это версия, и ссылается на ту же страницу в последней документации.
- На каждой странице есть каноническая ссылка на ту же страницу в последней документации или на последнюю главную страницу, если страницы там больше нет.
- Страница, которой больше нет в последней документации, также получает `noindex, follow`.
- Карта сайта есть только у последней документации.

## Какие релизы имеют версионную документацию {#which-releases-have-versioned-docs}

Переключатель и перечисленные выше правила находятся в `docs/.vitepress/versions.ts`. Тег релиза, созданный до появления этого файла, не может показывать переключатель, поэтому он не публикуется как версия. Список начинается с первого тега релиза, который содержит этот файл. Пока ни один тег релиза его не содержит, документация собирается из настроенной ссылки (ref), как раньше, и добавляется только `next`. Теги с суффиксом, такие как `-rc.1`, не являются стабильными релизами и игнорируются.

## Настройки сборки {#build-settings}

Читаются файлом `docs/.vitepress/config.ts`. Все необязательны; обычная сборка без них даёт сайт без версий.

| Переменная | Назначение |
|----------|---------|
| `DOCS_VERSION` | `vX.Y` для релиза, `next` для документации разработки, пусто для сборки без версий. |
| `DOCS_LATEST_VERSION` | Метка последнего релиза. Сборка, у которой `DOCS_VERSION` равна ей, является последней. |
| `DOCS_LATEST_URL` | Публичный адрес последней документации. Обязательна для старого релиза и для `next`. |
| `DOCS_VERSIONS_URL` | Откуда браузер загружает `versions.json`. Без неё переключатель остаётся скрытым. |
| `DOCS_LATEST_PAGES` | Путь к JSON-массиву с путями страниц последней документации. Без него каждая страница старого релиза указывает на последнюю главную страницу и помечается `noindex`. |

## Языки {#languages}

Каждая версия собирается на всех трёх языках (английском, русском и армянском) за одну сборку, поэтому `/vX.Y/ru/` и `/next/hy/` существуют рядом с `/vX.Y/`. У релиза, созданного до добавления языков, есть только английский. Смотрите [Перевод документации](/ru/developers/translating-docs).
