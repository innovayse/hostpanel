# Контракт чтения реестра плагинов {#plugin-registry-read-contract}

Эта страница для тех, кто запускает или создаёт реестр плагинов. Она описывает, что Hostpanel запрашивает у реестра и что ему нужно в ответе. Как издатель загружает пакет, она не описывает: это на усмотрение реестра; загрузка, используемая шаблоном рабочего процесса релиза, описана в разделе [Публикация плагина](/ru/developers/publishing-a-plugin). Сторона оператора, с настройками и уровнями доверия, описана в разделе [Реестр плагинов](/ru/operators/plugin-registry).

Клиент реестра это `PluginRegistryClient` в `backend/src/Innovayse.Hostpanel.Infrastructure/Plugins/Registry/`, а типы передачи данных это записи `*Wire` рядом с ним. Если эта страница и код расходятся, прав код.

## Правила, действующие для каждого вызова {#rules-that-apply-to-every-call}

- **Адрес.** Все пути ниже отсчитываются от `PluginRegistry__BaseUrl` оператора. Hostpanel добавляет конечный слеш, если его нет, поэтому `https://registry.example.com/v1` и `https://registry.example.com/v1/` равнозначны.
- **Анонимное чтение.** Hostpanel не отправляет ни заголовка `Authorization`, ни cookie, ни учётных данных аккаунта. Каждая конечная точка на этой странице должна отвечать без них для бесплатного плагина. Реестр, которому для чтения нужен вход, использовать нельзя.
- **Лицензионный ключ.** Единственное, что Hostpanel может отправить, это `X-Licence-Key`, и только если оператор ввёл ключ для платного или закрытого плагина, и только при запросе релиза, странице плагина, списке версий и загрузке пакета. Он не отправляется при запросе списка и при массовом запросе новейших версий (`POST /v1/plugins/latest`), но проверка обновлений заново запрашивает каждый установленный плагин с сохранённым ключом на странице плагина с этим ключом, чтобы лицензиат видел новейшую версию платного или закрытого плагина. Ключ это не более 256 печатных ASCII-символов (от `!` до `~`, без пробелов) после обрезки пробелов; Hostpanel отклоняет всё остальное при сохранении и никогда не отправляет такой ключ. Он уходит только на собственный origin реестра, на каждом шаге перенаправления внутри него, и никогда не пишется в журнал. Отвечайте `401`, когда ключ нужен, а не передан, и `403`, когда ключ недействителен; Hostpanel показывает их как `PLUGIN_REGISTRY_LICENCE_REQUIRED` и `PLUGIN_REGISTRY_LICENCE_INVALID`.
- **Только HTTPS.** Адрес это абсолютный URL `https`. Сертификат должен быть действителен для этого имени.
- **Один origin.** Каждый запрос, каждый шаг перенаправления и каждый адрес пакета должны иметь схему, хост и порт реестра. Ответ, указывающий в другое место, отклоняется, и с него ничего не загружается.
- **JSON.** Имена записываются в camelCase и читаются без учёта регистра. Неизвестные Hostpanel члены игнорируются, поэтому реестр может добавлять члены. JSON-ответ ограничен 1 МиБ.
- **Заголовки.** Вызовы JSON отправляют `Accept: application/json`. Загрузка пакета отправляет `Accept: application/zip, application/octet-stream`.
- **Перенаправления.** GET можно перенаправлять (301, 302, 303, 307 или 308) не более трёх раз и только внутри того же origin. `POST` проверки обновлений никогда не перенаправляется: отвечайте на него напрямую.
- **Коды статусов.** Принимается любой статус успеха. Ответ 404 на запрос релиза, страницу плагина или список версий означает «такого в каталоге нет». В этих вызовах и при загрузке пакета 401 и 403 это лицензионные ответы, описанные выше. Ответ 404 на список или проверку обновлений и любой другой статус ошибки приводят к тому, что вызов завершается как недоступный.
- **Время.** Один вызов, включая загрузку, должен завершиться в пределах `PluginRegistry__Timeout` оператора (по умолчанию 30 секунд).

## Ограниченные плагины: идентичность экземпляра {#restricted-plugins-the-instance-identity}

Реестр может не выдавать плагин публике и отдавать его только установкам, которые он проверил. Hostpanel читает способ распространения плагина из члена `distribution` строки списка и страницы плагина (`summary`): `Download` (по умолчанию, когда член отсутствует или неизвестен) или `HostOnly`. Для плагина `HostOnly` Hostpanel не отправляет `X-Licence-Key`, а вместо этого подписывает свои вызовы. Реестру без ограниченных плагинов всё это не нужно.

**Регистрация.** Hostpanel создаёт пару ключей Ed25519 и вызывает `POST {BaseUrl}instances` с телом `{"publicKey": "<base64 от 32-байтового открытого ключа>", "baseUrl": "<публичный https-адрес установки>"}`. Ответ имеет вид `{"id": "<guid>", "challenge": "<текст>"}` (остальные члены игнорируются). Отвечайте `409` на уже зарегистрированный ключ, `422` или `400` на ключ или адрес, которые вы не примете, и `429` при превышении вашего лимита.

**Проверка.** Затем Hostpanel отдаёт ровно этот challenge как `text/plain` с `Cache-Control: no-store` по адресу `/.well-known/hostpanel-registry/{id}` на своём публичном адресе и вызывает `POST {BaseUrl}instances/{id}/verify` без тела. Запросите этот адрес из реестра, сравните и ответьте `200`, если совпало. Hostpanel начинает заново с новой парой ключей и снова регистрируется при `422` с кодом ошибки `INSTANCE_CHALLENGE_VALIDATION_FAILED` (у challenge истекло время или число попыток), при `404` и при `409`. `422` с другим кодом (например, `INSTANCE_PROOF_VALIDATION_FAILED`, адрес не отдал challenge) повторяется позже с паузой.

**Подписанные вызовы.** Для плагина `HostOnly` Hostpanel подписывает `GET plugins/{id}/versions`, `GET plugins/{id}/versions/{version}`, `POST plugins/{id}/versions/{version|latest}/download-tickets` и итоговый `GET` по адресу, названному в ответе с тикетом. Заголовки: `X-Hostpanel-Instance` (идентификатор), `X-Hostpanel-Timestamp` (unix-секунды), `X-Hostpanel-Nonce` (16–64 символа, новый при каждом вызове) и `X-Hostpanel-Signature` (Ed25519 в base64). Подпись берётся от UTF-8-байтов этих строк, соединённых символом перевода строки, без завершающего перевода строки:

```text
HOSTPANEL-REGISTRY-V1
<METHOD>
<request target exactly as sent, path and query, including ?ticket=...>
<lower-case hex SHA-256 of the body>
<timestamp>
<nonce>
```

Ни у одного из этих вызовов нет тела, поэтому четвёртая строка это хеш пустой строки, `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`. Ответ с тикетом имеет вид `{"ticket": "...", "downloadUrl": "..."}`, причём `downloadUrl` должен быть на собственном origin реестра и содержать тикет. Отказы реестра читаются из члена `type` тела его ошибки: `401` с `INSTANCE_SIGNATURE_INVALID_UNAUTHORIZED`, `INSTANCE_TIMESTAMP_UNAUTHORIZED` или `INSTANCE_REPLAY_UNAUTHORIZED`; `403` с `INSTANCE_NOT_VERIFIED_FORBIDDEN`, `INSTANCE_REVOKED_FORBIDDEN` или `DOWNLOAD_TICKET_INVALID_FORBIDDEN`; и `429` с `INSTANCE_RATE_LIMIT_EXCEEDED`. Массовый запрос `POST plugins/latest` не подписывается и для ограниченного плагина может отвечать пустым `downloadUrl`.

## Как BaseUrl связан с путём загрузки {#how-baseurl-relates-to-the-upload-path}

Hostpanel строит каждый адрес чтения, добавляя пути ниже к `BaseUrl`. Загрузка, показанная в разделе [Публикация плагина](/ru/developers/publishing-a-plugin#upload-with-an-api-key), это `POST /v1/plugins/{id}/versions`, и рабочий процесс релиза строит её из собственной переменной `PLUGIN_REGISTRY_URL`, в которой нет сегмента версии (`https://registry.example.com`). Обе стороны рядом:

| Кто | Настройка | Значение | Адрес, который используется |
|---|---|---|---|
| Рабочий процесс издателя | `PLUGIN_REGISTRY_URL` | `https://registry.example.com` | `POST https://registry.example.com/v1/plugins/{id}/versions` |
| Hostpanel оператора | `PLUGIN_REGISTRY_BASE_URL` | `https://registry.example.com/v1/` | `GET https://registry.example.com/v1/plugins/{id}/versions/{version}` |

Таким образом, `BaseUrl` оператора это URL реестра издателя плюс сегмент `/v1/`. Чтение и загрузка тогда используют одну коллекцию, `/v1/plugins/{id}/versions`: `POST` туда загружает, а GET на `/v1/plugins/{id}/versions/{version}` читает один релиз. Реестр вправе отдавать чтение по другому префиксу, лишь бы `BaseUrl` оператора заканчивался там, где начинается путь `plugins`.

## Конечные точки {#the-endpoints}

### Список и поиск {#list-and-search}

```
GET {BaseUrl}plugins?q={text}&category={category}&page={page}&pageSize={pageSize}
```

| Параметр | Когда отправляется | Значение |
|---|---|---|
| `q` | только когда оператор ввёл поисковый запрос | Текст с URL-экранированием, не более 100 символов. Сопоставляйте его с названием, описанием и автором по своему усмотрению. |
| `category` | только когда выбрана категория | Одно из `Payment`, `Provisioning`, `Registrar`, `App`, `Other`, записанное именно так. Читайте без учёта регистра. |
| `page` | всегда | Начинается с 1. |
| `pageSize` | всегда | От 1 до 100 (панель администратора запрашивает 20). Возвращайте не больше этого числа элементов. |

Ответ:

```json
{
  "items": [
    {
      "pluginId": "sample-gateway",
      "name": "Sample gateway",
      "description": "Takes card payments through a sample processor.",
      "publisherName": "Example Publisher",
      "iconUrl": "icons/sample-gateway.svg",
      "category": "Payment",
      "latestVersion": "1.2.0",
      "verified": true,
      "pricing": "Free"
    }
  ],
  "page": 1,
  "pageSize": 20,
  "total": 1
}
```

`total` это число плагинов, подходящих под фильтр, по всем страницам. Отрицательное значение читается как 0. `page` и `pageSize` не нужны: Hostpanel использует те, что запросил сам. Члены, которые Hostpanel не использует (рейтинг, число загрузок и так далее), могут присутствовать.

### Новейшие версии установленных плагинов {#latest-versions-of-installed-plugins}

```
POST {BaseUrl}plugins/latest
Content-Type: application/json

{ "ids": ["sample-gateway", "another-plugin"] }
```

Идентификаторы это идентификаторы плагинов, которые оператор установил или загрузил. Ответьте простым JSON-массивом: по одному элементу для каждого известного вам идентификатора и ничего для неизвестного. Каждый элемент описывает новейшую опубликованную версию в той же форме, что и релиз (см. следующий раздел):

```json
[
  {
    "pluginId": "sample-gateway",
    "version": "1.2.0",
    "downloadUrl": "/v1/plugins/sample-gateway/versions/1.2.0/download",
    "sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08",
    "verified": true,
    "sdkVersion": "3.1.0",
    "requiresLicence": false,
    "changelog": "Fixes a rounding error."
  }
]
```

Ответ не разбивается на страницы: он должен уместиться в 1 МиБ. Элемент для идентификатора, о котором не спрашивали, игнорируется, а элемент, у которого `version` не является строгим `major.minor.patch`, пропускается. `verified` и `requiresLicence` могут быть `null`, что читается как `false`. `pluginId` должен быть корректным идентификатором плагина, иначе весь ответ недействителен. Так вкладка «Установленные» узнаёт, что есть обновление, только по `version`. У элемента нет названия, поэтому Hostpanel показывает идентификатор; `requiresLicence`, равное `true`, читается как платный плагин.

Элемент может также содержать `changelog`, то есть список изменений этой новейшей версии в Markdown, по тем же правилам, что и член строки версии. Hostpanel использует его, чтобы показать, что приносит обновление, поэтому реестру, у которого есть такие списки, стоит его отдавать.

### Один релиз {#one-release}

```
GET {BaseUrl}plugins/{id}/versions/{version}
```

`id` и `version` это сегменты пути с URL-экранированием. Ответ:

```json
{
  "pluginId": "sample-gateway",
  "version": "1.2.0",
  "downloadUrl": "https://registry.example.com/v1/files/sample-gateway-1.2.0.zip",
  "sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08",
  "verified": true
}
```

| Член | Правило |
|---|---|
| `pluginId`, `version` | Необязательны. Если присутствуют, они должны совпадать с запрошенными символ в символ, иначе установка отклоняется. Если отсутствуют, Hostpanel берёт запрошенные значения. |
| `downloadUrl` | Обязателен. Абсолютный или относительный к `BaseUrl` (путь, начинающийся с `/`, отсчитывается от корня хоста). Должен указывать на схему, хост и порт самого реестра. |
| `sha256` | Обязателен. SHA-256 ZIP-файла, 64 шестнадцатеричных символа, в любом регистре. |
| `verified` | Необязателен, при отсутствии `false`. Это значение читает уровень доверия `VerifiedOnly`. |

Отвечайте 404, когда в реестре нет такой версии. Остальные члены (идентификатор ключа, размер, статус, список изменений и так далее) здесь игнорируются.

### Страница одного плагина {#one-plugin-page}

```
GET {BaseUrl}plugins/{id}
```

Ответ: запись списка как `summary`, плюс ссылки и новейшая версия.

```json
{
  "summary": { "pluginId": "sample-gateway", "name": "Sample gateway", "latestVersion": "1.2.0", "pricing": "Free" },
  "licence": "MIT",
  "repository": "https://example.org/sample/gateway",
  "buyUrl": null,
  "contactUrl": "https://example.org/contact",
  "documentationUrl": "https://example.org/docs",
  "supportUrl": "https://example.org/support",
  "latest": { "version": "1.2.0", "status": "Published", "publishedAt": "2026-01-02T03:04:05Z" }
}
```

`summary` подчиняется правилам из раздела «Записи списка» ниже, с той разницей, что отсутствие `latestVersion` допускается. Ссылки сохраняются, только если это абсолютные адреса `http` или `https` (они могут указывать на любой хост, панель администратора открывает их в новой вкладке); всё остальное отбрасывается. `latest` это версия, как описано дальше, или `null`. Отвечайте 404, когда плагина нет в каталоге: Hostpanel показывает это как «не найдено».

### Версии плагина {#versions-of-a-plugin}

```
GET {BaseUrl}plugins/{id}/versions
```

Ответ: JSON-массив версий, новейшие первыми.

```json
[
  {
    "version": "1.2.0",
    "sdkVersion": "3.1.0",
    "sizeBytes": 20480,
    "publishedAt": "2026-01-02T03:04:05Z",
    "status": "Published",
    "statusReason": null,
    "replacementVersion": null,
    "minHostVersion": "1.0.0",
    "maxHostVersion": null,
    "changelog": "Fixes a rounding error.",
    "permissions": ["FileSystem"],
    "icon": { "url": "/media/icon.png", "contentType": "image/png", "sizeBytes": 900, "width": 64, "height": 64 },
    "screenshots": [{ "url": "/media/shot1.png", "contentType": "image/png", "sizeBytes": 52000, "width": 800, "height": 600 }]
  }
]
```

| Член | Правило |
|---|---|
| `version` | Обязателен, строгий `major.minor.patch`. Строка без пригодного значения пропускается. |
| `status` | Обязателен: `InReview`, `Published`, `Rejected`, `Deprecated` или `Yanked`, читается без учёта регистра. Строка с другим значением пропускается. |
| `permissions` | Необязателен. `Process`, `RawSockets`, `ReflectionEmit`, `NativeInterop` или `FileSystem`. Неизвестные имена игнорируются. |
| `icon`, `screenshots` | Необязательны. `url` абсолютный или относительный к `BaseUrl`; изображение не с собственного origin реестра отбрасывается. Сохраняется не более 20 скриншотов. |
| `changelog` | Необязателен, Markdown, переводы строк сохраняются, не более 20000 символов. Hostpanel показывает его как оформленный текст (заголовки, списки, жирный шрифт, код и ссылки `https`; сырой HTML показывается как текст). |
| другие текстовые члены | Очищаются от управляющих символов и обрезаются по длине. |

Если одна и та же `version` перечислена дважды с разными статусами, Hostpanel оставляет самый строгий: `Yanked`, затем `Rejected`, `InReview`, `Deprecated` и `Published`.

Отвечайте 404, когда плагина нет в каталоге.

## Записи списка {#listing-entries}

Hostpanel проверяет каждую запись, и одна запись, не являющаяся плагином (неверный идентификатор, нет названия, неизвестная цена), делает весь ответ недействительным с `PLUGIN_REGISTRY_RESPONSE_INVALID`. Запись без пригодного `latestVersion` просто пропускается.

| Член | Правило |
|---|---|
| `pluginId` | Обязателен (`id` тоже читается). Идентификатор плагина: строчные буквы, цифры и одиночные дефисы, не более 64 символов. |
| `name` | Обязателен, не пуст после удаления управляющих символов и окружающих пробелов. Обрезается до 200 символов. |
| `latestVersion` | Строгая версия `major.minor.patch` или `null` для плагина, у которого ничего не опубликовано. Запись с отсутствующим, `null` или некорректным значением исключается со страницы; остальные записи сохраняются. |
| `latestChangelog` | Необязателен, Markdown, не более 20000 символов. Список изменений новейшей версии, показывается на карточке в каталоге. |
| `pricing` | Обязателен. `Free`, `Paid` или `Private`, читается без учёта регистра. |
| `category` | Необязателен. Неизвестное или отсутствующее значение показывается как `Other`. |
| `description` | Необязателен, обрезается до 2000 символов. |
| `publisherName` | Необязателен (`author` тоже читается), обрезается до 200 символов. |
| `sdkVersion` | Необязателен, обрезается до 32 символов, показывается только для сведения. В списке его может не быть. |
| `iconUrl` | Необязателен. Абсолютный или относительный к `BaseUrl`. Сохраняется только если он на собственном origin реестра; любой другой адрес значка отбрасывается. |
| `verified` | Необязателен, при отсутствии `false`. Показывается как значок. Решение о доверии при установке читает `verified` из релиза, поэтому отдавайте его в обоих местах. |

Текст реестра показывается в панели администратора как простой текст. Разметка в нём не интерпретируется.

## Пакет {#the-package}

`downloadUrl` запрашивается через GET. В ответе должен быть подписанный ZIP, описанный в разделе [Публикация плагина](/ru/developers/publishing-a-plugin#zip-content-rules), в пределах `MaxDownloadBytes` оператора (по умолчанию 50 МиБ). `Content-Length` сверх лимита отклоняется до прочтения хотя бы одного байта, а тело без этого заголовка обрывается при превышении лимита. Имя файла значения не имеет.

Затем Hostpanel проверяет в таком порядке, прежде чем пакет сохраняется:

1. Уровень доверия по `verified` из релиза, а для `OwnKeysOnly` по идентификатору ключа в `plugin.sig`.
2. SHA-256 загруженного файла по `sha256` из релиза, без учёта регистра.
3. `id` и `version` в `plugin.json` пакета по тем, что запрашивались.
4. Обычные правила пакета и подпись по ключам, которым доверяет хост. Пакет из реестра должен быть подписан; допуск неподписанных пакетов для ручной загрузки здесь никогда не действует.

Публикуйте `sha256` именно того файла, который вы отдаёте. Замена файла без обновления релиза приводит к тому, что любая установка завершается с `PLUGIN_REGISTRY_CHECKSUM_MISMATCH`, поэтому версию лучше считать неизменяемой, как только она попала в каталог.

## Быстрая проверка {#a-quick-check}

При работающем реестре все эти запросы должны выполняться без учётных данных для бесплатного плагина:

```bash
curl --fail https://registry.example.com/v1/plugins?page=1\&pageSize=20
curl --fail --header "Content-Type: application/json" --data '{"ids":["sample-gateway"]}' https://registry.example.com/v1/plugins/latest
curl --fail https://registry.example.com/v1/plugins/sample-gateway/versions/1.2.0
curl --fail https://registry.example.com/v1/plugins/sample-gateway
curl --fail https://registry.example.com/v1/plugins/sample-gateway/versions
```

Для платного или закрытого плагина релиз, страница, список версий и загрузка должны отвечать `401` без заголовка и `403` с неверным ключом:

```bash
curl --header "X-Licence-Key: YOUR-KEY" --fail https://registry.example.com/v1/plugins/paid-plugin/versions/1.0.0
```

Затем запросите `downloadUrl` из последнего ответа и сравните `sha256sum` файла с `sha256`.
