# Перевод Hostpanel {#translating-hostpanel}

Hostpanel поставляется на английском, русском и армянском языках.

<Callout type="note">
Английский является исходным языком и запасным вариантом, когда текста нет на другом языке.
</Callout>

## Где лежат тексты {#where-the-texts-live}

| Часть | Путь | Кем загружается |
|------|------|-----------|
| Панель администратора | `admin/src/locales/<lang>/<area>.json` | `admin/src/locales/messages.ts` |
| Клиентский портал | `client/locales/<lang>/<module>.json` | `client/plugins/i18n.ts` (список `MODULES`) |
| Сообщения об ошибках API | `backend/src/Innovayse.Hostpanel.Application/Resources/ErrorMessages.resx` (en) с `ErrorMessages.ru.resx` / `ErrorMessages.hy.resx` | Язык берётся из заголовка запроса `X-Language`; `Accept-Language` не используется. Неизвестное или отсутствующее значение заменяется на `en`. |
| Сообщения проверки API | `ApplicationValidationMessages*.resx` в `Application/Resources/` и `ValidationMessages*.resx` в `Shared/Resources/` | Так же, как выше: заголовок `X-Language`, запасной вариант `en`. |
| Шаблоны писем | Редактируются для каждого языка в панели администратора, не в файлах | |
| Содержимое витрины | Вводится для каждого языка в панели администратора | |

## Как называются ключи {#how-keys-are-named}

**Панель администратора.** Имя файла служит первым сегментом ключа. В `nav.json` лежат `nav.*`, которые используются как `t('nav.dashboard')`. У каждого раздела свой файл: `billing.json`, `clients.json`, `servers.json` и так далее.

**Клиентский портал.** Ключи вложены в файлы модулей и при запуске объединяются в один набор в `client/plugins/i18n.ts`.

**API.** Ключом служит код ошибки, например `SIGN_IN_UNAUTHORIZED`.

<Callout type="warning">
Никогда не переименовывайте ключ в файле перевода. Меняйте только значение.
</Callout>

## Плейсхолдеры и множественное число {#placeholders-and-plurals}

Сохраняйте каждый плейсхолдер `{name}` точно таким же, как в английском оригинале. Тесты на соответствие проверяют их и падают, если плейсхолдер пропущен или переименован.

В панели администратора правило русского множественного числа определено в `admin/src/i18n.ts`. Добавляя форму множественного числа на русском, следуйте уже имеющемуся там правилу. Например:

```ts
// admin/src/locales/ru/billing.json
{
  "invoiceCount": "{n} счёт | {n} счёта | {n} счетов"
}
```

Три слота соответствуют форме для одного, для двух, четырёх и для пяти и более, как в функции `russianPlural` в `i18n.ts`.

## Стиль {#style}

Короткие простые предложения. Используйте те же термины, что и в остальном языке. Небольшой глоссарий основных терминов:

| English | Русский | Հայերեն |
|---------|---------|---------|
| Invoices | Счета | Հաշիվ-ապրանքագրեր |
| Services | Услуги | Ծառայություններ |
| Support Tickets | Тикеты поддержки | Աջակցության հայտեր |
| Servers | Серверы | Սերվերներ |
| Clients | Клиенты | Հաճախորդներ |

Не добавляйте названия продуктов, которых нет в английском оригинале.

## Проверьте, что ничего не пропущено {#check-that-nothing-is-missing}

<Callout type="tip">
Запускайте <code>lint:i18n</code> перед отправкой. CI запускает те же скрипты.
</Callout>

::: code-group

```bash [Admin panel]
cd admin && npm run lint:i18n
```

```bash [Client portal]
cd client && yarn lint:i18n
```

```bash [API]
cd backend && dotnet test tests/Innovayse.Hostpanel.Architecture.Tests --filter ResourceCoverageTests
```

:::

Запуск с отсутствующими ключами выглядит так:

```
lint:i18n failed: 2 problem(s).
  missing in ru: nav.documentation
  missing in hy: nav.documentation
```

Проверка панели администратора сообщает об отсутствующих, лишних и неиспользуемых ключах, а также о вызовах перевода без английского оригинала. Тестовые файлы `admin/tests/locales/parity.test.ts` и `admin/tests/locales/messages.test.ts` проверяют, что во всех языках одинаковые ключи и что нет пропущенных плейсхолдеров.

`lint:i18n` клиентского портала и `client/tests/locales/parity.test.ts` проверяют то же самое: одинаковые ключи во всех языках, отсутствие пустых строк, одинаковые плейсхолдеры.

`ResourceCoverageTests` (в архитектурных тестах бэкенда) проверяет, что у каждого кода ошибки в `HostpanelErrorCodes.cs` есть предложение в каждом языковом файле, без лишних ключей и со значениями, отличающимися от английских.

## Посмотрите свой язык локально {#see-your-language-locally}

Запустите стек разработки (см. [Локальный запуск](/ru/developers/local-dev)).

- **Демо:** если доступно публичное демо, кнопка «Try the demo» в навигационной панели документации открывает панель администратора. Переключите там язык, чтобы проверить текущее состояние без локального стека.
- **Панель администратора:** используйте переключатель языка в верхней панели. Выбор хранится в браузере как `admin.locale`.
- **Клиентский портал:** используйте переключатель языка, который добавляет к URL `/ru` или `/hy`. Английский отдаётся без префикса. Обзор того, что видят клиенты, смотрите в разделе [Клиентский портал](/ru/customers/portal).
- **Сообщения об ошибках API:** отправьте `X-Language: en`, `X-Language: ru` или `X-Language: hy` в любом запросе и прочитайте поле `detail` в теле ошибки. Любое неподдерживаемое значение заменяется на `en`.
- **Шаблоны писем:** переведённые версии управляются в панели администратора. Как добавить языковую версию, смотрите в разделе [Шаблоны писем](/ru/staff/email-templates).

## Отправьте изменение {#send-the-change}

Допустим один pull request на язык и раздел. Сначала запустите все проверки выше. Скриншоты двух-трёх переведённых экранов помогают ревью. Откройте pull request в ветку `develop`.
