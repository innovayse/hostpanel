# Переход с WHMCS {#moving-from-whmcs}

<Label type="admin" />

<DemoLink path="/migration" />

Hostpanel импортирует ваши данные из WHMCS. Вы устанавливаете в WHMCS небольшое PHP-дополнение. Затем Hostpanel
запрашивает у дополнения ваши записи, страница за страницей, и импортирует их. В WHMCS ничего не записывается.

## Что понадобится {#what-you-need}

- Установка WHMCS на PHP 8.1 или новее. Дополнение использует возможности PHP 8.1.
- Публичный HTTPS-адрес этой установки WHMCS. Hostpanel обращается к нему с вашего сервера Hostpanel.
- Доступ администратора к обеим системам и доступ по FTP или SSH к файлам WHMCS.

## Из WHMCS за пять шагов {#from-whmcs-in-five-steps}

1. В Hostpanel откройте **Инструменты миграции**, нажмите **Новая миграция**, введите адрес WHMCS и
   выберите данные для импорта. Hostpanel создаст секретный ключ.
2. Скачайте `innovayse-migration.zip` с карточки задания и распакуйте его в корневую папку
   WHMCS.
3. В WHMCS откройте **Configuration > System Settings > Addon Modules**, активируйте
   **Hostpanel Migration**, нажмите **Configure** и вставьте ключ в поле **Migration Key**.
4. В Hostpanel нажмите **Проверить**. Дождитесь надписи **Плагин подключён**.
5. Нажмите **Начать импорт**, а когда он завершится, просмотрите **Отчёт об импорте**.

В разделах ниже каждый шаг объясняется подробнее, а также описано, что делать при сбоях.

## Как работает миграция {#how-a-migration-works}

Задание миграции хранит секретный ключ. Дополнение в исходной системе читает каждый запрос, проверяет
ключ и возвращает по одной странице записей. Hostpanel импортирует каждую страницу, прежде чем запросить
следующую. Загрузка выполняется в фоне, поэтому закрытие браузера её не останавливает.

Если сервер перезапустится посреди загрузки, задание восстановления (`RecoverInterruptedMigrationJobsCommand`) запускается
каждые пять минут и помечает как неудавшееся любое задание, у которого сигнал активности не обновлялся последние пятнадцать
минут (оба интервала настраиваются), так что задание можно повторить.

Адрес источника должен быть публичным HTTPS-адресом. Внутренние адреса и схемы, отличные от HTTPS, не
разрешены.

## Что импортируется {#what-is-imported}

Записи загружаются в таком порядке. Порядок важен: для услуги сначала должны существовать клиент и продукт;
для ответа на тикет, сам тикет.

| Порядок | Тип записи | Примечания |
|---|---|---|
| 1 | Клиенты | Одна учётная запись на клиента. |
| 2 | Контакты | Дополнительные контакты импортированного клиента. |
| 3 | Продукты | Каталог продуктов с группами продуктов. |
| 4 | Счета | Связываются с клиентом по адресу электронной почты. |
| 5 | Услуги | Связываются с клиентом и с продуктом по названию. |
| 6 | Домены | Связываются с клиентом. |
| 7 | Тикеты | Связываются с клиентом. |
| 8 | Заказы | Здесь связываются с продуктами. |
| 9 | Транзакции | Связываются со счётом. |
| 10 | Предложения | Связываются с клиентом. |
| 11 | База знаний | Статьи и их категории. |
| 12 | Ответы на тикеты | Ответы на импортированные тикеты. |
| 13 | Объявления | Публичные объявления. |
| 14 | Загрузки | Файлы и их категории. |
| 15 | Сетевые проблемы | Инциденты страницы статуса. |

Типы, которые нужно включить, вы выбираете при создании задания. Невыбранные типы пропускаются полностью.

## Что не импортируется {#what-is-not-imported}

**Пароли.** Перенесённые клиенты получают случайный непригодный пароль. Чтобы войти, им нужно сбросить его через
процедуру сброса пароля.

<Callout type="note">
Попросите клиентов воспользоваться «Забыли пароль?» при первом входе после переезда.
</Callout>

Записи, которые дополнение не экспортирует, не импортируются, и их нужно настроить заново вручную. К ним
относятся учётные данные платёжных шлюзов, журналы электронной почты и настройки двухфакторной аутентификации.

## Перед началом {#before-you-start}

<Callout type="danger">
Сделайте резервную копию базы данных Hostpanel перед первым импортом. Миграцию нельзя откатить
автоматически; резервная копия, единственный путь восстановления, если что-то пойдёт не так.
</Callout>

<Callout type="tip">
Перед импортом настройте в Hostpanel валюты, хостинг-серверы и отделы поддержки. Услуги
связываются с продуктами и серверами, а тикеты, с отделами. Записи, для которых здесь нет родительской
записи, пропускаются.
</Callout>

## Создание миграции {#create-a-migration}

<Steps>
<li>

**Откройте «Инструменты миграции»**

Откройте **Инструменты миграции** в панели администратора и нажмите **Новая миграция**.

Заполните:
- **URL источника**: корневой адрес вашей установки WHMCS, например `https://billing.example.com`.
  Hostpanel сам добавит путь дополнения `/modules/addons/innovayse_migration/api.php`. Можно также
  вставить полный адрес, который показывает страница самого дополнения; путь повторно не добавляется.
- **Название** (необязательно): имя этого задания, например `Production Server`.
- **Данные для импорта**: типы записей для загрузки. Используйте **Выбрать все** или отметьте отдельные типы.

Нажмите **Создать миграцию**. Для задания будет создан секретный ключ.

</li>
<li>

**Установите дополнение в WHMCS**

Скачайте `innovayse-migration.zip` с карточки **Требуется настройка** и распакуйте его в корневую
папку WHMCS. Файлы окажутся в:

```
/modules/addons/innovayse_migration/
```

В админ-панели WHMCS откройте **Configuration > System Settings > Addon Modules**. Найдите
**Hostpanel Migration**, нажмите **Activate**, затем **Configure**. Вставьте секретный ключ с карточки
**Требуется настройка** в поле **Migration Key** и нажмите **Save Changes**.

В разделе **Access Control** отметьте роли администраторов, которым разрешено открывать страницу дополнения в WHMCS. Эта страница
показывает, задан ли ключ, и **URL источника**, к которому обращается Hostpanel. Для самого импорта
отмечать какие-либо роли не требуется.

</li>
<li>

**Проверьте соединение**

Нажмите **Проверить**. Hostpanel вызывает конечную точку ping дополнения. Карточка покажет одно из:
- **Плагин подключён**: ключ принят.
- **Проверка**: запрос выполняется.
- **Ожидание плагина**: ожидание повторной попытки.
- **Недоступен**: дополнение не ответило или отклонило ключ. Проверьте URL источника, убедитесь, что
  дополнение активно в WHMCS, и убедитесь, что ключ в настройках дополнения совпадает с ключом на карточке.

</li>
<li>

**Начните импорт**

Нажмите **Начать импорт**. Задание перейдёт в статус **В очереди**, а затем в **Выполняется**, когда его
подхватит фоновый обработчик. Счётчики **Перенесено**, **Пропущено** и **Ошибка** обновляются по мере обработки записей.

</li>
</Steps>

## Статусы задания {#job-statuses}

| Статус | Значение |
|---|---|
| Ожидает | Задание создано, но ещё не запущено. |
| В очереди | Запуск запрошен; фоновый обработчик его ещё не подхватил. |
| Выполняется | Обработчик активно загружает данные. |
| Завершена | Все выбранные типы записей загружены без ошибок. |
| Ошибка | Загрузка остановилась, не завершившись. |

## Если задание завершилось ошибкой {#when-a-job-fails}

Причина ошибки показана на карточке задания. Нажмите **Повторить импорт**, чтобы снова поставить загрузку в очередь.
Повтор сбрасывает счётчики и начинает с самого начала. Уже импортированные записи
пропускаются, поэтому повтор добавляет только то, что появилось нового.

| Причина | Что делать |
|---|---|
| Источник недоступен | Проверьте URL источника и убедитесь, что WHMCS работает. |
| Источник отклонил запрос, проверьте ключ | Дополнение ответило статусом ошибки. Чаще всего ключ неверен или дополнение не активно: скопируйте ключ с карточки задания в настройки дополнения заново. Та же причина показывается, когда дополнение отвечает 429 (слишком много неверных ключей с этого адреса; подождите 15 минут), 503 (дополнение не может записать журнал попыток во временную папку сервера) или 500 (экспорт не удался; посмотрите журнал ошибок WHMCS). |
| Не удалось импортировать записи | Подробности смотрите в журнале сервера. Устраните причину и повторите. |
| Импорт был остановлен | Загрузка была отменена. Повторите, когда будете готовы. |
| Сервер остановился до завершения импорта | Процесс был прерван (перезапуск или сбой). Задание восстановления запускается каждые 5 минут и помечает ошибкой любое задание, у которого 15 минут нет сигнала активности (оба интервала настраиваются). Повторите, когда сервер стабилизируется. |
| Адрес источника не разрешён, укажите публичный HTTPS-адрес | URL источника должен использовать HTTPS и указывать на публичный адрес. Внутренние адреса не разрешены. |

## Безопасный повторный запуск {#run-it-again-safely}

<Callout type="note">
При повторном запуске каждый тип записей пропускает дубликаты. Группы продуктов, категории базы знаний и
категории загрузок используются повторно без уведомления. Все остальные существующие записи фиксируются в журнале как «Пропущено»
с причиной «Уже существует» и остаются без изменений.
</Callout>

Записи сопоставляются так: клиенты по адресу электронной почты, контакты по адресу электронной почты, продукты по названию,
домены по доменному имени, услуги по клиенту и идентификатору услуги в источнике (строки, импортированные до того, как идентификатор стал сохраняться, по клиенту и домену или имени пользователя панели), счета по
клиенту и внешнему идентификатору, тикеты и предложения по клиенту и теме, заказы по номеру заказа,
транзакции по клиенту и идентификатору транзакции, статьи базы знаний по заголовку, объявления по заголовку
и дате (только по заголовку, если в источнике нет даты), сетевые проблемы по заголовку и дате начала (только по
заголовку, если в источнике нет даты начала), загрузки по названию и категории, ответы на тикеты по
тикету, автору, роли и сообщению. Категории загрузок сопоставляются по названию.

Каждая услуга в записи источника несёт собственный идентификатор, поэтому при повторе уже импортированная услуга пропускается,
даже если у неё нет домена или имени пользователя панели, а две услуги с общим доменом импортируются обе. Только услуги,
импортированные до того, как идентификатор стал сохраняться, сопоставляются по клиенту и домену (или имени пользователя
панели); услуга из их числа, у которой нет ни того, ни другого, не имеет ключа сопоставления и при повторе импортируется снова.

Для типов, у которых есть ключ сопоставления (клиенты, контакты, продукты, услуги, домены, счета, тикеты, предложения, заказы, транзакции, статьи базы знаний, объявления, сетевые проблемы, загрузки и ответы на тикеты), повторный запуск того же задания добавляет только записи, которые появились после предыдущего запуска.

Чтобы заново импортировать изменённую запись, сначала удалите её в Hostpanel, затем повторите задание.

## Проверка результата {#check-the-result}

После завершения импорта выборочно проверьте данные:

- Число клиентов совпадает с WHMCS.
- Открытые счета и балансы верны.
- Активные услуги находятся на нужных серверах.
- У доменов правильные даты окончания.
- Открытые тикеты находятся в нужных отделах.
- Выберите пять клиентов и проверьте их услуги, счета и тикеты от начала до конца.

Откройте **Отчёт об импорте**, чтобы просмотреть каждую пропущенную запись и запись с ошибкой. См.
[Отчёт об импорте и причины пропуска](/ru/migration/import-report).

## После переезда {#after-the-move}

Когда миграция завершена и проверена:

- В WHMCS очистите поле дополнения **Migration Key** и сохраните. Если ключ не задан, дополнение отклоняет
  любой запрос. Затем деактивируйте дополнение и удалите папку `modules/addons/innovayse_migration/`.
- Удалите старые задания миграции (**Удалить миграцию**), когда их отчёт об импорте больше не нужен.
  Это удаляет задание и весь его журнал и не может быть отменено.

## Для контрибьюторов: дополнение {#for-contributors-the-addon}

Дополнение находится в `backend/plugins/innovayse_migration/`. Его точка входа,
`modules/addons/innovayse_migration/api.php`, который загружает исходную систему, аутентифицирует
запрос и передаёт его в `ApiKernel`.

### Структура {#layout}

```
modules/addons/innovayse_migration/
  api.php
  autoload.php
  innovayse_migration.php
  lib/
    Module.php
    ApiKernel.php
    Router.php
    Paging/
    Mapping/
    Database/
    Addon/
    Export/
    Http/
    Auth/
```

### Формат запроса {#request-format}

Каждый запрос содержит тело POST в формате JSON:

<SettingTable :settings="[
  { name: 'key', type: 'string', description: 'Ключ миграции, заданный в настройках дополнения.' },
  { name: 'action', type: 'string', description: 'Одно из: ping, totals, clients, contacts, product_groups, products, invoices, services, domains, tickets, ticket_replies, orders, transactions, quotes, knowledgebase_categories, knowledgebase, announcements, download_categories, downloads, network_issues.' },
  { name: 'page', type: 'number', default: '1', description: 'Номер страницы, начиная с 1.' },
  { name: 'perPage', type: 'number', default: '100', description: 'Размер страницы, от 10 до 500.' },
  { name: 'afterId', type: 'number', description: 'Курсор по ключу: вернуть только строки, id которых больше этого значения. Если задан, page игнорируется.' },
]" />

Действие `ping` возвращает `{"ok":true}`. Действие `totals` возвращает по одному счётчику на каждый тип сущности.
Действия с наборами данных возвращают страницу строк.

### Аутентификация {#authentication}

Дополнение сравнивает ключ за постоянное время. После 10 неудачных попыток в течение 15-минутного окна
адрес вызывающей стороны блокируется до конца окна. Успешная аутентификация сбрасывает
счётчик.

### Ответы с ошибками {#error-responses}

| Статус HTTP | Сообщение | Условие |
|---|---|---|
| 401 | `Invalid migration key.` | Ключ не передан, не настроен или неверен. |
| 429 | `Too many failed attempts.` | Адрес заблокирован ограничителем. |
| 503 | `Attempt log unavailable.` | Файл журнала ограничителя нельзя прочитать или записать. |
| 400 | `Unknown action.` | Поле `action` не соответствует ни одному известному действию. |
| 500 | `Source system bootstrap not found.` | `init.php` находится не там, где его ожидает дополнение. |
| 500 | `Export failed.` | Экспортёр выбросил исключение; подробности вызывающей стороне не возвращаются. |

### Запуск тестов {#running-the-tests}

```bash
cd backend/plugins/innovayse_migration
composer install
./vendor/bin/phpunit
```

Тесты используют драйвер базы данных в памяти и не требуют работающей исходной системы.

### Коды ошибок (API Hostpanel) {#error-codes-hostpanel-api}

API Hostpanel возвращает такие коды для операций миграции:

| Код | Сообщение |
|---|---|
| `MIGRATION_JOB_NOT_FOUND` | Такого задания миграции нет. |
| `MIGRATION_JOB_NOT_PENDING` | Это задание миграции уже запущено или завершено и не может быть запущено снова. |
| `MIGRATION_JOB_NOT_FAILED` | Это задание миграции не завершилось ошибкой, поэтому его нельзя повторить. |
| `MIGRATION_JOB_INVALID_TRANSITION` | Это задание миграции не может выполнить это действие в текущем состоянии. |
| `MIGRATION_PLUGIN_NOT_FOUND` | Плагин миграции недоступен в этом развёртывании. |
| `MIGRATION_CONNECTION_UPSTREAM_FAILED` | Не удалось подключиться к исходной системе. Проверьте адрес и повторите. |
