# Реестр плагинов {#plugin-registry}

Реестр плагинов представляет собой каталог подписанных пакетов плагинов. Когда вы направляете Hostpanel на реестр, на странице «Плагины» панели администратора появляется вкладка «Каталог»: на ней можно искать по каталогу, открывать страницу с описанием плагина, устанавливать выбранную версию и хранить лицензионный ключ платного плагина.

По умолчанию реестр выключен, а Hostpanel поставляется без адреса реестра. Реестр выбираете вы, и вы же решаете, насколько ему доверять.

<Callout type="warning">
Плагин работает внутри вашего сервера. Включение реестра не делает безопасным каждый плагин в списке. Прежде чем что-либо устанавливать, прочитайте ниже об уровнях доверия.
</Callout>

## Включение {#switch-it-on}

Задайте два значения в `.env` и пересоздайте стек:

```bash
PLUGIN_REGISTRY_ENABLED=true
PLUGIN_REGISTRY_BASE_URL=https://registry.example.com/v1/
```

| Настройка | Переменная compose | По умолчанию | Значение |
|---|---|---|---|
| `PluginRegistry__Enabled` | `PLUGIN_REGISTRY_ENABLED` | `false` | Включает реестр. Пока он выключен, любое обращение к реестру возвращает `PLUGIN_REGISTRY_DISABLED`, а вкладка «Каталог» не показывается. |
| `PluginRegistry__BaseUrl` | `PLUGIN_REGISTRY_BASE_URL` | пусто | Адрес реестра: абсолютный URL с `https` и именем хоста, без имени пользователя и пароля, без запроса и без фрагмента. |
| `PluginRegistry__Timeout` | нет | `00:00:30` | Предельное время одного обращения к реестру, включая загрузку пакета. От 1 секунды до 5 минут. |
| `PluginRegistry__MaxDownloadBytes` | нет | `52428800` (50 МиБ) | Самый большой пакет, который принимает Hostpanel. От 1 до 104857600 (100 МиБ). |

Для `Timeout` и `MaxDownloadBytes` переменной `.env` нет. Задайте их как записи окружения службы API в переопределяющем файле compose, так же как настройки нумерации заказов в [справочнике по настройке](/ru/operators/configuration).

Заданный адрес должен быть корректным, даже если реестр выключен, а включённый реестр без адреса останавливает API при запуске. Сообщение при запуске называет неверную настройку.

Что означает адрес и что реестр должен отвечать по нему, описано в разделе [Контракт чтения реестра плагинов](/ru/developers/plugin-registry-contract).

## Что отправляет Hostpanel {#what-hostpanel-sends}

Hostpanel обращается только к адресу, который вы настроили:

- Вкладка «Каталог» запрашивает каталог с вашим поисковым текстом, категорией и страницей.
- Страница с описанием запрашивает страницу плагина и список его версий.
- Установка запрашивает выбранный вами выпуск, сверяет его со списком версий и затем загружает его пакет.
- Проверка обновлений отправляет идентификаторы плагинов, которые вы установили или загрузили (но не встроенных), и запрашивает их самые новые версии.
- Установка сначала читает страницу плагина, где сказано, публичный плагин или ограниченный. Для ограниченного плагина установка также регистрируется в реестре, как описано в разделе [Ограниченные плагины и регистрация этого сервера](#restricted-plugins-and-the-registration-of-this-server).

Для платного или приватного плагина также отправляется сохранённый для него лицензионный ключ в заголовке `X-Licence-Key`, и только на собственный адрес реестра: при запросе страницы плагина, списка версий, поиска выпуска, загрузки пакета и проверки обновлений для этого плагина. В список каталога ключ никогда не попадает. Не отправляются ни cookie, ни токен входа, ни имя хоста, ни настройки, ни данные клиентов или пользователей. Если вы не хотите, чтобы идентификаторы плагинов покидали ваш сервер, оставьте реестр выключенным.

Запрос, перенаправление и адрес пакета должны иметь схему, хост и порт реестра, а пакет, расположенный где-либо ещё, отклоняется. Имя реестра также не должно разрешаться в сам сервер: адреса loopback, link-local (включая адрес метаданных облака), неопределённые и multicast отклоняются. Диапазоны частных сетей разрешены, так что реестр внутри вашей сети работает, а реестр на `localhost` нет.

## Ограниченные плагины и регистрация этого сервера {#restricted-plugins-and-the-registration-of-this-server}

Некоторые плагины в реестре не предлагаются всем желающим. Реестр отдаёт их список версий, сведения о выпуске и пакет только проверенной им установке, а на сайте реестра скачать их нельзя. Реестр помечает такой плагин как **ограниченный** (`distribution: HostOnly`). Публичный плагин работает ровно так, как описано выше, и ничего из этого ему не нужно.

### Что делает регистрация {#what-the-registration-does}

Когда реестр включён, Hostpanel создаёт себе идентичность по отношению к реестру. Делать ничего не нужно:

1. **Пара ключей.** Hostpanel один раз генерирует пару ключей Ed25519. Закрытый ключ хранится в зашифрованном виде в таблице настроек с той же защитой, что и другие секреты сервера, никогда не показывается и не отправляется. Если реестр просит начать заново (см. ниже), создаётся новая пара, потому что реестр не регистрирует один ключ дважды.
2. **Регистрация.** Hostpanel отправляет реестру две вещи: открытый ключ и публичный адрес этой установки, то есть настройку `ClientBaseUrl` API (см. [справочник по настройке](/ru/operators/configuration)). Реестр отвечает идентификатором экземпляра и вызовом (challenge), случайным текстом.
3. **Подтверждение.** Реестр запрашивает `/.well-known/hostpanel-registry/{id}` по этому публичному адресу, а Hostpanel отвечает ровно этим вызовом, обычным текстом, который нельзя кешировать. Когда текст совпадает, реестр помечает установку как подтверждённую. Это доказывает, что зарегистрировавший управляет адресом; реестру это не сообщает, кто вы.
4. **Подписанные запросы.** С этого момента каждый запрос ограниченного плагина подписывается закрытым ключом: список версий, сведения о выпуске, запрос одноразового билета на загрузку и сама загрузка пакета. Подпись охватывает метод, точную цель запроса, метку времени и случайное значение, используемое один раз, поэтому запрос нельзя изменить или воспроизвести. Сам пакет загружается по билету, который действует один раз, около минуты, для этой установки и этой версии.

Регистрация выполняется сама: фоновое задание запускает её при старте и снова при каждом запросе ограниченного плагина. Её безопасно повторять. После сбоя она ждёт 30 секунд, затем 1 минуту, 2 минуты и так далее, до одного часа, прежде чем попробовать снова. Состояние регистрации показано на вкладке **Каталог** в карточке **Регистрация в реестре**: ещё не зарегистрирован, ожидает подтверждения, подтверждён, отозван или ошибка с причиной на вашем языке. Кнопка **Повторить регистрацию** запускает её немедленно, не дожидаясь паузы; после отзыва она запрашивает новую идентичность.

### Что отправляется, а что нет {#what-is-sent-and-what-is-not}

| Обращение | Что отправляется |
|---|---|
| Регистрация | Открытый ключ и публичный адрес этой установки. |
| Подтверждение | Ничего, кроме идентификатора экземпляра в адресе. Реестр читает вызов с вашего сервера. |
| Список версий, сведения о выпуске, билет и пакет ограниченного плагина | Идентификатор экземпляра, время, случайное значение и подпись в заголовках `X-Hostpanel-Instance`, `X-Hostpanel-Timestamp`, `X-Hostpanel-Nonce` и `X-Hostpanel-Signature`. Лицензионного ключа нет. |

Hostpanel никогда не отправляет закрытый ключ, пароль, cookie, токен входа, настройку, клиента или пользователя, а также имя хоста сервера, кроме настроенного вами публичного адреса. Реестр узнаёт настроенный вами публичный адрес и время каждого запроса ограниченного плагина; это и есть вся идентичность. Если вы этого не хотите, оставьте реестр выключенным или не устанавливайте ограниченные плагины: регистрация при запуске выполняется, только пока реестр включён.

### Что нужно настроить {#what-you-need-to-set-up}

- **Публичный https-адрес.** `ClientBaseUrl` должен быть публичным https-адресом установки, а не `localhost`, адресом частной сети или именем без точки. Иначе регистрация завершится ошибкой `PLUGIN_REGISTRY_INSTANCE_ADDRESS_INVALID`, и карточка назовёт настройку.
- **Путь well-known должен доходить до API.** Реестр обращается к `https://your-address/.well-known/hostpanel-registry/{id}`. Пограничный прокси перед Hostpanel должен направлять этот путь на API так же, как `/api/`. Caddyfile стека Docker Hub (`docker/caddy/Caddyfile`) это делает; с другим прокси добавьте маршрут для префикса `/.well-known/hostpanel-registry/` на службу API. Без этого регистрация завершается ошибкой `PLUGIN_REGISTRY_INSTANCE_CHALLENGE_UNREACHABLE`.
- **Правильные часы.** Подписанный запрос принимается в пределах нескольких минут от времени реестра. Если часы сервера сбиты, реестр отклоняет запрос, а Hostpanel сообщает, что нужно исправить часы сервера; включите на хосте синхронизацию времени (NTP).

### Отзыв {#revocation}

Если оператор реестра отзывает вашу установку, подписанные запросы отклоняются, карточка показывает **Отозван**, а автоматическое задание её не трогает. Свяжитесь с оператором реестра. После этого **Повторить регистрацию** запрашивает новую идентичность.

## Доверие к реестру {#registry-trust}

Чьи плагины разрешено устанавливать, определяет настройка `plugins.registry_trust`. Меняйте её в карточке «Доверие к каталогу» в верхней части вкладки «Каталог». Изменение сразу действует на следующую установку и записывается в журнал действий.

| Значение | Что разрешает |
|---|---|
| `VerifiedOnly` (по умолчанию) | Только плагины, которые реестр помечает как проверенные. Неизвестное сохранённое значение читается как это. |
| `AnyRegistryPublisher` | Любого издателя, которого перечисляет реестр, проверенного или нет. При выборе этого значения панель показывает предупреждение. |
| `OwnKeysOnly` | Только пакет, ключ подписи которого входит в ваши собственные ключи из `PluginSigning__OperatorKeys`. Ключ, поставляемый с Hostpanel, не считается. |

Уровень доверия служит лишь первой проверкой. Каждая установка из реестра, что бы вы ни выбрали, также должна пройти следующие:

1. **Контрольная сумма.** Хеш пакета должен совпадать с SHA-256, опубликованным реестром для этого выпуска. Иначе пакет отклоняется с `PLUGIN_REGISTRY_CHECKSUM_MISMATCH`.
2. **Идентичность.** В `plugin.json` внутри пакета должны быть указаны идентификатор плагина и версия, которые вы запросили. Пакет другого плагина или другой версии отклоняется с `PLUGIN_REGISTRY_PACKAGE_REFUSED`.
3. **Подпись.** `plugin.sig` должен быть действителен для ключа, которому доверяет Hostpanel: поставляемого с ним или одного из ваших `PluginSigning__OperatorKeys`.

Реестр представляет собой каталог, а не корень доверия. Скомпрометированный реестр может предложить пакет, но не может заставить Hostpanel установить тот, который не подписан доверенным ключом.

### Пакеты без подписи из реестра не устанавливаются никогда {#unsigned-packages-are-never-installed-from-a-registry}

Настройка `plugins.allow_unsigned` позволяет рабочему серверу принимать пакет, загруженный вручную, без действительной подписи. К установке из реестра она никогда не применяется. Пакет из реестра должен нести действительную подпись в любом окружении, включая разработку и тестирование, независимо от того, включён `allow_unsigned` или выключен.

Чтобы доверять издателю, ключ которого не поставляется с Hostpanel, сначала добавьте этот ключ в `PluginSigning__OperatorKeys` (переменные compose называются `PLUGIN_OPERATOR_KEY_ID` и `PLUGIN_OPERATOR_PUBLIC_KEY`, см. [справочник по настройке](/ru/operators/configuration)).

## Ограничения загрузки {#download-limits}

- Пакет потоком записывается во временный файл в каталоге подготовки плагинов и никогда не держится в памяти. Файл удаляется по окончании установки при любом результате.
- Пакет больше `MaxDownloadBytes` отклоняется, как только заявленная длина или прочитанные байты превышают предел, с `PLUGIN_REGISTRY_PACKAGE_REFUSED`.
- JSON-ответ реестра (список или выпуск) ограничен 1 МиБ.
- Перенаправление выполняется только для запроса GET, не более трёх переходов и только внутри собственного источника реестра.
- Всё обращение, включая загрузку, должно уложиться в `PluginRegistry__Timeout`.

После этих ограничений пакет проходит те же проверки, что и загруженный вручную: правила манифеста, ограничения архива, версия SDK и, если вы не подтвердили понижение версии (см. ниже), отсутствие понижения.

## Просмотр и установка {#browse-and-install}

Когда реестр включён, на странице «Плагины» три вкладки: «Установленные», «Каталог» и «Настройки». «Установленные» показывает ваши плагины карточками, на ней есть кнопка **Загрузить плагин**, поиск и фильтры. «Каталог» показывает каталог теми же карточками.

1. Откройте **Плагины** и выберите **Каталог**.
2. Ищите по названию или выберите категорию (Платежи, Провижининг, Регистратор, Приложение или Другое). Список разбит на страницы.
3. На каждой карточке показаны название, издатель, самая новая версия, версия SDK, под которую собран плагин, его цена (Бесплатный, Платный или Приватный) и значок «Проверен», если реестр помечает плагин как проверенный.
4. Нажмите **Установить**, чтобы поставить самую новую версию, или откройте карточку, чтобы перейти на страницу с описанием (ниже) и выбрать другую версию.
5. Перезапустите сервер, когда баннер это предложит. Новый плагин загружается при следующем запуске.

Плагин, который у вас уже есть, показывается как установленный с его версией. Если у реестра есть более новая версия, кнопка называется **Обновить до** этой версии. Обновление подготавливается так же, как загруженное обновление: оно применяется при следующем перезапуске. На вкладке «Установленные» у плагина с более новой версией в реестре виден значок обновления.

Запись каталога, у которой нет подходящей версии, из списка исключается, а остальная часть страницы показывается. Запись, которая вообще не является плагином (неверный идентификатор, нет названия, неизвестная цена), по-прежнему приводит к сбою всей страницы с `PLUGIN_REGISTRY_RESPONSE_INVALID`.

### Страница с описанием {#the-details-page}

Карточка открывает собственную страницу плагина (то же делают кнопка с шестерёнкой и название на карточке). Её вкладки: «Обзор», «Настройки», «Версии», «Лицензия» и «Изменения», причём последние три есть только у плагинов из реестра. Там же находятся действия **Обновить** и **Удалить**. На странице показаны:

- Название, издатель, цена, значок «Проверен», установленная версия, подготовленная версия, ожидающая перезапуска, и доступное обновление.
- Ссылки, которые указал издатель: документация, поддержка, репозиторий исходного кода, где купить лицензию, и лицензия плагина.
- Список **Версии**. В каждой строке показаны версия, статус (опубликована, устарела или отозвана), дата, версии хоста, на которых она работает (и входит ли в них этот сервер), заметки о выпуске и запрашиваемые разрешения. Отозванную версию установить нельзя, как и версию, которая не работает на этом сервере.
- **Удалить** для плагина, который вы установили или загрузили. Сначала запрашивается подтверждение, затем удаляются файлы плагина, а завершается удаление после перезапуска. Данные, сохранённые плагином, остаются, пока вы их не удалите. Встроенный плагин удалить нельзя.

В каждой строке версии одно действие: **Установить** для плагина, которого у вас нет, **Обновить** для версии новее установленной, **Откатить** для более старой и ничего для той, что установлена. Панель просит подтвердить каждую установку.

**Понижение версии разрешено, но только после явного подтверждения**, в котором предупреждается, что в более старой версии могут отсутствовать исправления и она может не прочитать данные, записанные более новой. Без подтверждения запрос отклоняется с `PLUGIN_DOWNGRADE_REFUSED`. Скрипту, который вызывает `POST /api/admin/plugins/registry/{id}/install`, для того же эффекта нужно передать `"allowDowngrade": true`. Понижение подготавливается к следующему перезапуску так же, как обновление, и записывается в журнал действий как принудительное понижение.

### Список изменений и обновления {#release-notes-and-updates}

Список изменений говорит, что меняет версия, ещё до установки. Это Markdown, который пишет издатель, и показывается он как оформленный текст.

- **Вкладка «Каталог».** У карточки с версией есть ссылка **Что нового в**, которая раскрывает список изменений самой новой версии. Для плагина, который у вас уже есть, при наличии более новой версии ссылка **Что изменилось** открывает страницу с описанием, где обновление объяснено.
- **Вкладка «Установленные».** У каждого плагина есть ссылка **Что нового в** для установленной версии. У плагина с обновлением есть также **Что нового в** для новой версии и **Что изменится в**, открывающая страницу с описанием.
- **Страница с описанием.** Строки списка **Версии** открывают свой список изменений, а у плагина с обновлением над ними показан блок **Что изменится с 1.0.0 до 1.2.0**.
- **Обновление.** **Обновить** не запускается сразу. Диалог подтверждения «Обновить плагин?» показывает **Что изменится с 1.0.0 до 1.2.0** и список изменений каждой версии после установленной вплоть до выбранной, от новой к старой, поэтому даже обновление с пропуском версий показывает все. Если у промежуточной версии нет списка изменений, вместо пропуска показывается «У этой версии нет списка изменений.» Нажмите **Обновить** в диалоге, чтобы подготовить версию, или отмените, и ничего не изменится. Обновление применяется при следующем перезапуске, как и раньше.

### Лицензионные ключи {#licence-keys}

Платному или приватному плагину нужен лицензионный ключ от его издателя. Карточка «Лицензионный ключ» на странице с описанием показывает, сохранён ли ключ, и позволяет сохранить новый (он заменяет старый) или удалить его. Ключ состоит не более чем из 256 печатных символов, без пробелов. Ключ только записывается: он хранится на вашем сервере в зашифрованном виде и больше не показывается, ни одна конечная точка его не возвращает, а в журналах и журнале действий его нет. Сохраните ключ до установки. Без него реестр отвечает, что нужна лицензия, а с неверным отвечает, что он недействителен (`PLUGIN_REGISTRY_LICENCE_REQUIRED` и `PLUGIN_REGISTRY_LICENCE_INVALID` ниже).

### Конечные точки {#endpoints}

Для скриптов. Всем им нужен администратор, и все они находятся под `/api/admin/plugins`:

| Метод и путь | Что делает |
|---|---|
| `GET /registry` | Каталог с разбиением на страницы (вкладка «Каталог»). |
| `GET /registry/updates` | Самая новая версия в реестре для каждого установленного вами плагина. |
| `GET /registry-instance` | Положение этого сервера в реестре: `state` (`NotRegistered`, `Pending`, `Verified`, `Revoked`, `Error`), идентификатор экземпляра, публичный адрес, код и описание последнего сбоя и срок следующей автоматической попытки. Ничего секретного. |
| `POST /registry-instance/retry` | Немедленно запускает регистрацию, не дожидаясь паузы, и отвечает состоянием, в котором её оставила. Недоступно в демо-установке. |
| `GET /registry/{id}` | Страница с описанием одного плагина с его версиями. Лицензионный ключ не возвращается никогда, только признак, сохранён ли он. |
| `PUT /registry/{id}/licence` | Сохраняет лицензионный ключ плагина. Тело: `{ "key": "YOUR-KEY" }`. |
| `DELETE /registry/{id}/licence` | Удаляет сохранённый ключ. |
| `POST /registry/{id}/install` | Устанавливает или подготавливает одну версию. Тело: `{ "version": "1.2.0", "allowDowngrade": false }`. |
| `DELETE /{id}` | Удаляет установленный или загруженный плагин. |

Для установки нужен администратор, в демо-установке она недоступна. Каждая установка и каждый отказ, происходящий до установки, записываются в журнал действий с идентификатором и версией плагина, а также с SHA-256, если пакет был загружен.

## Ошибки {#errors}

| Код | Статус | Когда |
|---|---|---|
| `PLUGIN_REGISTRY_DISABLED` | 409 | Реестр выключен или у него нет адреса. |
| `PLUGIN_REGISTRY_UNAVAILABLE` | 502 | Реестр недоступен, ответил статусом ошибки или ответил 404 на что-либо, кроме поиска выпуска. |
| `PLUGIN_REGISTRY_TIMED_OUT` | 504 | Обращение заняло больше `PluginRegistry__Timeout`. |
| `PLUGIN_REGISTRY_RESPONSE_INVALID` | 502 | Ответ не соответствует тому, что должен присылать реестр: неверный JSON, неверный идентификатор плагина, версия, цена или контрольная сумма либо выпуск не того, что запрашивали. Одна запись, не являющаяся плагином (неверный идентификатор, нет названия, неизвестная цена), приводит к сбою всей страницы; запись без подходящей версии просто пропускается. |
| `PLUGIN_REGISTRY_PLUGIN_NOT_FOUND` | 404 | В реестре нет такой версии этого плагина. |
| `PLUGIN_REGISTRY_PACKAGE_REFUSED` | 502 | Адрес пакета или перенаправление выходят за источник реестра, пакет превышает предел размера либо это другой плагин или другая версия, чем запрошено. |
| `PLUGIN_REGISTRY_CHECKSUM_MISMATCH` | 502 | Загруженный пакет не совпадает с опубликованным SHA-256. |
| `PLUGIN_REGISTRY_NOT_TRUSTED` | 403 | Настройка доверия к реестру не разрешает этот плагин: он не проверен при `VerifiedOnly` или его ключ подписи не входит в ваши при `OwnKeysOnly`. |
| `PLUGIN_REGISTRY_LICENCE_REQUIRED` | 422 | Плагин платный или приватный, и реестр ответил, что нужен лицензионный ключ, потому что для него ничего не сохранено. Сохраните ключ на странице с описанием. |
| `PLUGIN_REGISTRY_LICENCE_INVALID` | 422 | Реестр отклонил сохранённый лицензионный ключ. Замените его действительным. |
| `PLUGIN_REGISTRY_HOST_INCOMPATIBLE` | 409 | Версия не работает на этой версии Hostpanel, потому что выходит за диапазон хоста, объявленный издателем. Выберите другую версию или обновите Hostpanel. |
| `PLUGIN_REGISTRY_VERSION_YANKED` | 409 | Издатель отозвал эту версию, поэтому её нельзя установить. |
| `PLUGIN_REGISTRY_VERSION_COMPROMISED` | 409 | Реестр отверг эту версию, например потому что она оказалась небезопасной. Она не устанавливается никогда. |
| `PLUGIN_DOWNGRADE_REFUSED` | 409 | Версия старше установленной, а понижение не подтверждено (`allowDowngrade`). |
| `PLUGIN_REGISTRY_INSTANCE_ADDRESS_INVALID` | 422 | `ClientBaseUrl` не является публичным https-адресом, пригодным для реестра. Задайте его и повторите регистрацию. |
| `PLUGIN_REGISTRY_INSTANCE_NOT_VERIFIED` | 409 | Реестр ещё не подтвердил этот сервер, поэтому ограниченный плагин не выдаётся. Регистрация выполняется сама; проверьте карточку на вкладке «Каталог». |
| `PLUGIN_REGISTRY_INSTANCE_REVOKED` | 409 | Реестр отозвал эту установку. Свяжитесь с оператором реестра, затем повторите регистрацию. |
| `PLUGIN_REGISTRY_INSTANCE_CHALLENGE_UNREACHABLE` | 502 | Реестр не смог прочитать подтверждающий текст по адресу `/.well-known/hostpanel-registry/{id}` на вашем публичном адресе. Направьте этот путь на API. |
| `PLUGIN_REGISTRY_INSTANCE_SIGNATURE_REJECTED` | 502 | Реестр не принял подпись. Повторите регистрацию; если это повторяется, сохранённая идентичность, возможно, повреждена. |
| `PLUGIN_REGISTRY_INSTANCE_CLOCK_SKEW` | 502 | Часы этого сервера слишком сильно расходятся с точным временем. Исправьте часы сервера и повторите. |
| `PLUGIN_REGISTRY_INSTANCE_REPLAY_REJECTED` | 502 | Реестр принял запрос за повтор предыдущего. Повторите попытку. |
| `PLUGIN_REGISTRY_DOWNLOAD_TICKET_REFUSED` | 502 | Реестр не принял одноразовый билет на загрузку. Повторите установку. |
| `PLUGIN_REGISTRY_INSTANCE_LIMIT_REACHED` | 429 | Реестр ограничивает, как часто этот сервер может регистрироваться или запрашивать ограниченные плагины. Подождите и повторите. |

Hostpanel никогда не показывает вам собственный текст ошибки реестра, а в журнале остаётся только вид сбоя, поэтому ни адрес, ни ответ не могут попасть ни туда, ни туда.

Установка также может завершиться любым отказом, возможным при обычной загрузке плагина, например `PLUGIN_SIGNATURE_KEY_UNKNOWN`, `PLUGIN_SIGNATURE_INVALID`, ошибкой манифеста или `PLUGIN_ARCHIVE_TOO_LARGE`. Это значит, что сам пакет неприемлем, и ничего не было установлено.
