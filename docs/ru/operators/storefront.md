# Шаблоны витрины и брендинг {#storefront-templates-and-branding}

Как публичный клиентский портал выбирает оформление, как добавить новое и какие настройки задают его бренд.

Публичный портал поставляется с тремя вариантами оформления и показывает выбранный.
У всех одинаковая SEO-разметка: canonical, hreflang и schema.org находятся в
`client/pages/` и никогда не в шаблоне.

Задайте собственный адрес сайта, иначе карта сайта будет указывать тот хост, с которого
пришёл очередной запрос. За прокси это может быть внутренний адрес контейнера.
Эту задачу решает `NUXT_PUBLIC_BASE_URL` на этапе сборки; готовый образ при запуске
читает `NUXT_SITE_URL`, и это значение переопределяет встроенное.

| Шаблон | Описание |
|---|---|
| `aurora` | По умолчанию. Тёмная и светлая темы, армянская типографика, живой поиск доменов |
| `nova` | Посадочная страница хостинга, нацеленная на конверсию: цены, сравнение тарифов, безопасность, миграция, FAQ |
| `classic` | Исходное оформление витрины |

`nova` приносит собственные шапку, подвал, главную страницу и страницу хостинга, а поиск
доменов и оформление заказа берёт у aurora: оформление заказа и есть путь к покупке,
а его вторая копия стала бы вторым местом, где может жить ошибка в платеже. Его
дизайн-токены имеют префикс `--n-*` и объявлены только внутри `.tpl-nova` и
`html[data-template='nova']`, поэтому включение этого шаблона не затрагивает два других.

Ряд его карточек утверждает то, что эта кодовая база проверить не может: хранилище NVMe,
CDN, серверное кеширование, межсетевой экран, сканер вредоносного ПО, расписание
резервного копирования, показатель доступности, бесплатную миграцию. Каждая зависит
от настройки и скрыта, пока оператор её не включит:

| Настройка | Что показывает |
|---|---|
| `portal.features.storage` | карточку хранилища SSD/NVMe |
| `portal.features.caching` | карточку серверного кеширования |
| `portal.features.cdn` | карточку CDN |
| `portal.features.firewall` | карточку межсетевого экрана |
| `portal.features.malware` | карточку защиты от вредоносного ПО |
| `portal.features.backups` | карточки резервного копирования в главном блоке, полосе доверия и сетке безопасности |
| `portal.trust.uptime` | показатель доступности в полосе доверия, дословно |
| `portal.migration.free` | значок «бесплатная миграция», если задано `true` |

Любое непустое значение включает первые шесть; в настройке доступности хранится сам
показатель. Таблица сравнения и раздел отзывов тоже строятся по данным: таблица
показывает только строки характеристик, введённые в **Admin → Products → Specification**,
а раздел отзывов не выводится вовсе, потому что отзывы клиентов пока негде брать.

**Как выбирается шаблон.** В порядке приоритета:

1. Настройка `portal.template`, которую можно менять в **Admin → Settings → Portal appearance**
2. Переменная окружения `NUXT_PUBLIC_PORTAL_TEMPLATE`
3. `classic` (`DEFAULT_TEMPLATE` в `client/templates/types.ts`)

Неизвестное значение приводит к `classic`, а не к пустому сайту, поэтому опечатка
в поле админки не может положить витрину.

**Как добавить шаблон.** Создайте `client/templates/<name>/` с `layout/Header.vue`,
`layout/Footer.vue` и компонентом в `pages/` для каждого маршрута, затем зарегистрируйте
загрузчики в `client/templates/registry.ts` и добавьте имя в `TEMPLATE_NAMES` в
`client/templates/types.ts`. Модульный тест проверяет, что каждый шаблон реализует
каждый слот, поэтому отсутствующая страница ломает сборку, а не выводит пустоту.

Два правила делают шаблоны безопасно заменяемыми:

- **Шаблоны отображают, страницы решают.** Компонент шаблона принимает типизированные
  свойства и возвращает разметку; страница над ним отвечает за загрузку данных, SEO и
  бизнес-логику. Так оба оформления идут по одному пути кода и дают один набор тегов head.
- **Тексты хранятся в i18n** под ключом верхнего уровня с именем шаблона
  (`aurora.hero.title`), зарегистрированным в массиве `modules` файла
  `client/plugins/i18n.ts`. Файлы локалей автоматически не обнаруживаются.

`aurora` везде следует первому правилу, кроме одного исключения: его
`pages/Checkout.vue` по-прежнему содержит процесс оформления заказа, потому что
разделять работающий платёжный путь стоит только тогда, когда под рукой есть бэкенд
для тестового заказа. Это скрипт `classic` байт в байт с переработанной разметкой,
так что они не могут разойтись.

Страницы `classic` перенесены из исходных компонентов маршрутов как есть и сохраняют
собственную загрузку данных. В этом и был смысл: перенести страницу в 500 строк без
изменений гораздо безопаснее, чем переписывать её, а оформление, которое она выводит,
как раз и заменяется. Новым шаблонам следует брать пример с `aurora`, а не с `classic`.

## Брендинг и цветовая схема {#branding-and-colour-mode}

**Брендинг и цветовая схема** настраиваются в **Admin → Settings**; для первого запуска
есть запасной вариант через переменные окружения `NUXT_PUBLIC_PORTAL_*` (после того как
значение задано в админке, оно имеет приоритет):

| Настройка | Запасная переменная окружения | Что делает |
|---|---|---|
| `portal.site.name` | `NUXT_PUBLIC_PORTAL_SITE_NAME` | Название сайта для `og:site_name`, alt-текста логотипа и структурированных данных. Если пусто, используется встроенное название. |
| `portal.site.tagline` | `NUXT_PUBLIC_PORTAL_SITE_TAGLINE` | Meta description по умолчанию. |
| `portal.theme.default` | `NUXT_PUBLIC_PORTAL_THEME_DEFAULT` | `light`, `dark` или `system` для посетителя без сохранённого выбора. Выбор посетителя хранится в cookie `color-mode` и применяется на сервере, поэтому вспышки неверной темы нет. |
| `portal.theme.user_toggle` | `NUXT_PUBLIC_PORTAL_THEME_USER_TOGGLE` | `false` скрывает переключатель светлой и тёмной темы. |
| `portal.logo` | `NUXT_PUBLIC_PORTAL_LOGO` | Логотип для светлых фонов. |
| `portal.logo.dark` | `NUXT_PUBLIC_PORTAL_LOGO_DARK` | Логотип для тёмных фонов; если не задан, берётся светлый. |
| `portal.logo.mark` | `NUXT_PUBLIC_PORTAL_LOGO_MARK` | Квадратный логотип-значок без надписи для компактных мест. |
| `portal.favicon` | `NUXT_PUBLIC_PORTAL_FAVICON` | Значок во вкладке браузера; загрузка файла создаёт весь набор значков. |
| `portal.brand.primary` | `NUXT_PUBLIC_PORTAL_BRAND_PRIMARY` | Основной цвет бренда в формате `#rrggbb`. Из него выводится вся основная шкала: кнопки, ссылки, акценты, кнопки в письмах. Текст на нём автоматически становится тёмным, если цвет слишком светлый для белого. |
| `portal.brand.accent` | `NUXT_PUBLIC_PORTAL_BRAND_ACCENT` | Акцентный цвет в формате `#rrggbb`: градиенты, значки и второстепенные выделения. |
| `portal.brand.font_heading` | `NUXT_PUBLIC_PORTAL_BRAND_FONT_HEADING` | `inter`, `noto-sans-armenian`, `noto-serif-armenian` или `system`. Шрифты входят в поставку, из сервисов шрифтов ничего не загружается. |
| `portal.brand.font_body` | `NUXT_PUBLIC_PORTAL_BRAND_FONT_BODY` | Тот же список, для основного текста. |

Логотипы и фавиконку можно загрузить в **Admin → Settings → Branding** или указать
ссылками. `portal.template`, `portal.theme.default` и шрифты принимают только значения
из списка, а цвета только `#rrggbb`; всё остальное отклоняется с ошибкой
`INVALID_SETTING_VALUE` и фразой о том, что ожидалось. Если все настройки бренда пусты,
витрина использует собственные цвета и шрифты каждого шаблона, ровно как до появления
этих настроек.

**Аналитика и чат** тоже задаются настройками, по умолчанию они пусты, и пока они не
заданы, ничего не загружается:

| Настройка | Запасная переменная окружения | Что делает |
|---|---|---|
| `portal.analytics.gtm_id` | `NUXT_PUBLIC_PORTAL_GTM_ID` | Контейнер Google Tag Manager (`GTM-…`). Загружается только после того, как посетитель принял все cookie в баннере. |
| `portal.chat.provider` | `NUXT_PUBLIC_PORTAL_CHAT_PROVIDER` | `chatwoot`, `innochat` или пусто, если виджет не нужен. |
| `portal.chat.base_url` | `NUXT_PUBLIC_PORTAL_CHAT_BASE_URL` | Сервер чата, только `https://`. |
| `portal.chat.website_token` | `NUXT_PUBLIC_PORTAL_CHAT_WEBSITE_TOKEN` | Токен сайта из почтового ящика чата. Варианты `.ru` / `.hy` переопределяют его для отдельного языка. |

**Письма следуют бренду.** Каждый шаблон, который формирует API, может использовать
<span v-pre>`{{ site.name }}`, `{{ brand.primary }}`, `{{ brand.primary_dark }}`,
`{{ brand.on_primary }}`, `{{ brand.accent }}` и `{{ brand.logo_url }}`</span> (логотип для
тёмного фона в виде абсолютного URL, пусто, если он не загружен). Шаблон сброса пароля,
который поставляется со свежей установкой, использует их; установка, в которой эта
запись уже есть, хранит прежний HTML, пока её не сохранят заново в
**Admin → Settings → Email Templates**.

Связанные настройки оператора, все необязательные и скрытые, если пусты:
`portal.contact.whatsapp`, `portal.contact.telegram`, `portal.contact.email`,
`portal.contact.phone`, `portal.contact.address`, `portal.contact.map_url` (только https),
`portal.stats.clients`, `portal.stats.uptime`, `portal.stats.regions`, `portal.hero.badge`,
`portal.chat.provider`, `portal.newsletter.action_url`,
`portal.legal.tax_id`, `portal.social.{facebook,instagram,twitter,linkedin,youtube}`, а также
часы работы поддержки `portal.contact.hours` и их часовой пояс `portal.contact.timezone`.

Электронная почта, телефон, адрес, карта, часы и часовой пояс редактируются в **Admin → Settings → Storefront**;
электронная почта и адрес карты проверяются при сохранении. Адрес и часы можно также
задать для каждого языка вариантами `.ru` и `.hy` (`portal.contact.address.ru`, `portal.contact.hours.hy` и так далее);
если для языка своего значения нет, показывается значение по умолчанию.

Шаблон nova заявляет об оборудовании или коммерческом преимуществе только тогда, когда
оператор это включил (`true`; пустое значение или `false` скрывает):
`portal.features.{backups,storage,caching,cdn,firewall,malware}` и `portal.migration.free`.
Строка о доступности в его полосе доверия выводит `portal.stats.uptime`.

Панель запуска приложений в шапке выключена, пока `portal.apps.enabled` не равно `true`,
потому что приложения, на которые она ссылается, существуют только в развёртывании,
где они запущены. После включения каждому пункту нужен собственный URL:
`portal.apps.{account,tasks,erp,hostpanel,sheets,mail,docs,calendar}` или соответствующая
переменная `NUXT_PUBLIC_*`; пункты без URL опускаются.

Каждая предустановленная настройка редактируется в **Admin → Settings**; таблица
принимает по одной строке за раз.

Таблица сравнения на странице тарифов строится из строк характеристик каждого продукта,
которые редактируются в **Admin → Products → Specification**. Тарифы выстраиваются
по названию характеристики, поэтому одна и та же строка должна быть написана одинаково
у всех продуктов; если у тарифа такой строки нет, он показывает прочерк, а столбец не
сдвигается. Если ни у одного продукта нет характеристик, таблица не выводится вовсе.
