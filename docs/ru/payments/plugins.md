# Менеджер плагинов {#plugin-manager}

## Подписанные пакеты плагинов {#signed-plugin-packages}

Плагин выполняется внутри сервера, поэтому серверу нужно знать, кто создал пакет, прежде чем его запускать. Пакет плагина
(ZIP-архив, который вы загружаете на странице «Плагины») подписан отсоединённой подписью Ed25519, которая хранится в файле `plugin.sig`
в корне пакета.

### Что делает сервер {#what-the-server-does}

| Плагин | Рабочая среда | Разработка |
|---|---|---|
| Поставляется в образе сервера | загружается, не проверяется | загружается |
| Загружен, подписан доверенным ключом | устанавливается и загружается | устанавливается и загружается |
| Загружен, без подписи, изменён после подписания или подписан неизвестным ключом | отклоняется | устанавливается и загружается |

Проверка выполняется при загрузке пакета и ещё раз при каждом запуске сервера, поэтому пакет, изменённый на диске
позже, пропускается при следующем запуске. Пропускается только этот плагин; в журнале указаны плагин и причина.
Плагины, которые поставляются в образе, являются частью самого сервера, поэтому собственной подписи у них нет.

Все среды, кроме Development и Testing, считаются рабочими.

### Разрешение плагинов без подписи {#allowing-unsigned-plugins}

Откройте **Плагины** в панели администратора и включите **Разрешить плагины без подписи**. По умолчанию переключатель выключен,
а каждое его изменение записывается в журнал действий. Когда он включён, рабочий сервер устанавливает и загружает пакеты, не прошедшие
проверку подписи, поэтому включайте его, только если доверяете каждому загружаемому пакету. Изменение переключателя
сразу применяется к следующей загрузке, а к уже установленным плагинам, после следующего перезапуска.

### Доверенные ключи {#trusted-keys}

Сервер доверяет открытым ключам, перечисленным в двух местах. Ключи разработчиков поставляются вместе с сервером в разделе
`PluginSigning:MaintainerKeys` (идентификатор ключа `official-innovayse-2026`, которым подписаны плагины Innovayse). Свои ключи вы добавляете в
`PluginSigning:OperatorKeys`, например через переменные окружения:

```text
PluginSigning__OperatorKeys__0__KeyId=my-company-2026
PluginSigning__OperatorKeys__0__PublicKey=<base64 of the 32-byte public key>
```

Идентификатор ключа состоит из 1-64 символов `a-z`, `0-9`, `.`, `-` и `_`. Здесь указываются только открытые ключи. Сервер отказывается
запускаться, если ключ непригоден.

### Подпись пакета {#signing-a-package}

Формат описан в файле `rules/project.md` репозитория. Для подписи используйте инструмент подписи из копии
репозитория. Храните закрытый ключ вне любых репозиториев: инструмент отказывается работать с файлом ключа внутри рабочей копии git.

```bash
# once: create a key pair; this prints the public key for PluginSigning__OperatorKeys
dotnet run --project backend/tools/Innovayse.Hostpanel.PluginSigner -- keygen /secure/place/plugin-signing.key

# every release: sign the folder that will be zipped, then zip it as it is
dotnet run --project backend/tools/Innovayse.Hostpanel.PluginSigner -- sign ./my-plugin /secure/place/plugin-signing.key my-company-2026
```

Подписывайте после последнего изменения: если после подписи добавить, удалить или изменить любой файл, подпись станет недействительной. Пакет,
содержащий символическую ссылку или точку соединения (junction), подписать нельзя; поставляйте настоящие файлы.

Известное ограничение: подпись не защищает от понижения версии. Она показывает, что файлы получены от доверенного ключа
и не изменены, но не что это последний выпуск, поэтому более старую подписанную версию можно установить снова. Устанавливайте только
выбранные вами выпуски, а если всё, что подписано ключом, больше не должно считаться доверенным, удалите этот ключ из `PluginSigning`.

## Отклонённые плагины в списке {#refused-plugins-in-the-list}

Установленный плагин, нарушающий правило манифеста, пропускается при запуске сервера. В журнал попадает одно предупреждение,
в котором указаны плагин и правило, и плагин не запускается.

В списке плагинов на странице «Плагины» такой плагин показан как запись **Отклонён**. В ней указаны имя папки плагина
(в роли идентификатора), нарушенное правило и краткое пояснение, что не так; такой плагин никогда не отображается как включённый или загруженный. Таким образом
перечисляются только нарушения правил манифеста; пакет, который не прошёл по другой причине (например, проверку подписи), отражается
лишь строкой в журнале.

У каждой строки списка один из трёх статусов:

| Статус | Значение |
|---|---|
| Загружен | Пакет установлен и не отклонён; в строке указано, загружен ли плагин. Если более новая версия ждёт перезапуска, в строке показана и эта подготовленная версия. |
| Отклонён | Пакет установлен, но нарушил правило манифеста при запуске. В строке показаны правило и пояснение. |
| Удалён | Пакета больше нет, но плагин всё ещё хранит данные. В строке указан только идентификатор плагина; здесь можно очистить эти данные (см. ниже). |

Это те же правила, по которым отклоняется загрузка, и текст каждого совпадает с текстом ошибки при загрузке:

| Правило | Что изменить в пакете |
|---|---|
| `ManifestVersionUnknown` | Манифест объявляет версию манифеста, которую этот сервер не знает. |
| `SdkAssemblyOutdated` | Плагин собран с более старой версией SDK. Пересоберите его с текущей. |
| `PermissionUnknown` | Такого разрешения не существует. Используйте имя клиентского разрешения или `Any`. |
| `AdminPermissionDeclared` | Разрешение задано для маршрута, страницы или слота администратора. В административной части разрешений не бывает. |
| `RoutePathInvalid` | Путь маршрута недопустим. Используйте сегменты из строчных букв и параметры в фигурных скобках. |
| `RouteDuplicate` | Один и тот же маршрут объявлен дважды для одного метода в одной панели. |
| `LabelKeyMissing` | Используется ключ текста, но английские тексты его не определяют. |
| `SlotUnknown` | Содержимое помещено в слот, которого сервер не предоставляет. |
| `SlotContextKeyNotOffered` | Слот запрошен с контекстом, которого он не предоставляет. |
| `AssemblyUnreadable` | Не удалось прочитать файл в плагине. Загрузите его заново. |
| `SlotWidgetIdInvalid` | Идентификатор виджета недопустим. Используйте строчные буквы, цифры, дефисы и подчёркивания. |
| `SlotWidgetDuplicate` | Один и тот же идентификатор виджета объявлен дважды для одного слота. |
| `PluginIdInvalid` | Идентификатор плагина в манифесте недопустим. |
| `VersionInvalid` | Версия плагина не соответствует строгому формату. Запишите её как `major.minor.patch`, например `1.2.3`, без ведущих нулей. Далее могут следовать предварительная версия (`-beta.1`) и метаданные сборки (`+7`). |

Чтобы исправить отклонённый плагин, поправьте пакет и загрузите его снова (см. следующий раздел). Чтобы избавиться от него, удалите его
из списка; отклонённый плагин удаляется так же, как любой другой, по имени папки.

## Загрузка более новой версии {#uploading-a-newer-version}

Загрузка пакета для уже установленного плагина считается обновлением. Пакет проходит те же проверки, что и любая
загрузка (манифест, ссылка на SDK и подпись), после чего он **подготавливается** (staged) вместо замены установленного плагина,
потому что установленный плагин загружен и работает. Папка загруженного плагина никогда не перезаписывается на месте, поэтому это
верно и для той же версии. В ответ на загрузку сообщается, что нужен перезапуск, и называется подготовленная версия, а список
показывает её рядом с плагином. Повторная загрузка до перезапуска заменяет подготовленный пакет. Подготовка попадает в аудит:
«Staged Plugin Upgrade», «Staged Plugin Replacement» (та же версия ещё раз) или «Forced Plugin Downgrade».

**Версии строгие.** Версия записывается как `major.minor.patch` без ведущих нулей, к ней могут добавляться необязательные предварительная версия и
метаданные сборки. Версия `1.0` или `01.0.0` отклоняется при установке с ошибкой `PLUGIN_MANIFEST_VERSION_INVALID` (400), а плагин, в манифесте
которого уже такая версия, отклоняется при запуске и показывается как отклонённый. Метаданные сборки не учитываются: `1.0.0`
и `1.0.0+7`: одна и та же версия.

- **Замена происходит при перезапуске.** При запуске сервер сначала записывает обновление, затем ставит подготовленный пакет
  на место установленного. Если замена не удалась (например, файл заблокирован), остаётся установленная версия, запись
  возвращается в прежнее состояние, в журнал попадает ошибка, а подготовленный пакет сохраняется. Рабочие папки, оставшиеся от предыдущего запуска,
  удаляются при запуске, а версия, отложенная в сторону из-за сбоя, сначала возвращается на место.
- **Хук миграции выполняется после успешной замены.** После замены плагин, у которого есть хук миграции, мигрируется при запуске
  сервера, а в журнале действий появляется строка «Migrated Plugin Data». Запись об обновлении удаляется только
  после этого, а второе обновление поверх ещё не завершённого сохраняет версию «откуда» от первого. Плагин без хука миграции
  просто получает строку в журнале действий. Если пакет тем временем удалён, миграция отбрасывается.
- **Плагин с ожидающей миграцией отключён.** С момента записи обновления и до успешного выполнения хука
  плагин не вызывается и не запускается: его маршруты отвечают так, будто он отключён, платежи и выполнение заказов
  его не используют. Иначе он выполнял бы новый код на данных в старом формате. То же верно, если хук выбросил исключение или выполнялся слишком
  долго.
- **Повтор.** Хук пробуют снова при каждом запуске, а также сразу, как только оператор включает плагин или сохраняет его
  настройки: именно тогда плагин, который был выключен или которому не хватало обязательной настройки, получает возможность его выполнить. Хук должен быть
  идемпотентным, потому что неудачную попытку можно повторить. Если плагин остаётся отключённым, найдите в журнале его идентификатор.
- **У хука есть лимит времени.** `Plugins__MigrationTimeoutSeconds` (по умолчанию 120, от 1 до 3600), наибольшее время, на которое
  разрешено запустить один хук. По его истечении хост отменяет хук, перестаёт ждать, записывает плагин в журнал и держит его отключённым, пока
  одна из следующих попыток не завершится успешно, так что один зависший хук не может заблокировать запуск сервера или других плагинов. Хук, игнорирующий
  токен отмены, может продолжить работу в фоне.
- **Понижение версии отклоняется.** Версия старше той, которую установит перезапуск (подготовленная загрузка, если она есть,
  иначе установленная версия), получает ответ `PLUGIN_DOWNGRADE_REFUSED` (409), и ничего не подготавливается. То же происходит при загрузке,
  если установленную версию не удаётся прочитать как версию, потому что нельзя показать, что новая версия новее. Обе попытки
  попадают в аудит («Refused Plugin Downgrade»). Загрузите пакет ещё раз с параметром принудительной установки (`force=true` в
  `POST /api/admin/plugins/install`), чтобы всё равно подготовить его.
- **Настройки и сохранённые данные сохраняются** при обновлении.
- **Клиенты с сохранёнными картами считаются принадлежащими плагину с идентификатором `stripe`.** Обновление, которое ввело клиентов по шлюзам, копирует ранее сохранённых клиентов с картами в новую таблицу по шлюзам как клиентов плагина с идентификатором `stripe`, потому что только этот шлюз когда-либо их записывал. Если ваш плагин карточного шлюза использует другой идентификатор, установите плагин как `stripe` или перепишите `GatewayModuleId` в `GatewayCustomers` на идентификатор вашего плагина до того, как клиенты начнут платить сохранённой картой; иначе у этих клиентов снова запросят данные карты.
- **Та же версия** незагруженного плагина (например, отклонённого) сразу заменяет установленные файлы, как
  и раньше, но для применения всё равно нужен перезапуск.

Удаление плагина отбрасывает и подготовленное для него обновление. Плагин, поставляемый вместе со сборкой, никогда не заменяется и не удаляется,
даже если сервер его отклонил: его идентификатор остаётся занятым, поэтому загрузка с тем же именем никогда не загрузится вместо него.

## Удаление плагина и очистка его данных {#removing-a-plugin-and-purging-its-data}

Удаление плагина стирает файлы его пакета (и подготовленное для него обновление) и отключает плагин. Оно **не**
удаляет то, что плагин хранил: его настройки и сохранённые данные остаются, так что при повторной установке они будут найдены. Плагин
остаётся загруженным до следующего перезапуска, но отключается сразу и ничего не отвечает. Плагин, поставляемый в образе сервера,
удалить нельзя. Если файлов уже нет, но плагин когда-то был здесь включён, повторное удаление просто
отключает его. Удаление записывается в журнал действий.

Удалённый плагин, который всё ещё хранит данные, появляется в списке как **Удалён**. Чтобы удалить эти данные, используйте очистку в
этой строке, которая вызывает `DELETE /api/admin/plugins/{id}/data`:

- Она отклоняется с кодом `PLUGIN_STILL_INSTALLED` (409), пока на диске существует папка плагина, в образе сервера или
  в папке загрузок, даже если его `plugin.json` повреждён. Сначала удалите плагин, затем очищайте данные.
- Она отвечает `PLUGIN_NOT_FOUND` (404), когда у плагина нет данных; это же получит повторная очистка. Привязки виджетов слотов
  считаются хранимыми данными: удалённый плагин, у которого остались только привязки, отображается как **Удалён**, и его можно очистить.
- Она отключает плагин, ставит удаление в очередь и записывает его в журнал действий. Удаление выполняется в фоне и
  повторяется до успеха, поэтому может завершиться чуть позже ответа. Перезапуск не нужен.
- Она удаляет сохранённые данные плагина, а также привязки виджетов слотов плагина к продуктам (см. следующий раздел), которые были
  записаны до запроса очистки. Данные и привязки, записанные после этого, например переустановленным плагином,
  сохраняются.

<div class="warning custom-block">

Очистку нельзя отменить. Сохранённые данные плагина удаляются безвозвратно, поэтому сначала сделайте резервную копию (см.
[Резервное копирование](/ru/operators/backup)).

</div>

## Привязка виджета слота к продуктам после установки {#binding-a-slot-widget-to-products-after-install}

Плагин может поместить виджет в слот страницы и в манифесте ограничить его некоторыми продуктами через `productIds`. Идентификаторы продуктов
в разных установках различаются, поэтому плагин, нацеленный на ваши продукты, не может знать их при сборке. После
установки вы можете привязать каждый виджет к своим продуктам на странице плагина в панели администратора.

- Заданная там настройка переопределяет манифест. Виджет, для которого там выбраны продукты, показывается только для услуг этих
  продуктов, а `productIds` из манифеста для этого виджета игнорируются.
- Виджет, который никогда не привязывался, сохраняет привязку из манифеста. Если и в манифесте
  она не указана, виджет показывается для каждой услуги.
- Слот без услуги (например, клиентская страница) никогда не показывает виджет, у которого есть привязка.
- Удалённый продукт при показе виджета игнорируется. Если все продукты привязки удалены, виджет остаётся привязанным и
  не показывается нигде. К манифесту он не возвращается, потому что привязка решает, до чего виджет может дотянуться. Очистите привязку
  пустым списком, чтобы вернуть привязку из манифеста.
- При сохранении несуществующие идентификаторы продуктов отбрасываются. Если идентификаторы продуктов отправлены, но ни одного из них не существует, сохранение отклоняется с ответом 400 `PLUGIN_SLOT_PRODUCTS_UNKNOWN`, а привязка остаётся как была. Очистить её может только явный пустой список.
- Два одновременных сохранения одного виджета выполняются по очереди, и последнее заменяет весь набор.

Привязки хранятся в отдельной таблице `PluginSlotProductBindings` и записываются только сохранением оператора. Это
не настройка, и изменить их со страниц настроек или формы интеграции нельзя. Они удаляются при очистке
данных плагина, кроме привязки, сохранённой после запроса очистки: она остаётся.

API администратора: `GET /api/admin/plugins/{pluginId}/slot-widgets` выводит список виджетов загруженного плагина (для любого другого: 404 `PLUGIN_NOT_FOUND`) с полями
`slotId`, `widgetId`, `title`, `manifestProductIds`, `productIds` и `isBound`, а
`PUT /api/admin/plugins/{pluginId}/slot-widgets/{slotId}/{widgetId}` с телом `{ "productIds": [3, 7] }` отвечает
тем же форматом с сохранёнными продуктами. Пустой список очищает привязку. Если два сохранения одного виджета продолжают конфликтовать, ответ: 409. Виджет, которого плагин не объявил в этом слоте, получает ответ 404 `PLUGIN_SLOT_WIDGET_NOT_FOUND`.

## Ошибки плагинов {#plugin-errors}

API возвращает эти коды ошибок в поле `type` тела ответа с ошибкой.

| Код | Статус | Когда |
|------|--------|------|
| `PLUGIN_MANIFEST_INVALID` | 400 | Файл `plugin.json` отсутствует или его не удаётся разобрать. |
| `PLUGIN_MANIFEST_VERSION_UNKNOWN` | 400 | Манифест объявляет версию манифеста, которую этот сервер не знает. |
| `PLUGIN_MANIFEST_VERSION_INVALID` | 400 | Строка версии плагина не соответствует строгому формату (`major.minor.patch`). |
| `PLUGIN_MANIFEST_ID_INVALID` | 400 | Идентификатор плагина в манифесте недопустим. |
| `PLUGIN_ID_INVALID` | 400 | Идентификатор плагина, переданный в вызов удаления или очистки, недопустим. |
| `PLUGIN_SDK_VERSION_UNSUPPORTED` | 400 | Поле манифеста `sdkVersion` не принимается. Допустимое значение: `1.0`. |
| `PLUGIN_SDK_ASSEMBLY_OUTDATED` | 400 | Плагин собран со сборкой SDK более старой основной версии. Пересоберите с текущим SDK. |
| `PLUGIN_ASSEMBLY_UNREADABLE` | 400 | Сборку плагина или другой нужный файл не удаётся прочитать. Загрузите пакет заново. |
| `PLUGIN_HOST_ASSEMBLY_REFUSED` | 400 | Пакет содержит сборку, которую хост уже предоставляет. Удалите её из ZIP-архива. |
| `PLUGIN_ASSEMBLY_CONFLICT` | 400 | Пакет содержит сборку, имя файла которой уже поставляется другим установленным или подготовленным плагином. Переименуйте её или удалите другой плагин. |
| `PLUGIN_ARCHIVE_TOO_LARGE` | 413 | Загруженный архив превышает предельный размер. |
| `PLUGIN_ARCHIVE_UNSAFE` | 400 | Архив содержит небезопасные записи (например, выход за пределы каталога). |
| `PLUGIN_PERMISSION_UNKNOWN` | 400 | Разрешение, объявленное в манифесте, не существует. |
| `PLUGIN_ADMIN_PERMISSION_DECLARED` | 400 | Разрешение задано для маршрута, страницы или слота администратора. В административной части разрешений не бывает. |
| `PLUGIN_ROUTE_PATH_INVALID` | 400 | Путь маршрута в манифесте недопустим. |
| `PLUGIN_ROUTE_DUPLICATE` | 400 | Один и тот же маршрут объявлен дважды для одного метода в одной панели. |
| `PLUGIN_LABEL_KEY_MISSING` | 400 | В манифесте используется ключ текста, но файл английской локали его не определяет. |
| `PLUGIN_SLOT_UNKNOWN` | 400 | Содержимое помещено в слот, которого сервер не предоставляет. |
| `PLUGIN_SLOT_CONTEXT_KEY_NOT_OFFERED` | 400 | Слот запрошен с контекстом, которого он не предоставляет. |
| `PLUGIN_SLOT_WIDGET_ID_INVALID` | 400 | Идентификатор виджета недопустим. Используйте строчные буквы, цифры, дефисы и подчёркивания. |
| `PLUGIN_SLOT_WIDGET_DUPLICATE` | 400 | Один и тот же идентификатор виджета объявлен дважды для одного слота. |
| `PLUGIN_VIEW_MISSING` | 400 | Файл представления, объявленный в манифесте, отсутствует в пакете. |
| `PLUGIN_VIEW_INVALID` | 400 | Файл представления есть, но его не удаётся разобрать или его структура неверна. |
| `PLUGIN_VIEW_SCHEMA_UNSUPPORTED` | 400 | Версия схемы представления не поддерживается. |
| `PLUGIN_VIEW_BLOCK_KIND_UNKNOWN` | 400 | Блок представления использует вид, которого сервер не знает. |
| `PLUGIN_VIEW_ROUTE_UNDECLARED` | 400 | Представление ссылается на маршрут, не объявленный в манифесте. |
| `PLUGIN_MENU_ICON_INVALID` | 400 | Имя значка меню недопустимо. |
| `PLUGIN_PAGE_ID_INVALID` | 400 | Идентификатор страницы в манифесте недопустим. |
| `PLUGIN_UNSIGNED` | 400 | У пакета нет подписи, а сервер требует подписанные пакеты. |
| `PLUGIN_SIGNATURE_MALFORMED` | 400 | Файл подписи существует, но его не удаётся прочитать или разобрать. |
| `PLUGIN_SIGNATURE_KEY_UNKNOWN` | 400 | Пакет подписан ключом с идентификатором, которого сервер не знает. Добавьте открытый ключ в `PluginSigning:OperatorKeys`. |
| `PLUGIN_SIGNATURE_INVALID` | 400 | Подпись пакета не соответствует файлам. |
| `PLUGIN_NOT_TRUSTED` | 400 | SHA-256 архива не указан в `Plugins:TrustedPackageSha256`. |
| `PLUGIN_BUILT_IN` | 409 | Идентификатор плагина совпадает с плагином, поставляемым с сервером. Встроенные плагины заменить нельзя. |
| `PLUGIN_DOWNGRADE_REFUSED` | 409 | Загруженная версия старше установленной (или подготовленной). Передайте `force=true`, чтобы переопределить. |
| `PLUGIN_STILL_INSTALLED` | 409 | Очистка вызвана, пока папка плагина ещё существует на диске. Сначала удалите плагин. |
| `PLUGIN_NOT_FOUND` | 404 | Идентификатор плагина неизвестен или плагин не хранит данных. |
| `PLUGIN_SLOT_PRODUCTS_UNKNOWN` | 400 | Все идентификаторы продуктов в запросе привязки виджета слота неизвестны. |
| `PLUGIN_SLOT_WIDGET_NOT_FOUND` | 404 | Виджет слота не объявлен плагином. |
