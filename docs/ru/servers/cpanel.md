# Серверы cPanel <Label type="admin" /> {#cpanel-servers}

Hostpanel управляет аккаунтами cPanel через WHM API 1. Одна услуга соответствует одному аккаунту cPanel.

<Callout type="warning">
Эта интеграция ещё не проверена на рабочем сервере WHM. Вызовы соответствуют справочнику cPanel
WHM API 1 и протестированы только на сервере-заглушке. Опробуйте её на тестовом сервере, прежде чем
использовать для клиентов, и сообщите о своих наблюдениях.
</Callout>

## Что она делает {#what-it-does}

| Действие в Hostpanel | Функция WHM API 1 |
|---|---|
| Создание | `createacct` с `username`, `domain`, `password` и `plan` |
| Приостановка | `suspendacct` с `user` и `reason` |
| Возобновление | `unsuspendacct` с `user` |
| Удаление | `removeacct` с `username` |
| Смена пакета | `changepackage` с `user` и `pkg` |
| Смена пароля | `passwd` с `user` и `password` |
| Вход в cPanel | `create_user_session` с `user` и `service=cpaneld` |
| Проверка соединения | `version`, затем `listaccts` для подсчёта аккаунтов |
| Поиск аккаунта | `listaccts` с `searchtype=user` и `searchmethod=exact` |

**Пакет** продукта должен в точности совпадать с названием пакета WHM на сервере.

## Создание API-токена в WHM {#create-an-api-token-in-whm}

1. Войдите в WHM как `root` или как реселлер, которому принадлежат аккаунты.
2. Откройте **Development > Manage API Tokens** и нажмите **Generate Token**.
3. Задайте имя, например `hostpanel`. Скопируйте токен. WHM показывает его только один раз.

Токен реселлера позволяет управлять только аккаунтами самого реселлера.

## Добавление сервера в Hostpanel {#add-the-server-in-hostpanel}

Откройте **Серверы**, нажмите **Добавить новый сервер** и заполните вкладку **Основное** так же, как для любого сервера. На
вкладке **Подробности**:

| Поле | Значение |
|---|---|
| Модуль | cPanel |
| Имя пользователя | Пользователь WHM, которому принадлежит токен, например `root` |
| API-токен | Токен из WHM |

Поля **Пароль** и **Хеш доступа** для cPanel не используются. API-токен хранится в
зашифрованном виде с помощью `ENCRYPTION_KEY`, как и другие секреты серверов, и никогда не записывается в журнал.

Поле **Использовать SSL для подключений** для cPanel игнорируется. К WHM и к адресу cPanel, который показывается
владельцам аккаунтов, всегда обращаются по HTTPS, что бы ни было отмечено в этом поле.

Затем нажмите **Проверить соединение**. Рабочий токен покажет версию WHM и число аккаунтов.
`SERVER_CONNECTION_NO_API_KEY` означает, что не задано имя пользователя или API-токен. Сервер, который показан
как недоступный, хотя токен верный, обычно предъявляет самоподписанный сертификат, см.
[Замечания по безопасности](#security-notes).

## Порты {#ports}

Hostpanel обращается к WHM на порту 2087 и показывает владельцам аккаунтов адрес cPanel на порту 2083. Оба
порта работают по HTTPS. Изменить их сразу для всех серверов cPanel можно в настройках `Provisioning`:

| Параметр | По умолчанию |
|---|---|
| `Provisioning__CPanelWhmPort` | `2087` |
| `Provisioning__CPanelUserPort` | `2083` |

## Что Hostpanel проверяет перед вызовом WHM {#what-hostpanel-checks-before-it-calls-whm}

- Имя пользователя нового аккаунта должно состоять из 1-16 строчных букв и цифр и начинаться с
  буквы. Уже существующие аккаунты продолжают работать под сохранённым именем. Имя, нарушающее
  правило, останавливает настройку с ошибкой `CPANEL_USERNAME_INVALID`, и WHM не вызывается.
  То же правило применяется, когда сотрудники сохраняют хостинг-аккаунт услуги в статусе «В ожидании» на сервере cPanel,
  а существующий аккаунт, добавленный сотрудниками, должен иметь имя, к которому может обратиться WHM (буквы, цифры,
  подчёркивание, дефис или точка, до 32 символов), так что неверное имя приводит к ошибке сразу.
- Домен должен быть корректным доменным именем как минимум из двух частей в ASCII (интернационализированное
  имя вводится в форме `xn--`). Иначе настройка останавливается с ошибкой
  `CPANEL_DOMAIN_INVALID`.
- Пустое значение в WHM никогда не отправляется.
- Ответ WHM размером более 16 МБ считается нечитаемым.
- Если WHM не отвечает на вызов создания, а Hostpanel затем не может и найти аккаунт,
  настройка завершается временной ошибкой, а не отказом, потому что аккаунт мог быть создан. Запустите
  настройку снова, когда сервер начнёт отвечать.

## Как работают повторы {#how-retries-behave}

- Создание: если WHM отказывает, а аккаунт с таким именем пользователя уже существует, Hostpanel сообщает о
  существующем аккаунте и его домене. Он принимается, только если домен принадлежит самой услуге.
- Приостановка и возобновление: отказ принимается, если аккаунт уже находится в запрошенном состоянии.
- Удаление: отказ принимается, только если WHM однозначно сообщает, что такого аккаунта нет.
- Смена пакета: отказ принимается, если аккаунт уже на запрошенном пакете.
- Если Hostpanel не может прочитать ответ WHM, он никогда не считает, что аккаунт удалён или создан.
- Создание с потерянным ответом: если и последующий поиск потерян, настройка отвечает
  `PROVISIONING_OUTCOME_UNKNOWN` (503) вместо отказа, услуга остаётся в статусе «В ожидании», и повтор всё уладит.

Собственный текст ошибок WHM никогда не показывается и не записывается в журнал, потому что в нём может быть имя аккаунта.

## Замечания по безопасности {#security-notes}

- Каждый вызов WHM выполняется как POST, а его аргументы, включая пароль аккаунта в `createacct` и
  `passwd`, передаются в теле запроса, а не в URL, поэтому журнал доступа WHM и любой прокси перед
  ним не записывают пароль. Hostpanel никогда не записывает эти URL в журнал, а в HTTP-клиенте для WHM
  журналирование запросов выключено.
- WHM должен предъявлять сертификат, которому доверяет Hostpanel: выданный публичным центром сертификации или центром, которому доверяет
  ваш хост Hostpanel. WHM поставляется с самоподписанным сертификатом, а Hostpanel не обходит
  проверку сертификатов, поэтому сервер, который его всё ещё использует, показывается как недоступный при проверке
  соединения. Сначала установите на WHM доверенный сертификат.
- Ссылки единого входа из `create_user_session` одноразовые и с ограниченным сроком. WHM не привязывает их
  к адресу браузера. Hostpanel передаёт ссылку браузеру, только если это адрес `https`
  без имени пользователя и пароля, его хост совпадает с именем хоста или IP-адресом самого сервера
  (сравнение без учёта регистра; точка в конце делает имя другим), а порт, порт
  cPanel (`Provisioning__CPanelUserPort`). Браузеру передаётся проверенный адрес в разобранном виде. Любая другая ссылка отбрасывается, клиент видит
  `SERVICE_CPANEL_SSO_URL_UPSTREAM_FAILED`, и ничего из ссылки не записывается в журнал.
- Вызовы WHM проходят через защиту исходящих адресов, как и у других панелей. Серверу с частным
  адресом нужен [маршрут частной сети](/ru/servers/servers#private-network-routes).
