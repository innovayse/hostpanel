# Провижининг <Label type="admin" /> {#provisioning}

Провижининг представляет собой процесс, в котором Hostpanel автоматически создаёт, приостанавливает и удаляет хостинг-аккаунты на серверах панелей управления.

## Когда заказ оплачен {#when-an-order-is-paid}

Когда клиент оплачивает заказ, Hostpanel принимает его и помечает каждую строку услуги как **В ожидании**. Хостинг-аккаунт в этот момент не создаётся. Он создаётся одним из двух способов:

- **Клиент проходит мастер настройки**: клиент открывает услугу в клиентском портале и нажимает «Настроить мою услугу», чтобы ввести домен, имя пользователя и платёжные данные. Провижининг запускается после сохранения настройки.
- **Сотрудники нажимают «Создать»**: для услуги в статусе «В ожидании» в панели администратора нажмите **Создать** в карточке «Команды модуля».

Мастер настройки отклоняется, пока первый счёт услуги не оплачен полностью (`SERVICE_FIRST_INVOICE_UNPAID`).

### Выбор сервера {#server-selection}

Провижининг выбирает сервер так:

1. Если у продукта есть **Группа серверов**, сервер выбирается из этой группы по типу заполнения группы. Отключённые и заполненные серверы пропускаются, а значение «Макс. число аккаунтов», равное 0, считается заполненным. Сервер без максимума никогда не бывает заполненным.
   - **LeastFull:** выигрывает сервер с наименьшим коэффициентом заполнения; при равенстве выбирается сервер по умолчанию, затем сервер с большей вместимостью, затем первый по названию.
   - **FillUntilFull:** сначала используется сервер по умолчанию, затем серверы с лимитом по порядку названий, затем серверы без лимита как резерв на случай переполнения. Сервер заполняется до максимума, затем берётся следующий.
2. Если у продукта нет группы серверов, модуль должен определяться однозначно: если на всех серверах используется только один поддерживаемый модуль, сервер этого модуля выбирается по LeastFull, который без группы действует всегда. Если используется больше одного модуля, заказ завершается ошибкой `PRODUCT_SERVER_GROUP_REQUIRED`.
3. Если подходящего сервера нет, операция завершается ошибкой `NO_ELIGIBLE_SERVER`.

При прочих равных условиях сервер по умолчанию имеет приоритет в своей группе или модуле. Число аккаунтов берётся из проверок соединения и задания Sync Server Account Counts, поэтому заполненность между синхронизациями приблизительна.

### Что происходит при провижининге {#what-happens-on-provisioning}

<Steps>
<li>

Hostpanel читает домен, имя пользователя и пароль услуги. Если пароль не задан, он генерируется и сохраняется в записи услуги до обращения к панели.

</li>
<li>

Hostpanel обращается к API панели управления сервера и создаёт хостинг-аккаунт с **названием пакета** продукта. Если у продукта нет названия пакета, операция завершается ошибкой `PRODUCT_PACKAGE_MISSING`.

</li>
<li>

В случае успеха услуга становится **Активной**, начинается расчётный период, а ссылка на провижининг сохраняется в записи услуги.

</li>
</Steps>

Повтор безопасен: если такой же аккаунт с тем же именем пользователя и доменом уже есть в панели, Hostpanel принимает его. Если имя пользователя занято другим доменом, провижининг завершается ошибкой `PROVISIONING_ACCOUNT_CONFLICT`. Когда панель отклоняет запрос, ответом будет `PROVISIONING_UPSTREAM_FAILED`. Если панель недоступна или её ответ потерян, никто не знает, был ли аккаунт создан, и ответом будет `PROVISIONING_OUTCOME_UNKNOWN` (503): услуга остаётся в статусе «В ожидании», а при следующем повторе аккаунт принимается, если он существует.

Если в записи услуги ещё нет домена или имени пользователя, провижининг завершается ошибкой `SERVICE_HOSTING_DETAILS_MISSING`. Попытка запустить провижининг для услуги не в статусе «В ожидании» возвращает `SERVICE_NOT_PENDING`.

В случае успеха клиент получает письмо `service-provisioned`.

### Неудачная регистрация домена в том же заказе {#failed-domain-registrations-on-the-same-order}

Если заказ содержит и хостинг-услугу, и домен, а регистрация домена не удалась, стоимость домена возвращается автоматически (через исходный шлюз или как кредит). Хостинг-услуга всё равно проходит провижининг.

## Карточка «Команды модуля» {#the-module-commands-card}

Карточка **Команды модуля** на странице услуги показывает действия, доступные для текущего статуса.

| Статус услуги | Доступные команды |
|----------------|--------------------|
| В ожидании | **Создать**, **Завершить** |
| Активна | **Приостановить**, **Завершить**, **Сменить тариф**, **Сменить пароль** |
| Приостановлена | **Возобновить**, **Завершить** |
| Завершена | (показывается только поле «Дата завершения») |

Кнопка **Войти в панель управления** (вверху страницы услуги) доступна для активных и приостановленных услуг. Она открывает URL единого входа в аккаунт клиента в панели управления (`SERVICE_CREDENTIALS_UPSTREAM_FAILED`, если панель не отвечает).

Для **Сменить тариф** и **Сменить пароль** должна быть задана ссылка на провижининг (то есть аккаунт успешно создан). Без неё возвращается `SERVICE_NOT_PROVISIONED`. Если сервер не назначен, возвращается `SERVICE_NO_SERVER_ASSIGNED`. Отказы панели возвращают `SERVICE_PACKAGE_UPSTREAM_FAILED` или `SERVICE_PASSWORD_UPSTREAM_FAILED`.

Перед **Завершить** всегда показывается диалог подтверждения.

Сотрудники также могут изменить статус напрямую выпадающим списком **Статус** в той же карточке, не обращаясь к панели; это удобно для исправления записи.

## Приостановка {#suspension}

Услугу можно приостановить двумя способами:

- **Вручную сотрудниками**: нажмите **Приостановить** в «Командах модуля».
- **Автоматически заданием биллинга**: задание **Suspend Overdue Services** приостанавливает услуги, счета которых просрочены дольше льготного периода `billing.renewal.suspend_after_overdue_days`.

Hostpanel сначала обращается к панели и обновляет собственную запись только после её подтверждения. Отказ панели возвращает `SERVICE_SUSPEND_UPSTREAM_FAILED`.

При приостановке услуги все SSH-ключи, установленные клиентом на сервере, удаляются автоматически.

<Callout type="warning">
Приостанавливайте услугу через Hostpanel, а не напрямую в панели управления. Приостановка на стороне панели блокирует пароль, но не мешает входить по ключу. Приостановка в Hostpanel удаляет ключи.
</Callout>

**Возобновить** снова устанавливает SSH-ключи на сервере после подтверждения панели. Отказ панели возвращает `SERVICE_UNSUSPEND_UPSTREAM_FAILED`.

## Завершение {#termination}

Услугу можно завершить тремя способами:

- **Вручную сотрудниками**: нажмите **Завершить** в «Командах модуля».
- **Автоматически в конце расчётного цикла**: отметьте **Автозавершение в конце периода** на вкладке «Автоматическое управление» услуги и при необходимости укажите **Причину завершения**.
- **Автоматически после долгой приостановки**: задание **Auto-Terminate Suspended** завершает услуги, которые были приостановлены дольше `billing.renewal.terminate_after_suspended_days` дней.

Когда услуга завершается вручную, Hostpanel сначала обращается к панели. Если панель отказывает, возвращается `SERVICE_TERMINATE_UPSTREAM_FAILED`, а услуга остаётся без изменений: смена статуса не записывается. Если панель соглашается, услуга получает статус «Завершена», а SSH-ключи отзываются.

Если панель отказала и услуга осталась прежней, ежедневное задание автозавершения повторяет попытку, когда услуга в следующий раз подлежит автозавершению, и в этот момент сотрудники получают письмо `service-termination-failed-admin`.

`SERVICE_TERMINATE_NOT_ALLOWED` возвращается при попытке завершить услугу, которая уже имеет статус «Завершена».

## Настройки автоматического управления {#auto-management-settings}

На вкладке **Автоматическое управление** услуги:

| Настройка | Что делает |
|---------|--------------|
| Автоматический биллинг | Включает для этой услуги формирование счетов на продление, приостановку за просрочку и автозавершение |
| Отменить автоприостановку | Не даёт заданию биллинга автоматически приостанавливать эту услугу |
| Приостановить до | Дата, после которой автоприостановка может возобновиться (только при включённом «Отменить автоприостановку») |
| Автозавершение в конце периода | Завершает услугу в конце текущего расчётного периода |
| Причина завершения | Примечание, записываемое при автозавершении (только при включённом «Автозавершение в конце периода») |

## Плановые задания {#scheduled-jobs}

| Задание (класс `Cron`) | Время по умолчанию (UTC) | Что делает |
|--------------------|--------------------|--------------|
| Sync Server Account Counts (`SyncServerAccountCountsCron`) | 06:00 | Обновляет актуальное число аккаунтов, показанное в каждой строке сервера |
| Auto-Terminate Suspended (`AutoTerminateSuspendedCron`) | 08:00 | Завершает услуги, приостановленные за неуплату дольше `billing.renewal.terminate_after_suspended_days` дней, затем завершает услуги, для которых задано автозавершение в конце цикла |
| Suspend Overdue Services (`SuspendOverdueServicesCron`) | 09:00 | Приостанавливает услуги, счёт которых просрочен дольше `billing.renewal.suspend_after_overdue_days` дней |

Время заданий задаётся в параметрах `ScheduledJobs`. Пороговые значения биллинга меняются в разделе **Настройки → Системные настройки**:
