# Серверы и группы серверов <Label type="admin" /> {#servers-and-server-groups}

<DemoLink path="/servers" />

Откройте **Серверы**, чтобы управлять серверами провижининга и группами балансировки нагрузки. Подзаголовок: «Управление серверами провижининга и группами балансировки нагрузки.»

## Список серверов {#the-server-list}

Серверы сгруппированы по модулям, по одной таблице на модуль. В каждой строке показаны **Название сервера**, **IP-адрес**, **Аккаунты**, **Статус** и **Действия**. Нажмите **Изменить** в строке, чтобы открыть настройки сервера. Если соединение исправно, статус выглядит так: «В сети · _n_ аккаунтов · _версия_».

**Значки статуса:** В сети, Не в сети, Не проверен.

**Действия в строке:** Проверить соединение, SSH (открывает диалог управления SSH-ключами), Изменить, Удалить.

Значок **ПО УМОЛЧАНИЮ** отмечает сервер по умолчанию для его модуля. При прочих равных условиях такой сервер имеет приоритет в своей группе или модуле, когда выбирается сервер для нового аккаунта (см. [Типы заполнения](#fill-types)).

<Callout type="note">
<strong>CWP7</strong>, <strong>Plesk</strong> и <strong>cPanel</strong> создают аккаунты автоматически. Поддержка cPanel появилась недавно и ещё не проверена на рабочем сервере WHM; см. <a href="/ru/servers/cpanel">Серверы cPanel</a>. Остальные пункты списка модулей (DirectAdmin, CentOS, Lukittu, Virtualmin, HyperVm) сохраняются, но не создают аккаунты автоматически, и проверить их соединение нельзя.
</Callout>

## Добавление сервера {#add-a-server}

Нажмите **Добавить новый сервер**. В форме три вкладки.

### Вкладка «Основное» {#general-tab}

| Поле | Примечания |
|-------|-------|
| Название | Понятная подпись, которая показывается в панели |
| Имя хоста | Используется для подключений к API этого сервера |
| IP-адрес | Основной публичный IP-адрес сервера |
| Назначенные IP-адреса | Дополнительные IP-адреса (по одному в строке) |
| Ежемесячная стоимость (USD) | Для ваших собственных записей |
| Дата-центр / NOC | Например, Hetzner, OVH |
| Макс. число аккаунтов | Оставьте пустым, если ограничения нет |
| Адрес статуса сервера | Полный путь к странице статуса, которая показывается в мониторе статуса клиентского портала |
| Сервер по умолчанию | Отметьте как сервер по умолчанию для этого модуля. При прочих равных условиях он имеет приоритет в своей группе или модуле |
| Отключить этот сервер | Не позволяет назначать на него новые аккаунты |

### Вкладка «Серверы имён» {#nameservers-tab}

До пяти серверов имён (имя хоста и IP для каждого), которые показываются клиентам при создании аккаунта на этом сервере: основной, дополнительный, третий, четвёртый, пятый.

### Вкладка «Подробности» {#details-tab}

| Поле | Примечания |
|-------|-------|
| Модуль | Панель управления: cPanel, Plesk, DirectAdmin, CentOS Web Panel, CWP7, Lukittu, Virtualmin, HyperVm |
| Имя пользователя | Имя пользователя API |
| Пароль | Пароль API (хранится в зашифрованном виде) |
| API-токен | API-токен, если модуль использует аутентификацию по токену (хранится в зашифрованном виде) |
| Хеш доступа | Используется CWP7 и Plesk для аутентификации в API (хранится в зашифрованном виде). cPanel вместо него использует имя пользователя и API-токен |
| Использовать SSL для подключений | Включает HTTPS для запросов к API. Для cPanel игнорируется, так как к нему всегда обращаются по HTTPS |

При редактировании в полях учётных данных показано **(пусто — не менять)**. Секреты хранятся в зашифрованном виде с помощью `ENCRYPTION_KEY`. Поля порта нет: порт API панели фиксирован для каждого модуля.

## Проверка соединения {#test-a-connection}

Нажмите **Проверить соединение** в строке сервера. Hostpanel обращается к API панели сервера и обновляет значок статуса. Результат показывается на месте, а не как ошибка страницы.

**Успех:** «В сети · _n_ аккаунтов · _версия_»

**Коды ошибок в результате проверки:**

| Код | Что проверить |
|------|---------------|
| `SERVER_CONNECTION_UNREACHABLE` | Неверно указаны имя хоста или IP, порт API панели заблокирован или панель не работает |
| `SERVER_CONNECTION_NO_ACCESS_HASH` | Для этого сервера не сохранён хеш доступа; добавьте его на вкладке «Подробности» |
| `SERVER_CONNECTION_NO_API_KEY` | Не сохранены ни ключ API, ни хеш доступа; добавьте учётные данные на вкладке «Подробности» |
| `SERVER_CONNECTION_MODULE_UNSUPPORTED` | У этого модуля нет проверки соединения; проверить его нельзя |

## Изменение и удаление сервера {#edit-and-delete-a-server}

Нажмите **Изменить** в строке, чтобы открыть форму. Операции с сервером, которого больше нет, возвращают `SERVER_NOT_FOUND`. Удаление сервера, на котором всё ещё размещены клиентские услуги или SSH-ключи, отклоняется (`SERVER_IN_USE`).

## Группы серверов {#server-groups}

Группы серверов позволяют назначить продукту набор серверов. Новые заказы распределяются по группе в соответствии с типом заполнения.

### Создание группы {#create-a-group}

В разделе **Группы** под списком серверов нажмите **Создать группу**.

| Поле | Примечания |
|-------|-------|
| Название группы | Например, «CWP Servers» |
| Тип заполнения | Как распределяются аккаунты (см. ниже) |
| Серверы | Переместите серверы из «Доступные» в «В группе» |

### Типы заполнения {#fill-types}

| Тип заполнения | Подпись |
|-----------|-------|
| LeastFull | Добавлять на наименее загруженный сервер |
| FillUntilFull | Заполнять активный сервер до предела, затем переключаться |

**Серверы, которые никогда не выбираются:** при любом типе заполнения отключённые и заполненные серверы пропускаются. Сервер считается заполненным, когда число его аккаунтов достигло значения «Макс. число аккаунтов». Значение 0 считается заполненным. Сервер без максимума (поле оставлено пустым) никогда не бывает заполненным.

**LeastFull:** выигрывает сервер с наименьшим коэффициентом заполнения (аккаунты ÷ максимум аккаунтов). У серверов без максимума коэффициент заполнения равен 0. При равенстве выбирается сервер по умолчанию, затем сервер с большей вместимостью, затем первый по названию.

**FillUntilFull:** сначала используется сервер по умолчанию. После него по порядку названий используются серверы, у которых есть максимум. Серверы без максимума идут последними, как резерв на случай переполнения. Сервер заполняется до достижения максимума, затем берётся следующий.

**Без группы:** если у продукта нет группы серверов, всегда действует LeastFull, какие бы типы заполнения ни использовали ваши группы.

**Сервер по умолчанию:** во всех случаях при прочих равных условиях сервер по умолчанию имеет приоритет в своей группе или модуле.

<Callout type="note">
Число аккаунтов берётся из проверок соединения и задания синхронизации числа аккаунтов серверов (Sync Server Account Counts), поэтому заполненность, которая показывается и используется при выборе, между синхронизациями приблизительна.
</Callout>

### Удаление группы {#delete-a-group}

Удаление группы, в которую продукты всё ещё выполняют провижининг, отклоняется (`SERVER_GROUP_IN_USE`). Удаление неиспользуемой группы снимает назначение со всех её серверов, но сами серверы не удаляются.

## Маршруты частной сети {#private-network-routes}

Если API панели управления сервера доступен только через VPN или частную сеть, задайте в окружении развёртывания переменную `PANEL_HOST_ADDRESSES` в виде пар `hostname=address` через запятую, например `srv4.example.com=10.77.0.1`. Hostpanel подключается к частному адресу, но сохраняет имя хоста для запроса и проверки сертификата TLS, поэтому ссылки для клиентов и проверка сертификатов не меняются.

Полный список параметров окружения см. в [справочнике по конфигурации](/ru/operators/configuration).
