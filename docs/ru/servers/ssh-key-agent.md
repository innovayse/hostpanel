# Агент SSH-ключей <Label type="admin" /> {#ssh-key-agent}

<DemoLink path="/servers" />

Агент SSH-ключей позволяет клиентам добавлять собственные открытые ключи ED25519 в свои хостинг-аккаунты. На каждом сервере работает небольшой процесс-агент; Hostpanel подключается к нему по SSH, используя ключ идентификации отдельного сервера и закреплённый отпечаток хоста.

## Как это работает {#how-it-works}

```
Hostpanel ──ssh (pinned host key, per-server ED25519)──▶ hpsshkeys@server
  authorized_keys: restrict,command="sudo -n /usr/local/sbin/hostpanel-ssh-key-agent"
  sudoers:         hpsshkeys ALL=(root) NOPASSWD: /usr/local/sbin/hostpanel-ssh-key-agent
```

Директива `restrict` отключает PTY, перенаправление портов и пользовательский rc; принудительная команда игнорирует всё, что просит запустить клиент; sudo разрешает только этот точный путь без аргументов. Запросы передаются через stdin в виде документа JSON; агент никогда не запускает оболочку и не берёт путь из запроса.

**Поддерживаемые модули серверов:** профиль агента (`cwp`) сопоставлен только с CWP7. Для всех остальных типов серверов клиентам показывается «Управление SSH-ключами недоступно».

## Настройка SSH на сервере {#set-up-ssh-on-a-server}

Откройте **Серверы** и нажмите действие **SSH** в строке сервера, чтобы открыть диалог управления SSH-ключами.

<Steps>
<li>

**Параметры подключения.** Заполните поля и сохраните. Эти параметры используются на всех последующих шагах.

| Поле | Примечания |
|-------|-------|
| SSH-хост | Имя хоста, которое клиенты используют для подключения (показывается клиенту) |
| SSH-порт | По умолчанию 22 |
| Хост агента | Адрес, к которому обращается Hostpanel, чтобы достучаться до агента (может отличаться от SSH-хоста) |
| SSH-порт агента | По умолчанию 22 |
| Служебный пользователь | Системная учётная запись, от имени которой работает агент; по умолчанию `hpsshkeys` |
| Тайм-аут подключения (с) | Через сколько секунд попытка подключения прекращается |
| Тайм-аут операции (с) | Через сколько секунд запрос к агенту прекращается |

**Сетевой доступ.** Hostpanel подключается с фиксированного адреса. Разрешите на порту агента только этот адрес с помощью строки для вашего брандмауэра (CSF, firewalld или ufw). Задайте `SSH_AGENT_SOURCE_ADDRESSES` в окружении развёртывания равным адресу, с которого управляемые серверы видят подключения Hostpanel; тогда диалог покажет готовые строки для брандмауэра и sshd.

В OpenSSH 9.8 и новее неудачные или неаутентифицированные подключения штрафуются по исходному адресу (`PerSourcePenalties`, включено по умолчанию). Добавьте адрес Hostpanel в `PerSourcePenaltyExemptList` в `sshd_config`, чтобы избежать временной блокировки. Диалог показывает точную строку, которую нужно добавить.

При использовании VPN или частной сети: введите частный адрес сервера как хост агента; хост, на котором работает Hostpanel, должен находиться в этой сети.

</li>
<li>

**Создание ключа.** Нажмите **Создать ключ**. Hostpanel создаёт для этого сервера пару ключей ED25519, хранит закрытый ключ в зашифрованном виде и показывает установщик в виде одной команды. Скопируйте команду и выполните её на сервере от имени root.

<Callout type="warning">
Запускайте установщик в обычном SSH-терминале, а не в браузерном терминале хостинг-панели. Браузерные терминалы теряют переменные с <code>$</code> и дублируют ввод, из-за чего команда ломается.
</Callout>

Перед распаковкой установщик проверяет контрольную сумму SHA256, показанную в панели администратора. Он выводит отпечатки ключей хоста сервера. Запомните их для следующего шага.

Установщик принимает такие флаги:

| Флаг | Действие |
|------|--------|
| `--provider <profile>` | Профиль агента: `cwp` для CWP7, `generic-linux` для обычного Linux |
| `--binding <id>` | Привязывает эту установку к записи сервера в Hostpanel |
| `--config <file>` | Использовать собственный файл конфигурации вместо файла профиля по умолчанию (для опытных пользователей) |
| `--dry-run` | Показать, что будет установлено, ничего не меняя |
| `--check` | Диагностика существующей установки (пользователь, блокировка, владелец и права, sudoers, ключ с принудительной командой, конфигурация, самопроверка, ключ хоста) |

Повторный запуск установщика обновляет бинарный файл агента и привязку, сохраняя существующий `agent.conf`. Установщик создаёт и записывает:

- `/usr/local/sbin/hostpanel-ssh-key-agent`: бинарный файл агента
- `/etc/sudoers.d/hostpanel-ssh-key-agent`: правило sudoers
- `/etc/hostpanel-ssh-key-agent/agent.conf`: конфигурация агента (из профиля)
- `/var/lib/hpsshkeys/.ssh/authorized_keys`: ключ служебного пользователя с принудительной командой

Установщик никогда не трогает sshd, брандмауэр, VPN, Jailkit и клиентские аккаунты.

</li>
<li>

**Закрепление ключа хоста.** Нажмите **Получить ключ хоста**. Hostpanel подключается к агенту без аутентификации и считывает отпечаток, который предъявляет сервер. Сравните его с тем, что вывел установщик; если они совпадают, нажмите **Использовать этот отпечаток** и сохраните. Все последующие подключения, предъявляющие любой другой отпечаток, отклоняются.

Если **Получить ключ хоста** не срабатывает:

| Код ошибки | Значение |
|------------|---------|
| `SSH_SETTINGS_INCOMPLETE` | Поле «Хост агента» пусто; сначала заполните параметры подключения |
| `SSH_AGENT_HOST_UNREACHABLE` | Нет сетевого пути к хосту и порту агента; проверьте адрес, брандмауэр и VPN |
| `SSH_AGENT_PORT_REFUSED` | Порт активно отклонил подключение; там ничего не слушает, либо брандмауэр отклоняет адрес Hostpanel |
| `SSH_AGENT_CONNECTION_CLOSED` | Сервер принял подключение, а затем закрыл его до приветствия SSH; проверьте `PerSourcePenalties`, `MaxStartups` и TCP wrappers |
| `SSH_HOST_KEY_UNREADABLE` | Подключение установлено, но ключ хоста не получен; проверьте, что на порту работает sshd |

</li>
<li>

**Проверка соединения.** Нажмите **Проверить агент**. В строке состояния показан один из вариантов:

- **Агент доступен**: агент ответил, привязка совпадает.
- **Агент недоступен**: подключиться не удалось; причину см. в «Последняя проверка не удалась».
- **Не проверялся**: настройки изменены после последней проверки.

Версия агента показывается как «Агент _версия_» или «Агент _версия_ (_профиль_)». Прежде чем сервер можно будет включить, нужна успешная проверка. Изменение хоста агента, порта, пользователя, ключа или закреплённого отпечатка сбрасывает проверку.

Если проверка не удалась, причина показывается как «Последняя проверка не удалась: _причина_» (`servers.ssh.failures.*`):

| Причина | Значение |
|--------|---------|
| сервер недоступен | Нет сетевого пути к хосту агента (`Unreachable`) |
| агент не ответил вовремя | Соединение открыто, но агент не ответил в срок (`Timeout`) |
| агент установлен для другого сервера | Хост верный, но привязка не та: проверьте хост агента или выполните на нём команду установки именно этого сервера (`BindingMismatch`) |
| версия агента не поддерживается | Агент слишком старый для этой версии Hostpanel (`UnsupportedVersion`) |
| внутренний сбой агента | Ошибка на стороне агента; смотрите `/var/log/hostpanel-ssh-key-agent.log` (`InternalError`) |
| агент отклонил запрос | Неожиданный отказ агента (`InvalidRequest`) |
| агент не поддерживает эту операцию | Версия агента не реализует эту операцию (`UnknownOperation`) |
| запрос слишком большой | Тело запроса превысило предельный размер агента (`RequestTooLarge`) |
| у сервера нет полных настроек агента | Одно или несколько обязательных полей пусты (`AgentNotConfigured`) |
| неизвестная причина | Неожиданный ответ (`Unknown`) |

В таблице перечислены частые причины. Панель администратора показывает около двадцати; полный список смотрите в `servers.ssh.failures` в файле локали.

`SSH_AGENT_NOT_VERIFIED` показывается при попытке включить сервер без успешной проверки. `SSH_MODULE_NOT_SUPPORTED` возвращается для типов серверов, модуль которых не имеет профиля агента.

</li>
<li>

**Включение.** Включите переключатель **Клиенты этого сервера могут управлять SSH-ключами**. Включение отклоняется, если другой уже включённый сервер использует тот же хост и порт агента (`SSH_AGENT_ENDPOINT_IN_USE`). Изменение хоста агента, порта, пользователя, ключа или закреплённого отпечатка сбрасывает проверку и требует повторной проверки перед повторным включением.

</li>
</Steps>

### Замена ключа {#rotate-identity}

Нажмите **Заменить ключ**, чтобы выпустить новый ключ для той же привязки сервера. Доступ клиентов по SSH-ключам прекращается немедленно, пока установщик не будет снова запущен с новой показанной командой.

Для аварийного восстановления в разделе **Дополнительно** можно вставить существующий закрытый ключ вместо создания нового.

## Ключи в течение жизни услуги {#keys-over-a-service-s-life}

| Событие | Ключи на сервере | В Hostpanel |
|-------|--------------------|--------------|
| Услуга приостановлена в Hostpanel | Удаляются с сервера (ключ, удаление которого не подтверждено, остаётся и записывается в журнал для сотрудников) | Приостановлено; при возобновлении возвращаются под тем же ID; InstallFailed, если не подтверждено |
| Аккаунт приостановлен только в панели | Остаются и продолжают работать: блокировка пароля не останавливает ключи. Вместо этого приостанавливайте через Hostpanel | Без изменений |
| Услуга завершена | Отзываются автоматически | Отозваны; если сервер не подтвердил, RevokeFailed с причиной, видно сотрудникам |
| Услуга перенесена на другой сервер | Остаются на старом сервере до ручного отзыва | Показаны как относящиеся к предыдущему серверу; на новый сервер ничего не отправляется |
| Управление SSH-ключами выключено | Остаются | Клиент по-прежнему может отзывать ключи, но не может добавлять |
| Агент удалён | Остаются, если сначала не выполнен отзыв всех | Отзыв не удаётся (RevokeFailed), пока агент не установлен снова |
| Ключ заменён | Не затрагиваются | Доступ клиентов по SSH выключен, пока установщик не запущен с новым ключом |
| Плагин удалён | Каждый ключ, выпущенный плагину, отзывается автоматически | Отозваны; если сервер не подтвердил, RevokeFailed с причиной, и попытки повторяются до успеха |

## Коды ошибок агента {#agent-error-codes}

Эти коды приходят от самого агента и появляются в ответах Hostpanel с ошибками или в журналах для сотрудников.

| Код | Значение |
|------|---------|
| `invalid_account` | Имя учётной записи не соответствует правилам именования сервера |
| `account_not_found` | В passwd нет записи для этой учётной записи |
| `account_not_eligible` | Учётная запись существует, но исключена (нет в `eligible_list`, нет в `ssh_group` или проверка панели провайдера не пройдена) |
| `account_suspended` | Пароль учётной записи заблокирован (`usermod -L`), а `check_shadow_lock` включён |
| `invalid_key` | Открытый ключ не является допустимым ключом ED25519 |
| `duplicate_key` | Отпечаток этого ключа уже есть под другим `key_id` |
| `key_id_conflict` | Тот же `key_id`, другое содержимое ключа |
| `too_many_keys` | Учётная запись достигла максимального числа управляемых ключей |
| `ssh_disabled` | Оболочка учётной записи отключена (например, `/sbin/nologin`), а `jail_enrol` выключен |
| `unsafe_path` | Каталог `.ssh` или файл `authorized_keys` является символической ссылкой или имеет неожиданного владельца |
| `file_too_large` | `authorized_keys` превышает предельный размер |
| `timeout` | Запрос выполнялся слишком долго (stdin: 10 с, всего: 60 с) |
| `internal_error` | Сбой на стороне агента; подробности в журнале аудита сервера |

## Удаление агента {#uninstall}

Перед удалением агента отзовите все управляемые ключи, чтобы клиенты не могли продолжать входить по осиротевшим ключам. Кнопки в панели администратора пока нет, поэтому используйте API администратора напрямую:

1. Вызовите `POST /api/admin/servers/{id}/ssh-keys/revoke-all`. Это удалит с сервера все управляемые ключи.
2. На сервере, в распакованном пакете установщика, выполните:

```bash
./uninstall.sh           # removes management key, sudoers entry, hpsshkeys user and agent binary; keeps agent.conf
./uninstall.sh --purge   # also removes agent.conf (audit log is always kept)
./uninstall.sh --dry-run # preview only
```

Программа удаления никогда не трогает sshd, брандмауэр, jailkit и файлы клиентов.

Чтобы убедиться, что после удаления не осталось управляемых ключей:

```bash
grep -rl 'hostpanel:' /home/*/.ssh/authorized_keys
```

## Что видят клиенты {#what-customers-see}

Клиенты управляют своими SSH-ключами на вкладке **SSH-ключи** своей услуги в клиентском портале. Они могут добавить ключ, вставив открытый ключ и дав ему подпись, увидеть отпечаток и подпись каждого установленного ключа и отозвать любой ключ по отдельности. Операции добавления и отзыва идут напрямую к агенту на сервере; в Hostpanel хранится только отпечаток ключа, но никогда не закрытый ключ.

Плагину, который объявляет доступ к SSH-хосту, можно выпустить ключ для услуги клиента, если на странице **Плагины** оператор привязал к продукту этой услуги один из виджетов услуг плагина. Продукт, указанный только в манифесте плагина, не считается: пока оператор его не привяжет, плагин не получает доступа ни к какому хостингу. Hostpanel создаёт пару ключей, устанавливает открытую половину через этого агента точно так же, как ключ, добавленный клиентом, и один раз передаёт закрытый ключ плагину; Hostpanel его не хранит и не записывает в журнал. Такой ключ показывается на вкладке **SSH-ключи** услуги, как и любой другой, и клиент может отозвать его в любой момент. Выключение плагина сохраняет его ключи (пока плагин выключен, он не может использовать хост); удаление плагина отзывает их.

Запросы на добавление и отзыв из клиентского портала ограничены 20 операциями за 60 секунд на клиента (политика `SshKeys`). Это можно изменить в настройках ограничения частоты запросов развёртывания.

Полное пошаговое описание см. в [руководстве по клиентскому порталу](/ru/customers/portal).
