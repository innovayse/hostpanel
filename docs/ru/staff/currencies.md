# Валюты, продления и задания <Label type="admin" /> {#currencies-renewals-and-jobs}

## Валюты {#currencies}

Откройте **Настройки → Валюты**, чтобы управлять валютами, которые принимает ваша панель.

**Столбцы:** Код, Числовой код, Формат, Знаков после запятой, Курс к базовой, База, Включена, Действия.

### Добавление валюты {#add-a-currency}

Нажмите **Добавить валюту** и заполните:

| Поле | Описание |
|------|----------|
| Код ISO | Трёхбуквенный код, например EUR |
| Числовой код | Числовой код ISO, например 978 |
| Префикс | Символ перед суммой, например € |
| Суффикс | Символ после суммы (необязательно) |
| Знаков после запятой | Число знаков после запятой |
| Курс к базовой | Курс обмена относительно базовой валюты |
| Включена | Могут ли клиенты выбирать эту валюту |

**Базовая валюта** всегда включена, и её курс всегда равен 1. Её нельзя отключить (`CURRENCY_BASE_DISABLE_NOT_ALLOWED`).

- **Сделать базовой** — назначает эту валюту новой базовой. Все остальные курсы обмена пересчитываются.
- **Обновить курсы обмена** — получает актуальные курсы из внешнего источника и автоматически обновляет все небазовые валюты. То же обновление выполняется само каждый день в 03:00 UTC; установка без выхода в интернет отключает его параметром `DISABLE_EXCHANGE_RATE_UPDATES` (см. [справочник по настройке](/ru/operators/configuration)). Если источник недоступен, курсы остаются прежними, а обновление повторяется на следующий день.
- **Обновить цены товаров** — пересчитывает все цены продуктов от базовой валюты по текущим курсам обмена.

<Callout type="warning">
«Обновить цены товаров» перезаписывает существующие цены продуктов. Это нельзя отменить.
</Callout>

## Как работают продления {#how-renewals-work}

Когда у услуги или домена приближается дата продления, система:

1. Выставляет счёт на продление за `billing.renewal.invoice_days_before` дней до срока оплаты.
2. Отправляет письма-напоминания в дни, указанные в `billing.renewal.reminder_days`.
3. Если включена настройка `billing.renewal.auto_apply_credit`, автоматически применяет кредитный баланс к счёту на продление.
4. После оплаты счёта продлевает услугу или домен ещё на один период оплаты.

## Предстоящие продления и домены с заблокированным продлением {#upcoming-renewals-and-claimed-domain-renewals}

**Биллинг, Предстоящие продления** показывает услуги и домены, которые продлеваются в ближайшие 30, 60 или 90 дней. В строке можно включить или выключить автоматический биллинг, а **Выставить все счета на продление этого клиента** выставляет все счета на продление, которые у этого клиента наступили сейчас, а не только тот, что в этой строке.

Когда оплаченное продление домена отправлено регистратору, а тот не дал ясного ответа, строка счёта остаётся **заблокированной** и показывается в списке *Продления доменов, ожидающие сотрудника* с именем клиента. **Проверьте домен у регистратора, прежде чем снимать блокировку.** Снятие блокировки позволяет следующему запуску продлений снова отправить продление регистратору. Если регистратор уже продлил домен, он будет продлён второй раз, и регистратор спишет за это деньги второй раз; снимайте блокировку, только если домен не был продлён.

## Обработка просрочки {#overdue-handling}

Если счёт на продление не оплачен к сроку, он получает статус **Просрочено**. Дальше:

1. Через `billing.renewal.suspend_after_overdue_days` дней услуга **приостанавливается**.
2. Ещё через `billing.renewal.terminate_after_suspended_days` дней услуга **завершается**.

Оплата просроченного счёта автоматически возобновляет услугу.

Отдельные услуги могут переопределять автоматическое поведение приостановки и завершения. В записи услуги можно задать:

- **Автоматический биллинг** — выставляются ли для этой услуги счета на продление автоматически.
- **Отменить автоприостановку** — не даёт глобальному правилу приостановить эту услугу.
- **Автозавершение в конце периода** — завершить услугу в конце периода оплаты, не дожидаясь глобального правила.

## Ежедневные задания биллинга {#the-daily-billing-jobs}

Эти задания выполняются автоматически по расписанию. Всё время указано в UTC. Каждое задание выполняется в одном экземпляре; запуск, пропущенный, пока сервер не работал, догоняется при следующем старте. Неудавшийся запуск записывается в журнал, а следующий выполняется по расписанию.

| Задание | Время по умолчанию | Что делает |
|---------|--------------------|------------|
| Обновление курсов валют | 03:00 UTC | Обновляет курсы валют из внешнего источника; цены продуктов не пересчитываются. Отключается параметром `DISABLE_EXCHANGE_RATE_UPDATES` |
| Обработка продлений | 05:00 UTC | Выставляет счета на продление услуг и доменов, срок которых наступает в настроенном окне |
| Обработка оплачиваемых позиций | 06:00 UTC | Помещает позиции из очереди в счета |
| Отправка напоминаний о продлении | 06:00 UTC | Отправляет письма-напоминания о продлении |
| Проверка просроченных счетов | 07:00 UTC | Отмечает неоплаченные счета с истёкшим сроком как «Просрочено» |
| Автозавершение приостановленных | 08:00 UTC | Завершает услуги, приостановленные дольше настроенного предела |
| Приостановка просроченных услуг | 09:00 UTC | Приостанавливает услуги с просроченными счетами сверх настроенного предела |
| Сверка платежей через шлюз | Каждые 5 минут (по умолчанию) | Проверяет ожидающие платежи через шлюз и отмечает счета оплаченными, когда шлюз подтверждает платёж |

Час запуска каждого задания задаётся параметрами `ScheduledJobs`. Полный список настроек `ScheduledJobs__*` приведён в [справочнике по настройке](/ru/operators/configuration).

## Автоматические письма сотрудникам {#automated-staff-emails}

Система автоматически отправляет сотрудникам следующие письма:

| Письмо | Когда отправляется |
|--------|--------------------|
| `gateway-payment-stalled-admin` | Платёж через шлюз находится в ожидании дольше 24 часов |
| `domain-renewal-failed-admin` | Не удалось выполнить автоматическое продление домена |
| `service-termination-failed-admin` | Не удалось выполнить автоматическое завершение услуги |
